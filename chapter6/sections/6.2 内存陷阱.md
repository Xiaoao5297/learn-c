# 6.2 内存陷阱

6.1 学会了申请和释放，这一节把动态内存的规则学完整：`calloc`、`realloc` 两个帮手，以及三大陷阱——内存泄漏、悬垂指针、双重释放。动态内存的自由，代价就是这些坑全靠自己防。

## 6.2.1 calloc：申请并清零

`calloc` 和 `malloc` 的区别只有一条：申请到的内存**自动全部填 0**。参数是"个数、单个大小"两个：

```c
int *arr = calloc(10, sizeof(int));    /* 10 个 int，全 0 */

/* 等价于 */
int *arr = malloc(10 * sizeof(int));
for (int i = 0; i < 10; i++) {
	arr[i] = 0;
}
```

```c
// 6.2.1 calloc_zero.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int *arr = calloc(5, sizeof(int));
	if (arr == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	for (int i = 0; i < 5; i++) {
		printf("arr[%d] = %d\n", i, arr[i]);
	}

	free(arr);
	arr = NULL;

	return 0;
}
```

<!-- output: 6.2.1 -->
```text
arr[0] = 0
arr[1] = 0
arr[2] = 0
arr[3] = 0
arr[4] = 0
```

什么时候用 `calloc`？希望初始值全 0 的时候。它的参数写法也顺带少犯一个错：字节数交给编译器算，不会写成 `malloc(10)` 这种"10 个字节"的失误。

`calloc` 同样可能失败返回 `NULL`，检查和 `malloc` 完全一样。

## 6.2.2 realloc：动态扩容

数组用着用着不够大了怎么办？静态数组只能干瞪眼，动态数组可以用 `realloc` 扩容：给它旧指针和新大小，它尽量在原地把空间扩大；原地放不下时，会另找一块更大的、**把旧内容搬过去**，再自动释放旧空间，然后把新地址返回给你。

```c
int *tmp = realloc(arr, new_size * sizeof(int));
```

但这里有一个必须养成的习惯：**返回值先接进临时变量，检查成功后再覆盖原指针**。因为失败时 `realloc` 返回 `NULL`，而旧内存还完好——如果直接写 `arr = realloc(arr, ...)`，失败的那一刻 `arr` 被覆盖成 `NULL`，旧内存的地址就丢了，既用不了也释放不了，变成泄漏。

正确写法固定是三步曲：

```c
int *tmp = realloc(arr, new_size * sizeof(int));    /* 第 1 步：临时变量接返回值 */
if (tmp == NULL) {                                  /* 第 2 步：检查 */
	/* 失败处理；旧内存还在 arr 里，需要时仍可 free(arr) */
}
arr = tmp;                                          /* 第 3 步：成功才覆盖 */
```

```c
// 6.2.2 realloc_grow.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int n = 3;
	int *arr = malloc(n * sizeof(int));
	if (arr == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	for (int i = 0; i < n; i++) {
		arr[i] = i + 1;
	}

	int new_n = 5;
	int *tmp = realloc(arr, new_n * sizeof(int));
	if (tmp == NULL) {
		printf("扩容失败，继续用原来的数组\n");
		free(arr);
		return 1;
	}
	arr = tmp;
	n = new_n;

	/* 新位置（下标 3、4）的内容不确定，要自己赋值 */
	arr[3] = 40;
	arr[4] = 50;

	for (int i = 0; i < n; i++) {
		printf("arr[%d] = %d\n", i, arr[i]);
	}

	free(arr);
	arr = NULL;

	return 0;
}
```

<!-- output: 6.2.2 -->
```text
arr[0] = 1
arr[1] = 2
arr[2] = 3
arr[3] = 40
arr[4] = 50
```

注意扩容后**新增部分的内容是不确定的**（`realloc` 只保证旧内容搬过去），下标 3、4 必须自己赋值。

## 6.2.3 realloc 实战：自动扩容的数组

把三步曲用进真实套路：容量满了就翻倍。这就是"动态数组"的经典实现，`vector` 这类可变容器的基本原理：

```c
// 6.2.3 auto_grow.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int capacity = 2;    /* 当前容量 */
	int count = 0;       /* 已存个数 */
	int *scores = malloc(capacity * sizeof(int));
	if (scores == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	int input[] = {88, 92, 76, 100, 54, 67};

	for (int i = 0; i < 6; i++) {
		if (count == capacity) {
			int new_capacity = capacity * 2;
			int *tmp = realloc(scores, new_capacity * sizeof(int));
			if (tmp == NULL) {
				printf("扩容失败\n");
				free(scores);
				return 1;
			}
			scores = tmp;
			capacity = new_capacity;
			printf("容量不够，已扩容到 %d\n", capacity);
		}
		scores[count] = input[i];
		count++;
	}

	printf("最终存了 %d 个成绩：\n", count);
	for (int i = 0; i < count; i++) {
		printf("%d ", scores[i]);
	}
	printf("\n");

	free(scores);
	scores = NULL;

	return 0;
}
```

<!-- output: 6.2.3 -->
```text
容量不够，已扩容到 4
容量不够，已扩容到 8
最终存了 6 个成绩：
88 92 76 100 54 67
```

容量从 2 到 4 再到 8，只扩容两次就装下 6 个数。翻倍扩容摊薄了搬家的开销，是工程上的标准做法。

## 6.2.4 陷阱一：内存泄漏

申请了内存却不释放，而且程序里再也没有指针指向它——这块内存就"漏"了：系统不能收走它，程序也用不了它。

```c
int *p = malloc(sizeof(int));
*p = 10;
/* 函数要结束了，忘了 free(p) */
```

在只跑一次的小程序里，泄漏几字节无所谓，程序退出时系统会全部回收。真正要命的是**反复执行**的代码：

```c
/* 危险示范：每循环一次漏一块 */
for (int i = 0; i < 100000; i++) {
	int *p = malloc(sizeof(int));
	if (p == NULL) {
		return 1;
	}
	*p = i;
	/* 忘了 free(p) */
}
```

循环 10 万次漏 10 万块，程序越跑越慢，最后把内存吃光。修复方式很朴素：**用完就还**。

```c
for (int i = 0; i < 100000; i++) {
	int *p = malloc(sizeof(int));
	if (p == NULL) {
		return 1;
	}
	*p = i;
	free(p);        /* 用完马上还 */
	p = NULL;
}
```

自查方法：数一数代码里 `malloc`/`calloc`/`realloc` 出现几次，`free` 就该配几次，和数 `fopen`/`fclose` 一样。

## 6.2.5 陷阱二：悬垂指针

内存已经释放，指针还记着那块地址——这个指针就是**悬垂指针**（dangling pointer）。再通过它访问内存，读到的可能是垃圾值，程序也可能崩溃，而且**未必当场崩**：更糟的情况是"看起来还能用"，然后在别处随机出问题。

```c
int *p = malloc(sizeof(int));
if (p == NULL) {
	return 1;
}
*p = 100;

free(p);

printf("%d\n", *p);    /* 错误示范：p 已悬垂，读已释放的内存 */
```

防法在 6.1.5 已经练过：**free 之后立刻置 NULL**。

```c
free(p);
p = NULL;
```

置换 NULL 还有一个现实的好处：6.3 起链表要反复 free 节点，把指针清干净能避免"不小心又 free 一次"——这就连到了第三个陷阱。

## 6.2.6 陷阱三：双重释放

同一块内存释放两次，称为双重释放（double free）。最直接的形态：

```c
int *p = malloc(sizeof(int));
free(p);
free(p);    /* 错误示范：第二次 free，未定义行为，通常崩溃 */
```

更隐蔽的形态是**两个指针指向同一块**：

```c
int *p = malloc(sizeof(int));
int *q = p;     /* q 和 p 指向同一块 */

free(p);
free(q);        /* 错误示范：等于又 free 了一次 p，双重释放 */
```

防法是先想清楚"谁负责释放"：多个指针可以同时指向一块内存，但**只有拥有它的那个指针负责 free，其他指针只是借用**。释放后，所有相关指针都置 NULL：

```c
int *p = malloc(sizeof(int));
if (p == NULL) {
	return 1;
}
int *q = p;     /* q 只是借用 */

/* ... 使用 ... */

free(p);        /* 由 p 释放，只释放这一次 */
p = NULL;
q = NULL;       /* 借用者也不再指向它 */
```

这类错误和悬垂指针一样是未定义行为，编译器不报错、崩溃时机随机。规范的做法是养成习惯：每次 free 之后立刻把指针置 NULL，第二次 `free(NULL)` 是安全无害的（标准规定 free 空指针什么也不做），坑就填上了。

## 6.2.7 三大陷阱对照表

| 陷阱 | 症状 | 防法 |
|------|------|------|
| 内存泄漏 | 申请了不还，内存越占越多 | 每个 `malloc` 配一个 `free` |
| 悬垂指针 | free 后还通过指针访问 | free 后立刻置 `NULL` |
| 双重释放 | 同一块内存 free 两次 | 只由拥有者释放一次；free 后置 `NULL` |
| 忘检查 | `malloc` 失败还继续用 | 每次分配后检查 `== NULL` |

口诀：**要检查、要配对、只还一次、还完置空。**

## 6.2.8 用工具找泄漏

靠眼睛数配对，代码一大难免看漏。好在有专门的工具替你数。最常用的是 Linux 上的 Valgrind：

```bash
valgrind --leak-check=full ./你的程序
```

程序正常跑完后，Valgrind 会报告：有没有泄漏、漏了多少字节、漏在哪一行申请的。比如忘了 `free`，它会明确指出 `definitely lost: 4 bytes` 和对应的源码行。

Valgrind 在 Android（Termux）上装不起来，本书的运行环境用不了它；在 Linux 电脑或虚拟机里照着示例跑一遍即可，用法本身一条命令。Windows 上没有 Valgrind，可以用 Visual Studio 的诊断工具或 Dr. Memory 达到类似效果。

当程序行为诡异（随机崩溃、越跑越慢）时，先想到的就是用工具查内存——这比盯着代码猜快得多。

## 6.2.9 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `arr = realloc(arr, new_size);` | 失败时旧地址丢失，泄漏 | `tmp = realloc(...)`，检查后 `arr = tmp` |
| 循环里 `malloc` 不 `free` | 累积泄漏 | 循环体内用完就 `free` |
| `free(p); printf("%d", *p);` | 悬垂指针 | free 后置 `NULL`，不再访问 |
| `free(p); free(q);`（q 和 p 同一块） | 双重释放 | 只由拥有者释放一次 |
| `calloc`/`realloc` 不检查返回值 | 同 `malloc` | 每次分配都检查 `== NULL` |

## 6.2.10 小结

- `calloc(个数, 大小)` 申请并清零；`realloc(旧指针, 新字节)` 扩容并搬运旧内容。
- 扩容三步曲：临时变量接返回值、检查 `NULL`、成功才覆盖原指针。
- 内存泄漏：申请不还；悬垂指针：还了还用；双重释放：同一块还两次。三者都是未定义行为。
- 口诀：要检查、要配对、只还一次、还完置空。
- 程序诡异时用 Valgrind（Linux）等工具查内存，别硬猜。

6. 编程题：用 `realloc` 实现一个能自动扩容的求和程序。初始容量 2，依次存入 5 个数 `{3, 5, 8, 12, 20}`（容量不够就翻倍），最后输出数组和总和。输出格式如下：

```text
容量不够，已扩容到 4
数组：3 5 8 12 20
总和：48
```

<summary>参考答案</summary>

1. 大小一样，区别在初始内容：`malloc` 的内存是垃圾值，`calloc` 会全部清零。另外 `calloc` 把"个数"和"单个大小"分开传，不容易把字节数算错。
2.

```c
int *tmp = realloc(arr, new_size * sizeof(int));
if (tmp == NULL) {
	/* 失败处理，旧内存仍在 arr 中 */
}
arr = tmp;
```

3. 失败时 `realloc` 返回 `NULL`，直接赋值会用 `NULL` 覆盖 `arr`，旧内存的地址就丢了——既用不了也 `free` 不了，变成内存泄漏。用临时变量接住，失败时旧指针还完好。
4. 双重释放。`q` 和 `p` 指向同一块内存，`free(p)` 之后那块内存已经归还，`free(q)` 等于再释放一次，是未定义行为。正确做法：只释放一次（由拥有者 `p` 负责），然后把 `p` 和 `q` 都置 `NULL`。
5. 输出：

```text
0 0 9
```

`calloc` 把三个元素清零，只有 `arr[2]` 被改成了 9。
6. 参考代码：

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int capacity = 2;
	int count = 0;
	int *arr = malloc(capacity * sizeof(int));
	if (arr == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	int input[] = {3, 5, 8, 12, 20};
	int sum = 0;

	for (int i = 0; i < 5; i++) {
		if (count == capacity) {
			int *tmp = realloc(arr, capacity * 2 * sizeof(int));
			if (tmp == NULL) {
				printf("扩容失败\n");
				free(arr);
				return 1;
			}
			arr = tmp;
			capacity *= 2;
			printf("容量不够，已扩容到 %d\n", capacity);
		}
		arr[count] = input[i];
		sum += input[i];
		count++;
	}

	printf("数组：");
	for (int i = 0; i < count; i++) {
		printf("%d ", arr[i]);
	}
	printf("\n");
	printf("总和：%d\n", sum);

	free(arr);
	arr = NULL;

	return 0;
}
```
