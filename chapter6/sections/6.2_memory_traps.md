# 6.2 动态内存进阶与陷阱

> 💬 **节前语：**
>
> 动态内存很自由，但"自由"是有代价的——**一切都要自己管**。
>
> 自由过头就会出事：
> - 申请了不释放 → 内存被偷偷吃掉（**内存泄漏**）
> - 释放了还用 → 程序崩溃（**悬垂指针**）
> - 释放了两次 → 程序崩溃（**双重释放**）
>
> 这一节，我们先把这些"坑"看得明明白白，再学两个好帮手：**`calloc`**（申请并清零）和 **`realloc`**（原地扩容）。
>
> 准备好了吗？开始吧！

---

## 6.2.1 好帮手1：calloc —— 申请并清零

### 📝 和 malloc 的区别

| 函数 | 语法 | 特点 |
|------|------|------|
| `malloc` | `malloc(字节数)` | 内容**不清零**（垃圾值） |
| `calloc` | `calloc(个数, 每个大小)` | 申请后**自动全填0** |

```c
// 申请 10 个 int，并全部清零
int *arr = (int *)calloc(10, sizeof(int));

// 等价于
int *arr = (int *)malloc(10 * sizeof(int));
for (int i = 0; i < 10; i++) arr[i] = 0;   // 手动清零
```

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int *arr = (int *)calloc(5, sizeof(int));
    if (arr == NULL) {
        printf("分配失败\n");
        return 1;
    }
    
    // 不赋值直接打印：全都是 0
    for (int i = 0; i < 5; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
    
    free(arr);
    return 0;
}
```

输出：
```
0 0 0 0 0 
```

> 📌 **什么时候用 calloc？** 希望数组初始全是 0 的时候。参数写法 `calloc(个数, 单个大小)` 也更不容易算错字节数。

## 6.2.2 好帮手2：realloc —— 动态扩容

### 🤔 问题：数组不够大了

```c
int *arr = (int *)malloc(3 * sizeof(int));
// 存着存着发现……需要 5 个位置了！
```

静态数组只能干瞪眼；动态数组可以——**用 `realloc` 扩大**！

### 📝 基本语法

```c
int *new_arr = (int *)realloc(arr, 新大小字节数);
```

realloc 会**尽量在原地址扩大**；如果原位置后面空间不够，它会在别处重新找一块大的、**把旧内容搬过去**、再自动释放旧空间。你只需要用返回的新指针。

> ⚠️ **重要：必须用返回值！** realloc 可能搬家，旧指针 `arr` 可能就失效了，所以一定写成 `arr = realloc(...)`（用返回值覆盖）。

### 📝 完整例子：从3个扩到5个

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int n = 3;
    int *arr = (int *)malloc(n * sizeof(int));
    if (arr == NULL) return 1;
    
    for (int i = 0; i < n; i++) {
        arr[i] = i + 1;      // 1 2 3
    }
    
    // 扩容：3 个 → 5 个
    int new_n = 5;
    int *tmp = (int *)realloc(arr, new_n * sizeof(int));
    if (tmp == NULL) {       // 扩容失败
        printf("扩容失败\n");
        free(arr);           // 旧内存还在，记得释放
        return 1;
    }
    arr = tmp;               // ✅ 用新指针覆盖
    n = new_n;
    
    // 新位置（下标3、4）的内容是垃圾值，给它们赋值
    arr[3] = 40;
    arr[4] = 50;
    
    for (int i = 0; i < n; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");
    
    free(arr);
    return 0;
}
```

输出：
```
1 2 3 40 50 
```

> 📌 **标准"扩容三步曲"：**
> ```
> 1. int *tmp = realloc(arr, 新大小);   // 先存到临时变量
> 2. if (tmp == NULL) { 失败处理 }       // 检查
> 3. arr = tmp;                          // 成功才覆盖
> ```
> 这样即使失败，旧的 `arr` 也还在（不会丢）。**不要直接 `arr = realloc(arr, ...)`**，万一失败，旧指针就丢了。

## 6.2.3 坑1：内存泄漏（Memory Leak）

### 🤔 什么是泄漏？

申请了内存却**没有释放**，而且程序不再能访问到它 → 这块内存就"漏"了，谁也拿不回来。

```c
// ❌ 泄漏现场
int *p = (int *)malloc(sizeof(int));
*p = 10;
// ... 忘记 free(p)！
```

**后果：** 如果程序不断申请不释放（比如循环里），内存会被一点点吃光，程序越来越慢、最终崩溃。

### 循环里泄漏的例子

```c
// ❌ 危险！每循环一次就漏一块内存
for (int i = 0; i < 100000; i++) {
    int *p = (int *)malloc(sizeof(int));
    *p = i;
    // 忘了 free(p)！→ 10万块内存全漏了！
}
```

**修复：循环内用完就 free：**

```c
// ✅ 循环内申请 + 释放
for (int i = 0; i < 100000; i++) {
    int *p = (int *)malloc(sizeof(int));
    if (p == NULL) return 1;
    *p = i;
    free(p);      // 用完马上还
}
```

> 📌 **自查方法：** 数一数代码里有多少个 `malloc`，就应该有多少个 `free`。就像数 `fopen` 和 `fclose` 一样。

> 🛠️ **工具推荐：** 光靠眼睛难免看漏。Linux/macOS 可以用工具检测泄漏，比如 `valgrind ./程序名` 会告诉你哪里漏了。学会了它，排查内存问题事半功倍（第11章还会专门讲调试工具）。

## 6.2.4 坑2：悬垂指针（Dangling Pointer）

### 🤔 什么是悬垂指针？

内存**已经释放**了，但指针还"记得"那块地址 → 这个指针就是**悬垂的**。

```c
int *p = (int *)malloc(sizeof(int));
*p = 100;
free(p);        // 内存已归还
printf("%d", *p);   // 🚨 悬垂！读一块已释放的内存，结果是垃圾值/崩溃
```

**比喻：** 房子已经被拆了，但你手里还拿着它的门牌号，找过去当然会出事。

### ✅ 修复：释放后置 NULL

```c
free(p);
p = NULL;       // ✅ 让指针"忘掉"那块地址
```

以后再用 p，可以先检查：

```c
if (p != NULL) {   // 安全护栏
    *p = 100;
}
```

> 📌 **习惯成自然：每次 `free` 之后立刻 `p = NULL;`**，悬垂 bug 基本就被杜绝了。

## 6.2.5 坑3：双重释放（Double Free）

### 🤔 什么是双重释放？

同一块内存**释放两次**：

```c
int *p = (int *)malloc(sizeof(int));
free(p);
free(p);        // 🚨 双重释放！第一次已归还，第二次系统就懵了 → 崩溃
```

**注意：** 更隐蔽的是"两个指针指向同一块内存"：

```c
int *p = malloc(sizeof(int));
int *q = p;     // q 和 p 指向同一块
free(p);
free(q);        // 🚨 同一块内存被释放了两次！崩溃
```

### ✅ 修复：弄清楚"谁拥有这块内存"

同一块内存**只能释放一次**。谁负责释放？要提前商量好：

```c
int *p = malloc(sizeof(int));
int *q = p;     // q 只是"借用"一下

// ... 使用 ...

free(p);        // ✅ 由 p 释放一次
p = NULL;
q = NULL;       // q 也别再用了（它和 p 指向同一块，已失效）
```

> 📌 **原则：一个 malloc，只能有一个对应的 free。** 多个指针可以"看"同一块内存，但负责释放的只有一个。

---

## 6.2.6 内存错误小结

| 坑 | 症状 | 怎么防 |
|----|------|--------|
| **泄漏** | 没 free，内存越占越多 | 数 malloc/free 配对 |
| **悬垂** | free 后还用 `*p` | free 后 `p = NULL`，用前检查 |
| **双重释放** | 同一块 free 两次 | 一块内存只释放一次 |
| **没检查** | malloc 失败直接用 | 每次 malloc 后判断 `== NULL` |

> 💡 **记口诀：** `malloc` 要检查、要配对、只释放一次、释放后置 NULL。

## 6.2.7 实战：动态扩容的"学生名单"

把第5章"文件版学生管理系统"里 `#define MAX_STUDENTS 100` 的静态上限，换成**动态扩容**——有多少学生存多少！

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int capacity = 2;    // 初始容量
    int count = 0;       // 当前人数
    int *scores = (int *)malloc(capacity * sizeof(int));
    if (scores == NULL) return 1;
    
    // 模拟不断加入学生成绩：5、88、92、76、100、54
    int new_scores[] = {88, 92, 76, 100, 54, 67};
    int total = 6;
    
    for (int i = 0; i < total; i++) {
        // 装不下了？扩容！
        if (count == capacity) {
            int new_capacity = capacity * 2;
            int *tmp = (int *)realloc(scores, new_capacity * sizeof(int));
            if (tmp == NULL) {
                printf("扩容失败\n");
                free(scores);
                return 1;
            }
            scores = tmp;
            capacity = new_capacity;
            printf("容量不够，已扩容到 %d\n", capacity);
        }
        
        scores[count] = new_scores[i];
        count++;
    }
    
    printf("最终存了 %d 个成绩：\n", count);
    for (int i = 0; i < count; i++) {
        printf("%d ", scores[i]);
    }
    printf("\n");
    
    free(scores);
    return 0;
}
```

输出：
```
容量不够，已扩容到 4
容量不够，已扩容到 8
最终存了 6 个成绩：
88 92 76 100 54 67 
```

> 💡 **这就是"动态数组"的经典套路（每次翻倍扩容）！** 翻倍扩容能保证总次数很少，效率高。第6.3节开始学的链表，其实就是为了解决"数组中间增删麻烦"而生的另一种数据结构。

## 6.2.8 本节小结

这一节我们学了：

✅ **calloc：** 申请内存并自动清零，`calloc(个数, 大小)`

✅ **realloc：** 动态扩容，"扩容三步曲"，必须用返回值

✅ **三大内存坑：** 泄漏（忘了free）、悬垂（free后还用）、双重释放（free两次）

✅ **防止口诀：** malloc 要检查、要配对、只释放一次、释放后置 NULL

> 💡 **记住：堆上的内存，是你自己借来的房子——按时还、只还一次、还完就别再回去住！**
