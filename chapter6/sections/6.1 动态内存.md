# 6.1 动态内存

前五章的程序有一个共同点：变量和数组的大小，都在写代码时就定死了。`int scores[100];` 无论来了 5 个人还是 500 个人，内存都按 100 个 `int` 准备。

这一节把"要多少内存"推迟到程序运行时决定：向系统现要现还，用的正是第 4 章学的指针。

## 6.1.1 栈与堆：两种内存

C 程序的变量住在内存里两个不同的区域：

| 对比项 | 栈（stack） | 堆（heap） |
|--------|-------------|------------|
| 住着什么 | 局部变量、普通数组 | `malloc` 申请的空间 |
| 谁分配 | 编译器自动安排 | 你手动申请 |
| 谁释放 | 函数结束自动清理 | 你必须手动 `free` |
| 大小 | 较小，有上限 | 大得多 |
| 特点 | 自动但死板 | 自由但要自己管 |

```c
int a = 10;              /* a 在栈上 */
int arr[100];            /* arr 在栈上 */
int *p = malloc(4);      /* p 本身在栈上，申请到的空间在堆上 */
```

栈上的内存函数一返回就自动回收，所以用起来省心；堆上的内存系统不会替你收，**申请和释放都要自己负责**。这一章学的 `malloc`/`free` 操作的就是堆。

## 6.1.2 malloc：申请内存

`malloc` 声明在 `stdlib.h` 里，接收要申请的字节数，返回这块内存的地址：

```c
#include <stdlib.h>

int *p = malloc(sizeof(int));    /* 申请 1 个 int 大小的空间 */
```

| 部分 | 含义 |
|------|------|
| `malloc(...)` | memory allocate，分配内存 |
| `sizeof(int)` | 要多大：一个 `int` 占几个字节，让编译器算 |
| `int *p` | 用指针记住这块堆内存的地址 |

两个细节值得强调：

1. **为什么写 `sizeof(int)` 而不是 `4`？** `int` 占几个字节因平台而异，写 `sizeof(int)` 永远正确，换个平台也不用改。
2. **为什么必须用指针接？** `malloc` 返回的是地址（类型是 `void *`，4.6 讲过可以赋给任何对象指针）。堆内存没有名字，只有地址，指针是唯一能记住它的方式。

```c
// 6.1.2 malloc_first.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int *p = malloc(sizeof(int));
	if (p == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	*p = 42;
	printf("*p = %d\n", *p);

	free(p);
	p = NULL;

	return 0;
}
```

<!-- output: 6.1.2 -->
```text
*p = 42
```

## 6.1.3 检查返回值：malloc 可能失败

上面示例里 `if (p == NULL)` 不是摆设。**`malloc` 可能失败**——要的内存太大、系统内存耗尽时，它返回 `NULL` 表示"没要到"。不检查就往下用 `*p`，是解引用空指针，属于未定义行为（4.1 讲过），程序可能当场崩溃。

```c
int *p = malloc(sizeof(int));

*p = 42;        /* 错误示范：没检查 p 是否为 NULL */
```

正确写法每次都不变，和第 5 章 `fopen` 之后检查 `fp == NULL` 是同一个纪律：

```c
int *p = malloc(sizeof(int));
if (p == NULL) {
	printf("内存分配失败\n");
	return 1;
}
```

从这一节起，**每一条 `malloc`（以及 6.2 的 `calloc`、`realloc`）后面都跟着一次 NULL 检查**，本章所有示例都遵守这条规矩，请照做。

## 6.1.4 动态数组：运行时定大小

`malloc` 最常用的场景是"运行时才知道要多大的数组"：要几个就申请几倍的 `sizeof(int)`。申请到的空间用下标访问，和普通数组一模一样：

```c
// 6.1.4 dynamic_array.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int n = 5;    /* 真实场景里 n 可能来自用户输入或文件 */

	int *arr = malloc(n * sizeof(int));
	if (arr == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	for (int i = 0; i < n; i++) {
		arr[i] = (i + 1) * 10;
	}

	for (int i = 0; i < n; i++) {
		printf("arr[%d] = %d\n", i, arr[i]);
	}

	free(arr);
	arr = NULL;

	return 0;
}
```

<!-- output: 6.1.4 -->
```text
arr[0] = 10
arr[1] = 20
arr[2] = 30
arr[3] = 40
arr[4] = 50
```

`arr[i]` 之所以能用，是因为 `arr` 存的就是首元素地址，下标运算是按地址加偏移来算的（4.2 讲过）。动态数组和普通数组在"用"上没有区别，区别全在"要"和"还"上。

注意：`malloc` 拿到的内存**内容是垃圾值**，不会自动清零。想全 0，要么自己循环赋值，要么用 6.2.1 的 `calloc`。

## 6.1.5 free：归还内存

`free` 接收当初 `malloc` 返回的指针，把那块内存还给系统：

```c
free(p);
p = NULL;    /* 好习惯：释放后立刻置 NULL */
```

两点说明：

1. **free 的是什么？** 释放的是 `p` 指向的那块堆内存，不是 `p` 这个指针变量本身。`p` 是栈上的局部变量，函数结束自动消失。
2. **为什么 free 后要置 `p = NULL`？** free 之后 `p` 还记着那块地址，但内存已经作废，再碰它就是悬垂指针（6.2.5 细讲）。置成 `NULL` 之后，误用会更容易被发现：`if (p != NULL)` 这类检查能挡住，直接解引用 `NULL` 也会立刻崩溃在明确的地址上，比"随机读到垃圾值"好排查得多。

```c
// 6.1.5 free_null.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int *p = malloc(sizeof(int));
	if (p == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	*p = 100;
	printf("释放前：*p = %d\n", *p);

	free(p);
	p = NULL;

	if (p == NULL) {
		printf("释放后：p 已置为 NULL\n");
	}

	return 0;
}
```

<!-- output: 6.1.5 -->
```text
释放前：*p = 100
释放后：p 已置为 NULL
```

申请和释放的配对关系，第 5 章已经见过一次：

| 拿 | 还 |
|----|----|
| `malloc`/`calloc`/`realloc` | `free` |
| `fopen` | `fclose` |

## 6.1.6 静态数组 vs 动态数组

| 对比项 | 静态数组 | 动态数组 |
|--------|----------|----------|
| 写法 | `int a[100];` | `int *a = malloc(100 * sizeof(int));` |
| 大小何时定 | 编译时 | 运行时 |
| 在哪个区 | 栈 | 堆 |
| 下标用法 | `a[i]` | `a[i]`，一样 |
| 用完要释放吗 | 不用，自动回收 | 必须 `free` |
| 忘了释放会怎样 | 没这回事 | 内存泄漏（6.2.4） |

一句话：数组换来"不用管"，动态内存换来"要多少给多少"。大小确定就用数组，大小运行时才知道才用 `malloc`——不要为了新学的东西把简单代码改复杂。

## 6.1.7 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `int *p = malloc(4);` | 依赖 `int` 是 4 字节的假设 | `malloc(sizeof(int))` |
| `malloc` 后不检查直接 `*p` | 失败时是空指针，未定义行为 | `if (p == NULL) { ... }` |
| `int x = malloc(sizeof(int));` | 地址塞不进 `int`，类型错误 | `int *p = malloc(sizeof(int));` |
| 用完不 `free` | 内存泄漏 | 每个 `malloc` 配一个 `free` |
| `free(p)` 后继续用 `p` | 悬垂指针 | `free` 后立刻 `p = NULL;` |
| 用 `%lu` 打印 `sizeof` 的结果 | 格式符不匹配 | `printf("%zu", sizeof(int))` |

## 6.1.8 小结

- 栈上的内存自动管理，堆上的内存手动管理；`malloc`/`free` 操作的是堆。
- `malloc(字节数)` 返回地址，用指针接住；大小用 `sizeof` 算，不写死数字。
- **每次 `malloc` 之后必须检查返回值是否为 `NULL`**，和 `fopen` 之后检查 `fp` 是同一条纪律。
- 动态数组用下标访问和普通数组一样；内容是垃圾值，用前先赋值。
- 用完 `free`，并且 free 后立刻把指针置 `NULL`。
- `malloc` 和 `free` 必须成对出现，就像 `fopen` 和 `fclose`。

## 练习

1. `malloc` 和 `free` 声明在哪个头文件里？
2. 局部变量 `int a = 10;` 和 `int *p = malloc(sizeof(int));` 各在内存的哪个区域？
3. 为什么申请 `n` 个 `int` 要写 `n * sizeof(int)`，而不是 `n * 4`？
4. 下面代码有什么问题？

```c
int *p = malloc(100 * sizeof(int));

for (int i = 0; i < 100; i++) {
	p[i] = i;
}
printf("%d\n", p[0]);
```

5. 写出下面程序的输出。

```c
int *p = malloc(2 * sizeof(int));
if (p == NULL) {
	return 1;
}
p[0] = 7;
p[1] = p[0] * 3;
printf("%d %d\n", p[0], p[1]);
free(p);
p = NULL;
```

6. 编程题：申请能装 6 个 `double` 的动态数组，存入 `{1.5, 2.5, 3.5, 4.5, 5.5, 6.5}`，用 `%.1f` 逐行打印每个元素，最后释放。输出格式如下：

```text
arr[0] = 1.5
arr[1] = 2.5
arr[2] = 3.5
arr[3] = 4.5
arr[4] = 5.5
arr[5] = 6.5
```

<details>
<summary>参考答案</summary>

1. `<stdlib.h>`。
2. `a` 在栈上；`malloc` 申请的那 1 个 `int` 在堆上（`p` 这个指针变量本身在栈上）。
3. `int` 占几个字节由平台决定，通常 4 但不保证。写 `sizeof(int)` 让编译器算，代码在任何平台都正确；写死 4 换个平台就可能错。
4. `malloc` 的返回值没检查。要申请 `100 * sizeof(int)` 字节，一旦失败 `p` 是 `NULL`，后面的循环和解引用全是未定义行为。应在使用前加 `if (p == NULL) { ... }`；用完还要 `free(p); p = NULL;`，示例里也没有释放。
5. 输出：

```text
7 21
```

`p[1] = p[0] * 3` 是 7 × 3 = 21。
6. 参考代码：

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	double *arr = malloc(6 * sizeof(double));
	if (arr == NULL) {
		printf("内存分配失败\n");
		return 1;
	}

	double values[] = {1.5, 2.5, 3.5, 4.5, 5.5, 6.5};
	for (int i = 0; i < 6; i++) {
		arr[i] = values[i];
	}

	for (int i = 0; i < 6; i++) {
		printf("arr[%d] = %.1f\n", i, arr[i]);
	}

	free(arr);
	arr = NULL;

	return 0;
}
```
