# 10.1 预处理与宏

> 💬 **节前语：**
>
> 打开你写过的任何 C 程序，第一行几乎都是 `#include <stdio.h>`。你有没有想过：**以 `#` 开头的那一行，到底是什么？**
>
> 其实你早就和"宏"打过无数次照面了——那些 `#define MAX 100`、`#define PI 3.14`，还有 `#include`、`#ifdef`，它们统统属于一个神秘阶段：**预处理（Preprocessing）**。
>
> C 程序的诞生要经过三步：
>
> ```
> 源代码(.c) ──预处理──► 展开后的源码 ──编译──► 汇编/机器码 ──链接──► 可执行程序
>              (处理 # 开头的指令)
> ```
>
> 预处理是在**编译器真正开工之前**，先对源码做一遍"文本加工"。这一节我们就看看这些 `#` 指令到底在干嘛，以及怎么用好它们。准备好了吗？开始吧！

---

## 10.1.1 三步曲：预处理、编译、链接

| 步骤 | 干什么 | 干活的工具 |
|------|--------|-----------|
| ① 预处理 | 处理所有 `#` 指令：把 `#include` 的头文件"抄"进来、把 `#define` 的宏"替换"成内容、处理 `#ifdef` 等 | `cpp` / `gcc -E` |
| ② 编译 | 把（预处理后的）C 代码翻译成机器码 | `gcc -c` |
| ③ 链接 | 把多个编译好的文件 + 库拼成一个可执行程序 | `gcc` |

> 💡 想偷看预处理后的样子？运行 `gcc -E 你的程序.c`，它会把所有 `#include`、`#define` 展开后的"原始文本"吐给你看——理解宏最好的办法就是亲眼看看它被展开成什么样！

---

## 10.1.2 常量宏：给"魔法数字"起名字

还记得我们反复写的 `#define MAX 100` 吗？它叫**对象宏（object-like macro）**，作用就是**文本替换**：编译前，把所有出现的 `MAX` 一词原样替换成 `100`。

```c
#include <stdio.h>

#define PI 3.14159
#define MAX 100

int main() {
    int scores[MAX];                    // 编译器看到的是 int scores[100];
    scores[0] = 88;
    double r = 2.5;

    printf("scores 能存 %d 个成绩，第一个是 %d\n", MAX, scores[0]);  // → 100、88
    printf("圆的面积：%.4f\n", PI * r * r);
    return 0;
}
```

输出：
```
scores 能存 100 个成绩，第一个是 88
圆的面积：19.6349
```

> 📌 **为什么要用宏？** 如果代码里"100"出现 20 次，将来要改成 200，你得改 20 个地方；用 `#define MAX 100` 只改一行！这解决了"**魔法数字**"（含义不明的裸数字）问题，也让代码能"自解释"。

### ⚠️ 三个注意

1. **没有分号！** `#define MAX 100` 结尾不能写 `;`，否则会替换成 `100;` 惹祸
2. **宏名习惯全大写**：`MAX`、`PI`，用来和普通变量区分
3. **只是"文本替换"**，不做任何检查——`#define MAX 100` 替换后，类型错误编译器照样会报，但宏本身不会帮你挡

> 🔎 其实，C 语言还给了我们更"正经"的常量写法，比如 `const int max = 100;` 和枚举 `enum { MAX = 100 };`。宏 vs `const`：宏发生在预处理、纯文本替换；`const` 是真正的变量，编译器能检查类型、还能取地址。**现代 C 更推荐能用 `const`/`enum` 就不用宏**，但宏在"条件编译、生成代码"这类场景依然无可替代。

## 10.1.3 带参宏：像函数，但它是"替换"

除了常量宏，还有**函数式宏（function-like macro）**——长得像函数调用，本质还是文本替换：

```c
#include <stdio.h>

#define SQUARE(x) ((x) * (x))      // 求平方的宏（注意到处是括号！）
#define MAX2(a, b) ((a) > (b) ? (a) : (b))   // 取较大的宏

int main() {
    printf("SQUARE(5) = %d\n", SQUARE(5));          // 5*5
    printf("SQUARE(2+3) = %d\n", SQUARE(2 + 3));    // 必须带括号才等于 25
    printf("MAX2(7, 12) = %d\n", MAX2(7, 12));
    return 0;
}
```

输出：
```
SQUARE(5) = 25
SQUARE(2+3) = 25
MAX2(7, 12) = 12
```

### 🚨 宏的"括号地狱"

`SQUARE(2+3)` 会替换成 `((2+3)*(2+3))` = 25。但如果你偷懒写成 `#define BAD(x) x*x`，那 `BAD(2+3)` 就变成 `2+3*2+3` = 11 了！**凡是参数，都要用括号包起来**——这是带参宏的头号大坑。

### ⚠️ 宏 vs 函数的本质差别

| | 带参宏 | 真正的函数 |
|---|--------|-----------|
| 本质 | 编译前**文本替换** | 编译成代码，运行时调用 |
| 速度 | 没有调用开销 | 有函数调用开销（很小） |
| 类型检查 | 无 | 有 |
| 副作用 | `SQUARE(a++)` 会让 `a` 加好多次！⚠️ | 参数只算一次 |
| 代码体积 | 每用一次复制一份 | 只有一份 |

> ⚠️ **血泪教训：千万别在带参宏里传"有副作用的表达式"。** `SQUARE(a++)` 展开成 `((a++)*(a++))`，`a` 会被自增两次！这种 bug 极难排查。

## 10.1.4 条件编译：让代码"按需出现"

有时我们希望同一份代码，在"调试模式"下多打印一些信息，正式版里又不带。用 `#ifdef ... #endif`：

```c
#include <stdio.h>

#define DEBUG           // 有这一行 → 调试模式；注释掉 → 正式模式

int main() {
    int total = 42;
    printf("开始计算……\n");

#ifdef DEBUG
    printf("[调试] 当前 total = %d\n", total);   // 只有定义了 DEBUG 才会编译
#endif

    printf("计算完成，结果是 %d\n", total);
    return 0;
}
```

- 有 `#define DEBUG` 时，输出会包含 `[调试]` 那一行
- 把 `#define DEBUG` 那行**注释掉**，`[调试]` 代码根本不会进入编译，正式版自然更干净

> 📌 **`#ifdef` 家族：**
> - `#ifdef 名字` / `#ifndef 名字` —— "定义了/没定义"就编译下面内容
> - `#if 条件` —— 按常量条件判断（如 `#if MAX > 50`）
> - 配套 `#else`、`#elif`、`#endif`

> 💡 我们平时用的 `gcc` 就能通过命令行**临时定义宏**，不用改代码：`gcc -DDEBUG 程序.c` 等价于在文件开头写了 `#define DEBUG`。

## 10.1.5 头文件卫士：防止"重复包含"

如果 `a.h` 里有一段定义，`b.c` 和 `c.c` 都 `#include "a.h"`……某些场景下同一内容可能被抄进来两次，导致"重复定义"报错。解法是**头文件卫士（include guard）**——每个头文件都用 `#ifndef/#define/#endif` 包一层：

```c
// 文件：student.h
#ifndef STUDENT_H            // 如果还没定义 STUDENT_H
#define STUDENT_H            // 就定义它

typedef struct {
    char name[32];
    int score;
} Student;

#endif                       // 结束
```

**原理：** 第一次 `#include` 时 `STUDENT_H` 还没定义 → 进入内容、顺手定义它；第二次再 `#include` 时，`STUDENT_H` 已经定义了 → `#ifndef` 不成立 → 整段被跳过。完美防重！

> 🔎 附带一提：`#include <stdio.h>` 用尖括号，是让编译器去**系统目录**找（标准库）；`#include "my.h"` 用双引号，是先在**当前目录**找。头文件怎么写、怎么多文件编译，我们在复习篇《Makefile》已经搭过架子了。

## 10.1.6 本节小结

这一节我们学了：

✅ **三步曲：** 预处理（处理 `#`）→ 编译 → 链接；`gcc -E` 可看展开结果

✅ **常量宏：** `#define PI 3.14`，解决"魔法数字"，全大写、不加分号

✅ **带参宏：** `#define SQUARE(x) ((x)*(x))`，纯文本替换、参数必须加括号、小心副作用

✅ **条件编译：** `#ifdef/#ifndef/#if...#endif`，让代码按需编译，`gcc -D名字` 也能定义

✅ **头文件卫士：** `#ifndef 名字 / #define 名字 ... #endif`，防止重复包含

> 💡 **记住：宏是"编译前的文本游戏"，它本身不检查类型、也不看作用域。用括号、用大写、少放副作用，就稳了。**
