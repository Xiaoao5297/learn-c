# 10.1 预处理与宏

从第一个程序起，我们的代码第一行几乎都是 `#include <stdio.h>`。第 1 章 1.3.2 说它"不是普通的 C 语句"，1.4.5 用过 `#define PI 3.14159`，4.7.3 用 `#ifndef` 写过头文件卫士——这三样东西其实是一家人：它们都以 `#` 开头，都在**编译开始之前**被处理。这一节把这一家人正式介绍给你。

它们属于一个叫**预处理**（preprocessing）的阶段。理解了预处理，你不仅会用宏，还会明白头文件是怎么工作的、调试开关是怎么做的。

## 10.1.1 编译之前，还有一道工序

第 0 章 0.2 节讲过程序的诞生流程。把它展开看，编译之前还有一步：

| 步骤 | 干什么 | 谁来干 |
|------|--------|--------|
| 预处理 | 处理所有 `#` 开头的指令：复制头文件、替换宏、裁剪条件编译 | 预处理器 |
| 编译 | 把预处理后的 C 代码翻译成机器码 | 编译器 |
| 链接 | 把多个目标文件和库拼成可执行程序 | 链接器 |

预处理器不理解 C 语法，它只做**文本加工**：你让它复制，它就复制；你让它替换，它就替换。这一点决定了宏的所有优点和所有坑。

想亲眼看看预处理后的代码长什么样？拿一个真实程序跑 `cc -E`（`-E` 表示只做预处理，不编译）：

```bash
cc -E 10.1.1_include_macro.c | less
```

你会看到几千行代码——那是 `stdio.h` 被原样抄进来的内容，最后才是你自己写的几行，其中 `MAX_SCORES` 已经变成了 `5`。预处理就是一场大规模的"复制粘贴 + 查找替换"。

## 10.1.2 常量宏：编译前就替换掉的文本

```c
// 10.1.1 include_macro.c
#include <stdio.h>

#define MAX_SCORES 5
#define PASS_LINE 60

int main(void)
{
	int scores[MAX_SCORES] = {88, 45, 92, 60, 73};

	printf("共有 %d 个成绩\n", MAX_SCORES);

	for (int i = 0; i < MAX_SCORES; i++) {
		if (scores[i] >= PASS_LINE) {
			printf("%d 及格\n", scores[i]);
		} else {
			printf("%d 不及格\n", scores[i]);
		}
	}

	return 0;
}
```

<!-- output: 10.1.1 -->
```text
共有 5 个成绩
88 及格
45 不及格
92 及格
60 及格
73 及格
```

`#define MAX_SCORES 5` 做的事只有一件：告诉预处理器，"接下来这份文件里，每次遇到 `MAX_SCORES` 这个词，都原样替换成 `5`"。编译器开工时，看到的是 `int scores[5]`——`MAX_SCORES` 三个字已经不存在了。

这就像给快递地址起了个备注名：单子上写的"老家"，实际寄出前已经被替换成详细地址；改地址只需要改备注里那一条，不用改每一张单子。代码里 `100` 出现 20 次、将来要改成 200，用宏只改一行；直接写数字就得改 20 处，漏一处就埋一个 bug——1.4 和 3.1 反复提过的"魔法数字"问题，宏是它的解药之一。

三个老规矩（1.4.5 讲过，这里收拢一下）：

1. **结尾不写分号**。预处理是纯文本替换，`#define MAX 5;` 会把代码替换成 `int scores[5;]`，报错报得莫名其妙。
2. **宏名习惯全大写**。`MAX_SCORES` 一看就知道是宏，和变量区分开。
3. **宏没有类型、没有作用域检查**。预处理器只认"这一串字"，从定义那一行起，到文件结尾都有效。

## 10.1.3 常量宏还是 const

1.4.5 对比过这两者，现在可以把结论说全：

| 对比项 | `#define MAX 5` | `const int max = 5;` |
|--------|-----------------|----------------------|
| 本质 | 编译前的文本替换 | 真正的、有类型的量 |
| 类型检查 | 没有 | 编译器检查 |
| 调试器可见 | 不可见（已被替换掉） | 可见 |
| 能否做数组长度 | 能 | C11 下变长数组可以，但不保证 |
| 能否取地址 | 不能 | 能 |

本书的实践准则：

- **数组和代码里的固定尺寸**（如缓冲区大小、通讯录容量）用常量宏——它必须是编译期常量，宏最直接。本教程从 3.1 起的 `#define MAX_SCORES 100` 都是这个用法。
- **有类型含义的量**（如 `const double pi = 3.14159;`）优先 `const`——类型检查和调试器支持都是真实的福利。

两者不是敌人，是分工不同的两个工具。

```c
// 10.1.2 macro_vs_const.c
#include <stdio.h>

#define TABLE_SIZE 8

int main(void)
{
	const int table_size = 8;

	int macro_table[TABLE_SIZE];
	int const_table[table_size];

	printf("宏定义的数组占 %zu 字节\n", sizeof(macro_table));
	printf("const 定义的数组占 %zu 字节\n", sizeof(const_table));
	printf("两者元素个数相同：%d\n", TABLE_SIZE == table_size);

	return 0;
}
```

<!-- output: 10.1.2 -->
```text
宏定义的数组占 32 字节
const 定义的数组占 32 字节
两者元素个数相同：1
```

## 10.1.4 带参宏：披着函数外衣的文本替换

宏还能带参数，长得像函数：

```c
#define SQUARE(x) ((x) * (x))
```

`SQUARE(5)` 会被替换成 `((5) * (5))`，`SQUARE(a)` 替换成 `((a) * (a))`。参数也是纯文本替换——这一点带来两个必须记住的坑。

```c
// 10.1.3 square_macro.c
#include <stdio.h>

#define SQUARE(x) ((x) * (x))

int main(void)
{
	int a = 4;

	printf("SQUARE(5) = %d\n", SQUARE(5));
	printf("SQUARE(2+3) = %d\n", SQUARE(2 + 3));
	printf("SQUARE(a) = %d\n", SQUARE(a));

	return 0;
}
```

<!-- output: 10.1.3 -->
```text
SQUARE(5) = 25
SQUARE(2+3) = 25
SQUARE(a) = 16
```

**坑一：参数必须各自加括号。** 假如偷懒写成 `#define SQUARE_BAD(x) x * x`，那么 `SQUARE_BAD(2 + 3)` 替换出来是 `2 + 3 * 2 + 3`——按优先级算是 11，不是 25。实参是个表达式时，替换后它就被运算符劈开了。给参数加括号、给整体加括号，是带参宏的铁律。

眼见为实：

```c
// 10.1.4 square_side_effect.c
#include <stdio.h>

#define SQUARE_BAD(x) x *x

int main(void)
{
	int m = 5;

	printf("SQUARE_BAD(5) = %d\n", SQUARE_BAD(5));
	printf("SQUARE_BAD(m + 1) = %d（想要 36）\n", SQUARE_BAD(m + 1));

	return 0;
}
```

<!-- output: 10.1.4 -->
```text
SQUARE_BAD(5) = 25
SQUARE_BAD(m + 1) = 11（想要 36）
```

`m + 1` 替换成 `m + 1 * m + 1`，得 `5 + 5 + 1 = 11`。函数绝不会犯这种错，因为函数的参数是**先算好值再传进去**的；宏的参数是**把表达式原样抄进去**的。

**坑二：别传带副作用的参数。** `SQUARE(a++)` 展开成 `((a++) * (a++))`，`a` 在同一个表达式里被自增两次——而 C 明确规定这种"一个表达式里多次修改同一个变量"的行为是未定义的（1.4.6 提过溢出是未定义行为，这里是另一类）。更糟的是，有的编译器允许它编译通过，结果却说不准。所以用带参宏时，参数只传"干净"的变量或常量，别传 `++`、`--`、函数调用这类有副作用的表达式。

带参宏和真函数的差别，一张表看清：

| 对比项 | 带参宏 | 函数 |
|--------|--------|------|
| 本质 | 文本替换 | 编译成代码，运行时调用 |
| 参数 | 表达式原样抄入 | 先求值再传入 |
| 类型检查 | 无 | 有 |
| 参数求值次数 | 按替换位置出现几次就算几次 | 只算一次 |
| 适用 | 极短的代码片段 | 绝大多数情况 |

**默认写函数，极短且确定安全的场景才用宏。** 2.5 讲过"一个函数只做一件事"，宏不该破坏这条纪律。

## 10.1.5 多行宏与 do-while(0)

有时宏要"做好几件事"，想写成多行。预处理规定：宏的定义到行尾结束，要续行就在行尾放一个反斜杠 `\`。多行宏有个经典外壳——`do { ... } while (0)`：

```c
#define CLEAR_MASK(mask) do { (mask) = 0; } while (0)
```

为什么裹这么一层？因为宏是文本替换，调用处经常长这样：

```c
if (error)
	CLEAR_MASK(mask);   /* 展开后 if 只管 do-while 这一条语句，语义正确 */
```

如果不用 do-while 而直接写成 `{ (mask) = 0; }`，那么 `if (error) { ... } else ...` 这类场合，多出来的分号会让 `else` 对不上号。`do { ... } while (0)` 恰好是"一条语句"，既能包住多行，又能在任何需要一条语句的地方安全展开。这个写法在真实工程里随处可见，认识它、会照着写即可。

```c
// 10.1.5 debug_switch.c
#include <stdio.h>

#define DEBUG

int main(void)
{
	int total = 42;

	printf("开始计算\n");

#ifdef DEBUG
	printf("[调试] 当前 total = %d\n", total);
#endif

	printf("计算完成，结果是 %d\n", total);

	return 0;
}
```

<!-- output: 10.1.5 -->
```text
开始计算
[调试] 当前 total = 42
计算完成，结果是 42
```

## 10.1.6 条件编译：让代码"按需出现"

上面的示例里第一次出现了 `#ifdef ... #endif`。它的意思是：**只有当 `DEBUG` 这个宏被定义时，中间那段代码才参与编译**；否则预处理器直接把它删掉，编译器根本见不到这几行。

这正是"文本加工"的另一个用途——不但能替换文本，还能裁剪文本。常见场景是调试开关：

- 开发时保留 `#define DEBUG`，程序多打印中间信息；
- 发布时删掉（或注释掉）这一行，调试代码一行都不会进可执行文件，既不占体积也不拖速度。

`#ifdef` 家族全家福：

| 指令 | 意思 |
|------|------|
| `#ifdef 名字` | 定义过这个宏，就编译下面一段 |
| `#ifndef 名字` | **没**定义过，就编译下面一段 |
| `#else` / `#elif` | 与 `#ifdef` 配合的"否则/否则如果" |
| `#endif` | 条件编译的结束 |
| `#undef 名字` | 取消一个已定义的宏 |

两个实用补充：

1. **`#undef` 的用途**：取消之后，`#ifdef` 就查不到了。常见于"借用一个宏名做局部开关，用完立刻撤掉"，或者确保某个宏从干净状态开始定义。
2. **命令行也能定义宏**：`cc -DDEBUG hello.c` 等价于在文件开头写了 `#define DEBUG`。这样不用改源码就能切换调试开关，工程里最常用。

条件编译还可以用 `#if 常量表达式` 做数值判断，比如 `#if MAX > 50`。初学阶段用 `#ifdef`/`#ifndef` 就够了。

## 10.1.7 头文件卫士：#ifndef 的头号应用

4.7.3 已经用过这个三件套，当时它只是"照着抄"。现在你知道了原理，它就变得透明：

```c
// student.h
#ifndef STUDENT_H
#define STUDENT_H

/* 头文件内容 */

#endif
```

- 第一次被 `#include` 时，`STUDENT_H` 还没定义过，`#ifndef` 成立，内容被抄进来，顺手定义了 `STUDENT_H`；
- 第二次（哪怕隔着好几层包含关系）再被 `#include` 时，`STUDENT_H` 已存在，`#ifndef` 不成立，整段内容被预处理器跳过。

结果：同一份头文件无论被间接包含多少次，内容都只会出现一份，不会产生"重复定义"的链接错误。这就是"卫士"的含义——它守在头文件门口，第二拨人来了就请回。像第 4 章说的餐盘标签：第一次消毒后贴上"已消毒"，再端过来看到标签就直接跳过。

回忆 4.7 的分工：`#include <stdio.h>` 用尖括号，去系统目录找标准库；`#include "student.h"` 用双引号，先在自己项目目录找。这个区别的根源也在预处理：`#include` 就是"把那个文件的内容原样抄到这里"，抄之前得先找到文件——尖括号和双引号是两种不同的找法。

## 10.1.8 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `#define MAX 5;` | 分号被一起替换进代码 | `#define MAX 5` |
| `#define SQUARE(x) x * x` | 实参是表达式时被劈开 | `#define SQUARE(x) ((x) * (x))` |
| `SQUARE(a++)` | 参数有副作用，展开后多次求值，未定义行为 | 先算 `int t = a++;` 再 `SQUARE(t)` |
| `#ifdef` 配了 `#define` 忘了 `#endif` | 条件编译不闭合，编译错误 | 每个条件编译块用 `#endif` 收尾 |
| 头文件里没有卫士 | 被重复包含时报重复定义 | `#ifndef/#define/#endif` 三件套 |
| `#define PI 3.14` 后又 `#define PI 3.14159` | 重定义宏，部分编译器警告 | 先 `#undef PI` 再重新定义 |

## 10.1.9 小结

- 预处理在编译之前，做纯文本加工：复制头文件、替换宏、裁剪条件编译；`cc -E` 可以查看展开结果。
- 常量宏解决"魔法数字"问题；结尾不写分号、名字全大写、没有类型检查。
- 有类型含义的常量优先 `const`；数组尺寸等编译期常量用宏。
- 带参宏是文本替换：参数和整体都要加括号；不传有副作用的参数；默认写函数。
- 多行宏用反斜杠续行，用 `do { ... } while (0)` 包住，保证任何场合都安全展开。
- 条件编译 `#ifdef/#ifndef/#endif` 让代码按需参与编译；`#undef` 取消宏；`cc -D名字` 从命令行定义宏。
- 头文件卫士是 `#ifndef` 的头号应用，原理是"第一次路过时登记，第二次直接跳过"。

#### 一、选择题

#### 二、填空题

4. 编译；`-E`。
5. `#endif`；`-DDEBUG`。

#### 三、改错题

6. 三处错误：

- 第一处：`#define ADD(a, b) a + b;` 末尾多了分号。预处理是纯文本替换，`int r = ADD(3, 4);` 会展开成 `int r = 3 + 4;;`——多出一条空语句。虽然这个位置碰巧能编译，但它会污染所有"不需要分号"的展开位置，必须删掉。
- 第二处：`ADD` 的参数和整体都缺括号。展开成 `a + b` 后，如果参与更大的表达式（比如 `2 * ADD(3, 4)` 会变成 `2 * 3 + 4`，得 10 而不是 14）就出错。应写成 `#define ADD(a, b) ((a) + (b))`。
- 第三处：`DOUBLE(x) x + x` 同样缺括号。`2 * DOUBLE(5)` 展开成 `2 * 5 + 5`，得 15 而不是想要的 20。应写成 `#define DOUBLE(x) ((x) + (x))`。

修正后的完整程序：

```c
#include <stdio.h>

#define ADD(a, b) ((a) + (b))
#define DOUBLE(x) ((x) + (x))

int main(void)
{
	int r = ADD(3, 4);
	printf("%d\n", r);
	printf("%d\n", 2 * DOUBLE(5));

	return 0;
}
```

输出：

```text
7
20
```

#### 四、编程题

7. 参考代码：

```c
#include <stdio.h>

#define MAX2(a, b) ((a) > (b) ? (a) : (b))

int main(void)
{
	printf("MAX2(7, 12) = %d\n", MAX2(7, 12));
	printf("MAX2(3 + 4, 2 * 3) = %d\n", MAX2(3 + 4, 2 * 3));

	return 0;
}
```

输出：

```text
MAX2(7, 12) = 12
MAX2(3 + 4, 2 * 3) = 7
```

实参是表达式也不怕：替换后是 `((3 + 4) > (2 * 3) ? (3 + 4) : (2 * 3))`，括号保证了先算表达式再比较。

8. 参考代码：

```c
#include <stdio.h>

int main(void)
{
	int items = 3;

	printf("处理完成，共 %d 项\n", items);

#ifdef VERBOSE
	printf("[详细] 共处理 %d 项\n", items);
#endif

	return 0;
}
```

不带 `-DVERBOSE` 编译运行，输出一行 `处理完成，共 3 项`；用 `cc -DVERBOSE` 编译再运行，多一行 `[详细] 共处理 3 项`。调试信息只存在于定义了宏的版本里。

#### 五、思考题

9. 开放性引导，参考方向：一个 int 的 32 个二进制位确实可以各当一个开关，靠"按位"运算一次操作多个开关——打开、关闭、查询都能一步完成；判断奇偶只需看最后一位，按位与上一个 1 就能把它单独取出来；单写的 `&`、`|` 不是逻辑运算，而是按二进制位逐位做与、或。这正是下一节位运算的内容。
