# 10.2 位运算

上一节结尾留了个问题：能不能一次操作数据里的每一个二进制位？能。C 语言为此准备了一组**位运算符**（bitwise operators）：`&`、`|`、`^`、`~`、`<<`、`>>`。

位运算不关心数的"大小"，它直接盯着内存里的 0 和 1 做逻辑判断。第 0 章 0.3 说过"字节是 8 个二进制位"，这一节把这些位摊开来、一个一个摆弄。操作系统管内存权限、网络协议拆数据包、文件系统记录属性，底层全是位运算——它是 C 和硬件"对话"的方言。

## 10.2.1 二进制速成：把数摊开成位

第 0 章认识了"字节是 8 个二进制位"，这里把"位"真正用起来。一个 8 位二进制数，每一位都有权重：

```text
位序号：    7   6   5   4   3   2   1   0
权重：    128  64  32  16   8   4   2   1
```

比如 13 写成 8 位二进制是 `00001101`：8 + 4 + 1 = 13。最右边的位（位 0）权重是 1，叫**最低位**；最左边的位权重最高，叫**最高位**。

最低位是 1，数就是奇数；是 0，就是偶数。二进制数就像一排电灯开关：每个开关只有开（1）和关（0）两种状态，整个数就是这一排开关的组合状态。位运算做的事，就是不动手换数字，而是直接去拨这些开关。

先做几个热身实验：

```c
// 10.2.1 binary_basics.c
#include <stdio.h>

int main(void)
{
	printf("13 >> 1 = %d\n", 13 >> 1);
	printf("13 >> 2 = %d\n", 13 >> 2);
	printf("13 & 1 = %d（13 是奇数）\n", 13 & 1);
	printf("12 & 1 = %d（12 是偶数）\n", 12 & 1);

	unsigned int x = 13;

	for (int i = 3; i >= 0; i--) {
		printf("%u", (x >> i) & 1u);
	}
	printf(" 是 13 的二进制（低 4 位）\n");

	return 0;
}
```

<!-- output: 10.2.1 -->
```text
13 >> 1 = 6
13 >> 2 = 3
13 & 1 = 1（13 是奇数）
12 & 1 = 0（12 是偶数）
1101 是 13 的二进制（低 4 位）
```

最后那个循环里 `(x >> i) & 1u` 是一个通用套路：先把第 `i` 位挪到最低位，再和 1 按位与，就把第 `i` 位单独"抠"了出来。想打印任何整数的二进制，都靠它。

## 10.2.2 六个位运算符

| 运算符 | 名字 | 规则（对每一对位） | 一句话记忆 |
|--------|------|--------------------|------------|
| `&` | 按位与 | 两个都是 1 才得 1 | 全 1 才 1 |
| `\|` | 按位或 | 有一个是 1 就得 1 | 有 1 就 1 |
| `^` | 按位异或 | 两个不同才得 1 | 不同才 1 |
| `~` | 按位取反 | 0 变 1、1 变 0 | 全部反转 |
| `<<` | 左移 | 所有位往左挪，右边补 0 | 位全上移 |
| `>>` | 右移 | 所有位往右挪 | 位全下移 |

注意第一行：写进 Markdown 表格里的 `\|` 只是转义，代码里就是竖线 `|`。

用 6（`00000110`）和 3（`00000011`）逐位演示：

```c
// 10.2.2 six_operators.c
#include <stdio.h>

void print_bits(unsigned int x)
{
	for (int i = 7; i >= 0; i--) {
		printf("%u", (x >> i) & 1u);
	}
}

int main(void)
{
	unsigned int a = 6;
	unsigned int b = 3;

	printf("a     = "); print_bits(a); printf("（%u）\n", a);
	printf("b     = "); print_bits(b); printf("（%u）\n", b);
	printf("a & b = "); print_bits(a & b); printf("（%u）\n", a & b);
	printf("a | b = "); print_bits(a | b); printf("（%u）\n", a | b);
	printf("a ^ b = "); print_bits(a ^ b); printf("（%u）\n", a ^ b);
	printf("~a    = "); print_bits(~a & 0xFFu); printf("（低 8 位）\n");

	return 0;
}
```

<!-- output: 10.2.2 -->
```text
a     = 00000110（6）
b     = 00000011（3）
a & b = 00000010（2）
a | b = 00000111（7）
a ^ b = 00000101（5）
~a    = 11111001（低 8 位）
```

手工核对 `a & b`（全 1 才 1）：

```text
  00000110   （6）
& 00000011   （3）
-----------
  00000010   （2）：只有权重为 2 的那一位，两个数都是 1
```

`a ^ b`（不同才 1）：

```text
  00000110   （6）
^ 00000011   （3）
-----------
  00000101   （5）：第 0 位 0 和 1 不同得 1，第 1 位 1 和 1 相同得 0，第 2 位 1 和 0 不同得 1
```

两个细节：

1. `~a` 是把 `a` 的**全部 32 位**都取反，不只是低 8 位。我们打印时用 `& 0xFFu` 把高 24 位遮掉，只看低 8 位。`0xFF` 就是二进制的 8 个 1，十六进制写法后面会常见到。
2. `~a & 0xFFu` 这类表达式里，`&` 的优先级**低于** `==`（附录的优先级表），和比较运算混用时要加括号：`(x & MASK) == 0`，不写括号意思就变了。

还要特别区分一对长得像的兄弟：`&` 和 `&&` 不是一回事。`3 & 2` 是数值运算，逐位与得 2；`a && b` 是逻辑运算，只回答"都为真吗"，结果是 0 或 1。同理 `|` 和 `||`。写位运算时千万别多敲一个字符。

## 10.2.3 移位：左移翻倍，右移减半（有前提）

二进制数往左挪一位，每个位的权重都翻一倍，整体就是乘 2；往右挪一位，整体就是除 2——前提是**右移的那个数是无符号类型**。

```c
// 10.2.3 shift_rules.c
#include <stdio.h>

int main(void)
{
	int x = 6;

	printf("x     = %d\n", x);
	printf("x << 1 = %d\n", x << 1);
	printf("x << 2 = %d\n", x << 2);

	unsigned int u = 12;

	printf("u     = %u\n", u);
	printf("u >> 1 = %u（无符号：等于除以 2）\n", u >> 1);
	printf("u >> 2 = %u（无符号：等于除以 4）\n", u >> 2);

	return 0;
}
```

<!-- output: 10.2.3 -->
```text
x     = 6
x << 1 = 12
x << 2 = 24
u     = 12
u >> 1 = 6（无符号：等于除以 2）
u >> 2 = 3（无符号：等于除以 4）
```

左移的规则没有歧义：低位补 0，`x << k` 等价于 `x * 2^k`（前提是结果不溢出，溢出就丢弃高位）。

右移要小心，分两种情况：

| 被移的数 | 右移行为 | 能否当"除以 2"用 |
|----------|----------|------------------|
| 无符号整数（`unsigned int` 等） | 高位补 0，相当于除以 2 的 k 次方 | 能，结果确定 |
| 非负的有符号整数 | 大多数编译器高位补 0 | 通常能，但别依赖 |
| 负的有符号整数 | 标准说这是**实现定义**的（多数补符号位，即向下取整） | 不能 |

旧版教材常说"右移一位就是除以 2"，这句话对无符号数成立，对负的有符号数就靠不住了：`-7 >> 1` 在常见平台上得 `-4`（向下取整），而 `-7 / 2` 是 `-3`（向零取整），两者不一样；换一个编译器甚至可能得到别的值。**结论：想用移位代替除法，只用无符号数；有符号数老老实实用 `/`。** 这是位运算里最容易踩的语义坑。

另外，移位的位数不能超过类型的位宽：对 32 位 `int` 做 `x << 32` 是未定义行为，`x << 31` 则可能把符号位挪丢。移位前先想想数有多大。

## 10.2.4 掩码：一个 int 管 32 个开关

位运算最实用的场景来了：把一个整数的每一个位当成一个独立开关。用来挑出或挡住某些位的那个数，叫**掩码**（mask）——像装修时贴的遮蔽胶带，只让该刷漆的位置露出来。

定义一组权限标志，每个占一个位：

```c
#define PERM_READ  1   /* 二进制 001 */
#define PERM_WRITE 2   /* 二进制 010 */
#define PERM_EXEC  4   /* 二进制 100 */
```

注意取值是 1、2、4、8……每个标志独占一个位，互不重叠。于是权限的四种操作各有标准写法：

| 操作 | 写法 | 原理 |
|------|------|------|
| 打开（置 1） | `perm \|= PERM_READ;` | 或上 1，该位必变 1，其余位不变 |
| 关闭（清 0） | `perm &= ~PERM_READ;` | `~` 把掩码反转成"只差这一位是 0"，与上去掉该位 |
| 检查 | `if (perm & PERM_READ)` | 与出该位，非 0 即开 |
| 切换（翻转） | `perm ^= PERM_READ;` | 异或同一掩码两次回到原状 |

完整跑一遍：

```c
// 10.2.4 permission_flags.c
#include <stdio.h>

#define PERM_READ 1
#define PERM_WRITE 2
#define PERM_EXEC 4

int main(void)
{
	unsigned int perm = PERM_READ | PERM_WRITE;

	printf("初始 perm = %u\n", perm);

	if (perm & PERM_READ) {
		printf("可以读\n");
	}
	if (perm & PERM_WRITE) {
		printf("可以写\n");
	}
	if ((perm & PERM_EXEC) == 0) {
		printf("不能执行\n");
	}

	perm |= PERM_EXEC;
	printf("打开 EXEC 后 perm = %u\n", perm);

	perm &= (unsigned int)~PERM_WRITE;
	printf("关闭 WRITE 后 perm = %u\n", perm);

	perm ^= PERM_READ;
	printf("切换 READ 后 perm = %u\n", perm);

	if (perm & PERM_READ) {
		printf("READ 开着\n");
	} else {
		printf("READ 关了\n");
	}

	return 0;
}
```

<!-- output: 10.2.4 -->
```text
初始 perm = 3
可以读
可以写
不能执行
打开 EXEC 后 perm = 7
关闭 WRITE 后 perm = 5
切换 READ 后 perm = 4
READ 关了
```

对照二进制看每一步：`3` 是 `011`，加上 EXEC 变 `111`（7），关掉 WRITE 变 `101`（5），翻转 READ 变 `100`（4）。32 位的 `int` 理论上能塞 32 个这样的开关，改一个开关只需要一条位运算，不用数组、不用循环。

Linux 文件的 `rwx` 权限就是这么存的：`chmod 755` 里的 7 是 `111`（可读可写可执行），5 是 `101`（可读不可写可执行）——你从第 0 章就开始敲的 `chmod +x`，拆开看就是一个位标志系统。

再来一个更贴近应用的例子——用户资料的订阅标志：

```c
// 10.2.5 bitmask_check.c
#include <stdio.h>

#define FLAG_MAIL 1
#define FLAG_PHONE 2
#define FLAG_VIP 4

int main(void)
{
	unsigned int user = FLAG_MAIL | FLAG_VIP;

	printf("订阅邮件：%s\n", (user & FLAG_MAIL) ? "是" : "否");
	printf("绑定手机：%s\n", (user & FLAG_PHONE) ? "是" : "否");
	printf("VIP 会员：%s\n", (user & FLAG_VIP) ? "是" : "否");

	user |= FLAG_PHONE;
	printf("绑定手机后 user = %u\n", user);

	return 0;
}
```

<!-- output: 10.2.5 -->
```text
user = 5
订阅邮件：是
绑定手机：否
VIP 会员：是
绑定手机后 user = 7
```

定义新标志时，下一个值取 8，再下一个取 16……只要每个值只有一个位是 1，这些运算就都成立。`2.5` 讲过"一个函数只做一件事"，位标志则是"一个变量只存一类相关的开关"，思想一脉相承。

## 10.2.5 其他常见套路与两个提醒

几个一眼能认出来的惯用写法：

| 写法 | 含义 |
|------|------|
| `n & 1` | 取最低位：为 1 是奇数，为 0 是偶数 |
| `x & (1u << k)` | 检查第 k 位是否为 1 |
| `x \|= (1u << k)` | 打开第 k 位 |
| `x &= ~(1u << k)` | 关闭第 k 位 |
| `x ^ y ^ y` | 等于 `x`（同一个数异或两次抵消） |

最后一个性质常被用来做最简单的"加密"：原文异或密钥得密文，密文再异或同一密钥就还原。它同时引出一个有名的"炫技"写法——不用临时变量交换两个整数：

```c
a ^= b;
b ^= a;
a ^= b;
```

三步之后 `a`、`b` 确实互换了。但**本书不推荐**：它只对整数有效、可读性差、`a` 和 `b` 是同一个变量时会清零出错，而且现代编译器生成的临时变量交换版本性能毫不逊色。8.1.4 讲过交换必须用临时变量，这个纪律不要为了一时的"巧"放弃。知道有这个技巧、能读懂别人的代码，就够了。

两个提醒收尾：

1. 位运算只对整数类型有意义，`double` 没有位的概念，写了就是编译错误。
2. 移位把位挪出边界就是丢弃（左移溢出）、挪进来的位看类型（无符号补 0）。对负数右移的"实现定义"问题，10.2.3 已经强调过。

## 10.2.6 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `if (x & MASK == 0)` | `==` 优先级高于 `&`，先算了 `MASK == 0` | `if ((x & MASK) == 0)` |
| 把 `&` 写成 `&&`（或相反） | 按位与变成逻辑与，结果完全不同 | 分清：`&` 是位，`&&` 是逻辑 |
| 对负的有符号数用 `>>` 当除 2 | 行为实现定义，结果不可靠 | 无符号数才用移位代替除法，或直接用 `/` |
| `x << 32`（32 位 int） | 移位位数超过位宽，未定义行为 | 移位位数必须在 0 到 31 之间 |
| 标志值取 3、5 这类多位的数 | 两个标志共用位，互相干扰 | 标志值取 1、2、4、8……每值独占一位 |

## 10.2.7 小结

- 位运算直接操作二进制位：`&` 全 1 才 1、`|` 有 1 就 1、`^` 不同才 1、`~` 全部反转、`<<` 左移、`>>` 右移。
- 最低位权重是 1，`n & 1` 即可判断奇偶；`(x >> k) & 1` 可以抠出任意一位。
- 左移 k 位等价乘 2 的 k 次方；右移当除法用**只对无符号数可靠**，负的有符号数右移是实现定义的，别这么写。
- 掩码是位运算的主战场：一个 int 管 32 个开关，`\|=` 打开、`&= ~` 关闭、`&` 检查、`^=` 切换；标志值必须每个独占一位。
- `&`、`|` 是按位运算，`&&`、`||` 是逻辑运算，一个字符之差，含义天壤之别。

#### 一、选择题

1. A。`1100 & 1010 = 1000`，即 8：只有权重为 8 的那一位两边都是 1。
2. B。无符号数右移 2 位等价除以 4，24 / 4 = 6。

#### 二、填空题

4. 不同；`n & 1`（非 0 即奇数）。
5. `1u << k`；2 的幂（每个标志独占一个二进制位）。

#### 三、改错题

6. 三处错误：

- 第一处：`perm & PERM_READ == 0` 少了括号。`==` 的优先级高于 `&`，实际算的是 `perm & (PERM_READ == 0)`，即 `perm & 0`，恒为 0，判断永远"没有读权限"。应改为 `(perm & PERM_READ) == 0`。
- 第二处：`if (perm && PERM_WRITE)` 用了逻辑与。`perm && PERM_WRITE` 只回答"两者都非零吗"，不是检查写权限位。检查标志位应写 `if (perm & PERM_WRITE)`。
- 第三处：逻辑顺序不对——程序先"关闭"写权限（其实 `perm` 里本来就没有写权限位），又检查写权限，再打开写权限，输出 `perm = 3` 与注释意图"检查并修改"不符。若意图是"确认无写权限后再打开"，`perm = perm | PERM_WRITE` 没有语法错误，但前面的检查写错了；修改后这段逻辑应为：检查 `(perm & PERM_WRITE) == 0` 打印"没有写权限"，然后 `perm |= PERM_WRITE`。

修正后的完整程序：

```c
#include <stdio.h>

#define PERM_READ 1
#define PERM_WRITE 2

int main(void)
{
	unsigned int perm = PERM_READ;

	if ((perm & PERM_READ) == 0) {
		printf("没有读权限\n");
	}

	if ((perm & PERM_WRITE) == 0) {
		printf("没有写权限\n");
	}

	perm |= PERM_WRITE;
	printf("perm = %u\n", perm);

	return 0;
}
```

输出：

```text
perm = 3
```

#include <stdio.h>

8. 参考代码：

```c
#include <stdio.h>

#define FLAG_BOLD 1
#define FLAG_ITALIC 2
#define FLAG_UNDER 4

int main(void)
{
	unsigned int style = FLAG_BOLD | FLAG_UNDER;

	printf("粗体：%s\n", (style & FLAG_BOLD) ? "开" : "关");
	printf("斜体：%s\n", (style & FLAG_ITALIC) ? "开" : "关");
	printf("下划线：%s\n", (style & FLAG_UNDER) ? "开" : "关");

	style |= FLAG_ITALIC;
	style &= (unsigned int)~FLAG_UNDER;

	printf("style = %u\n", style);

	return 0;
}
```

输出：

```text
粗体：开
斜体：关
下划线：开
style = 3
```

初始 `style` 是 5（`101`），打开斜体变 7（`111`），关闭下划线变 3（`011`）。
