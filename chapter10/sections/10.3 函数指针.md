# 10.3 函数指针

第 4 章说指针存的是"门牌号"：变量的门牌号是它的地址，数组的门牌号是首元素的地址。那么函数呢？函数编译之后也住在内存里，占一段空间，也有自己的地址。把函数的地址存进一个指针，就是**函数指针**（function pointer）。

有了它，"函数"第一次变成了可以被传递的东西：能存进变量、能装进数组、能当参数传给另一个函数。这是 C 语言实现"把规则交给调用者"的全部秘密，下一节的 `qsort` 就是最大的受益者。

## 10.3.1 声明、赋值、调用

先看最朴素的三步：声明一个能装下"返回 `int`、收两个 `int`"这类函数的指针，让它指向某个函数，然后通过它调用。

```c
// 10.3.1 first_function_pointer.c
#include <stdio.h>

int add(int a, int b)
{
	return a + b;
}

int sub(int a, int b)
{
	return a - b;
}

int mul(int a, int b)
{
	return a * b;
}

int main(void)
{
	int (*op)(int, int);

	op = add;
	printf("op = add：20 + 5 = %d\n", op(20, 5));

	op = sub;
	printf("op = sub：20 - 5 = %d\n", op(20, 5));

	op = mul;
	printf("op = mul：20 * 5 = %d\n", op(20, 5));

	return 0;
}
```

<!-- output: 10.3.1 -->
```text
op = add：20 + 5 = 25
op = sub：20 - 5 = 15
op = mul：20 * 5 = 100
```

同一个 `op`，指谁就像谁：指向 `add` 它就是加法，指向 `mul` 它就是乘法。这像一个万能遥控器：按键本身不固定是"电视"还是"音响"，指到哪台设备，它就控制哪台。

把声明 `int (*op)(int, int)` 拆开读：

| 部分 | 含义 |
|------|------|
| `int` | 指向的函数返回 `int` |
| `(*op)` | `op` 是一个指针 |
| `(int, int)` | 指向的函数接收两个 `int` 参数 |

**`(*op)` 的括号不能省。** 写成 `int *op(int, int)` 就完全变了：这是一个"返回 `int *` 的普通函数"的声明，不是指针。括号在这里的作用和 4.7 提过的 `int (*p)[3]` 一样——把"指针"两个字先钉死，再看外面套的是什么。

三个配套知识点：

1. **函数名就是地址**。`op = add;` 直接写函数名即可，不用 `&add`（写了也对，效果相同）。和数组名类似（4.2），函数名在表达式里自动转换成函数的地址。
2. **两种调用写法都合法**：`op(20, 5)` 和 `(*op)(20, 5)`。前者像普通函数调用，可读性好，本书统一用它；后者把"通过指针找函数再调用"写得直白，读别人的代码时会遇到。
3. **指针类型必须匹配**。`op` 声明成"两个 `int` 进、一个 `int` 出"，就只能指向这种形状的函数。拿一个收一个参数的函数赋给它，编译器立刻报类型不匹配——这是好事，类型系统在替你把关。

## 10.3.2 函数指针数组：按下标选函数

普通指针能进数组，函数指针当然也能。声明一排"同形状"的函数指针，就能用**下标**选函数：

```c
// 10.3.2 op_table.c
#include <stdio.h>

int add(int a, int b)
{
	return a + b;
}

int sub(int a, int b)
{
	return a - b;
}

int mul(int a, int b)
{
	return a * b;
}

int main(void)
{
	int (*ops[])(int, int) = {add, sub, mul};
	const char *names[] = {"加法", "减法", "乘法"};

	int a = 20;
	int b = 5;

	for (int i = 0; i < 3; i++) {
		printf("%s：%d\n", names[i], ops[i](a, b));
	}

	return 0;
}
```

<!-- output: 10.3.2 -->
```text
加法：25
减法：15
乘法：100
```

`int (*ops[])(int, int) = {add, sub, mul};` 声明了一个数组，每个元素都是"两个 `int` 进、一个 `int` 出"的函数指针，初始化列表直接放三个函数名。读法从里往外：`ops[]` 是数组，`(*ops[i])` 说明元素是指针，两边的 `int` 和 `(int, int)` 描述指向的函数形状。

这个结构天生适合**菜单**：菜单选项是 1、2、3……把每个选项对应的函数按顺序放进数组，选项减 1 就是下标，一句 `ops[choice - 1]()` 就完成了分发。对比第 2 章的 `switch` 菜单：`switch` 每加一个选项要加一个 `case`，函数指针数组只往初始化列表里添一个名字，分发的逻辑一行不改。

## 10.3.3 把函数当参数传：apply 的雏形

函数指针最有力量的用法，是把它写进另一个函数的参数表——让一个函数"接收一段行为"：

```c
// 10.3.3 apply_to_array.c
#include <stdio.h>

int twice(int x)
{
	return x * 2;
}

int square(int x)
{
	return x * x;
}

void apply(int nums[], int count, int (*fn)(int))
{
	for (int i = 0; i < count; i++) {
		nums[i] = fn(nums[i]);
	}
}

void print_array(const int nums[], int count)
{
	for (int i = 0; i < count; i++) {
		printf("%d", nums[i]);
		if (i < count - 1) {
			printf(" ");
		}
	}
	printf("\n");
}

int main(void)
{
	int nums[4] = {1, 2, 3, 4};

	apply(nums, 4, twice);
	printf("翻倍后：");
	print_array(nums, 4);

	apply(nums, 4, square);
	printf("平方后：");
	print_array(nums, 4);

	return 0;
}
```

<!-- output: 10.3.3 -->
```text
翻倍后：2 4 6 8
平方后：4 16 36 64
```

`apply` 自己不知道"处理"具体是什么：它只负责遍历数组，每一步调用 `fn` 处理当前元素。**遍历的骨架是 `apply` 的，处理的规则是调用者的**——传 `twice` 就全部翻倍，传 `square` 就全部平方，`apply` 一行不改。

这种"我把函数传给你，你在合适的时机替我调用它"的模式，叫**回调**（callback）。生活里的对应是点外卖留备注：你把"放门口、打电话"这份指示（函数）交给骑手（框架函数），骑手到达时按照指示执行。餐厅只管做菜，"怎么交付"由你的备注决定——骨架和规则分离了。

参数写法 `int (*fn)(int)` 和变量声明一模一样，只是换了名字。`main` 里调用 `apply(nums, 4, twice)` 时，`twice` 自动转换成函数地址，和 10.3.1 的 `op = add` 是同一件事。

## 10.3.4 函数指针数组做菜单分发

把 10.3.2 和 10.3.3 合起来，写一个最小的"菜单分发"演示。真正的交互菜单在 10.5 毕业项目里做完整版，这里先把分发骨架搭出来：

```c
// 10.3.4 menu_demo.c
#include <stdio.h>

void greet(void)
{
	printf("你好，欢迎回来！\n");
}

void show_time_hint(void)
{
	printf("今天也要加油哦（示例菜单，不含真实时间）\n");
}

void farewell(void)
{
	printf("再见！\n");
}

int main(void)
{
	void (*actions[])(void) = {greet, show_time_hint, farewell};

	int choice = 2;

	if (choice >= 1 && choice <= 3) {
		actions[choice - 1]();
	} else {
		printf("没有这个选项\n");
	}

	choice = 1;
	if (choice >= 1 && choice <= 3) {
		actions[choice - 1]();
	}

	return 0;
}
```

<!-- output: 10.3.4 -->
```text
今天也要加油哦（示例菜单，不含真实时间）
你好，欢迎回来！
```

注意两个细节：

1. **无参函数的类型是 `void (*)(void)`**。数组声明里两个 `void` 各管一头：返回值是 `void`，参数表也是 `void`。指给它的三个函数必须严格是这个形状。
2. **下标先验证再使用**。`choice` 减 1 之前先检查范围，和数组下标必须先验证是同一条纪律（3.1.4）；不加检查，用户输入 0 或 9 就会越界读数组——读函数指针数组和读普通数组一样危险。

`qsort` 的第四个参数、菜单分发的数组、`apply` 的 `fn`，本节三个例子其实是同一个思想的三副面孔：**把"做什么"写死，把"怎么处理"留成参数**。下一节看看标准库怎么把这个思想用到排序上。

## 10.3.5 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `int *op(int, int);` | 声明的是返回 `int *` 的函数，不是指针 | `int (*op)(int, int);` |
| `op = add(3, 4);` | 把调用结果赋给指针，类型不匹配 | `op = add;` |
| `op = square;`（`square` 收一个参数） | 函数形状和指针类型不符 | 指针类型与函数严格一致 |
| `ops[choice - 1]()` 不检查 `choice` | 下标越界，行为不可预测 | 先验证 `choice` 范围再调用 |
| 以为 `(*op)(a, b)` 和 `op(a, b)` 有性能差别 | 没有，编译产物相同 | 用可读性好的 `op(a, b)` |

## 10.3.6 小结

- 函数也有地址，函数名在表达式里就是它的地址；存这个地址的指针叫函数指针。
- 声明语法 `int (*op)(int, int)`：`(*op)` 的括号把"指针"钉死，省略就变成函数声明。
- 赋值 `op = add;`，调用 `op(20, 5)`；指针类型必须和函数的"返回值 + 参数表"完全一致。
- 函数指针能进数组，按下标选函数，是菜单分发的标准做法；下标先验证再使用。
- 函数指针当参数就是回调：骨架函数接收调用者传来的"规则"，在合适的时机调用它；`qsort` 是这个思想最著名的应用。

#### 一、选择题

1. B。`(*op)` 的括号声明"op 是指针"，外层的 `int` 和 `(int, int)` 描述指向的函数形状。选项 A 是返回 `int *` 的普通函数。
2. B。函数名在表达式里自动转换成函数的地址，和数组名转换成首元素地址同理。
3. B。回调（callback）：把函数当数据传出去，由接收方在合适的时机调用。

#### 二、填空题

4. `int *`；`(*op)`。
5. `choice - 1`；`choice` 的取值范围（下标合法性）。

#### 三、改错题

6. 三处错误：

- 第一处：`int *op(int, int);` 声明的是"返回 `int *` 的函数 op"，不是函数指针。应改为 `int (*op)(int, int);`。
- 第二处：`op = square;` 类型不匹配。`square` 只收一个 `int` 参数，而 `op` 要求两个 `int` 参数的函数，编译器会报类型不兼容。要么换一个收两个参数的函数，要么再声明一个 `int (*fn1)(int);` 指向 `square`。
- 第三处：`op(5)` 的参数个数与 `op` 的类型不符（需要两个参数）。即便前两处修好，这行也通不过编译；想调用 `square` 应通过对应类型的指针。

修正后的完整程序：

```c
#include <stdio.h>

int add(int a, int b)
{
	return a + b;
}

int square(int x)
{
	return x * x;
}

int main(void)
{
	int (*op)(int, int);
	op = add;
	printf("%d\n", op(3, 4));

	int (*fn1)(int);
	fn1 = square;
	printf("%d\n", fn1(5));

	return 0;
}
```

输出：

```text
7
25
```

int bigger(int a, int b)

8. 参考代码：

```c
#include <stdio.h>

int negate(int x)
{
	return -x;
}

int inc(int x)
{
	return x + 1;
}

void transform(int nums[], int count, int (*fn)(int))
{
	for (int i = 0; i < count; i++) {
		nums[i] = fn(nums[i]);
	}
}

void print_array(const int nums[], int count)
{
	for (int i = 0; i < count; i++) {
		printf("%d", nums[i]);
		if (i < count - 1) {
			printf(" ");
		}
	}
	printf("\n");
}

int main(void)
{
	int nums[3] = {1, 2, 3};

	transform(nums, 3, negate);
	print_array(nums, 3);

	transform(nums, 3, inc);
	print_array(nums, 3);

	return 0;
}
```

输出：

```text
-1 -2 -3
0 -1 -2
```

第二次 transform 作用在第一次的结果上：`-1 + 1 = 0`，`-2 + 1 = -1`，`-3 + 1 = -2`。

#### 五、思考题

9. 开放性引导，参考方向：排序函数需要知道数组首地址、元素个数、单个元素大小和比较规则四样东西；比较函数收两个"待比较元素"的地址，返回负数、0、正数表示"小于、等于、大于"，不能只约定返回 -1 和 1；要通用就得用 `void *` 接住任意类型的地址，配合元素大小让排序函数能定位每一个元素。下一节的 `qsort` 原型 `void qsort(void *base, size_t nmemb, size_t size, int (*compar)(const void *, const void *))` 正是这四样的组合。
