# 0.4 终端与工具

这一节不要求你安装任何东西，只先认识两件事：

1. 终端里的命令大概在做什么。
2. 写 C 会用到的几类工具分别负责什么。

第 1 章会从安装开始，一步步带你操作。

## 0.4.1 终端、Shell 和命令

终端是一个让你输入命令的窗口。Shell 是终端里负责解释命令的程序，常见的有 Bash、Zsh、PowerShell。

打开终端后，通常会看到类似这样的提示符：

```text
user@machine:~/work$
```

它告诉你：

- `user`：当前用户。
- `machine`：机器名。
- `~/work`：当前目录。`~` 表示用户主目录。
- `$`：普通用户提示符。`#` 通常表示 root 用户。

你输入一行命令，按回车，Shell 解析并执行它。

## 0.4.2 最常用的几条命令

先认识下面这些，不要求一次记住：

| 命令 | 作用 | 例子 |
|------|------|------|
| `pwd` | 显示当前目录 | `pwd` |
| `ls` | 列出目录内容 | `ls -l` |
| `cd` | 切换目录 | `cd chapter1` |
| `mkdir` | 创建目录 | `mkdir test` |
| `cat` | 显示文本文件内容 | `cat hello.c` |
| `cp` | 复制文件 | `cp a.c b.c` |
| `mv` | 移动或重命名 | `mv old.c new.c` |
| `rm` | 删除文件 | `rm hello.c` |
| `echo` | 输出一段文字或变量 | `echo $PATH` |
| `clear` | 清屏 | `clear` |

`rm` 删除后通常不会进回收站。初学阶段不要对不熟悉的目录执行 `rm -rf`。

### Windows 下的对应命令

Windows 的 PowerShell 和 CMD 与 Linux Shell 不完全一样。下面只列最常见的对应关系：

| Linux | PowerShell | CMD |
|-------|------------|-----|
| `pwd` | `Get-Location` | `cd` |
| `ls` | `Get-ChildItem` | `dir` |
| `cd` | `Set-Location` | `cd` |
| `mkdir` | `New-Item -ItemType Directory` | `mkdir` |
| `cat` | `Get-Content` | `type` |
| `cp` | `Copy-Item` | `copy` |
| `mv` | `Move-Item` | `move` |
| `rm` | `Remove-Item` | `del` |
| `clear` | `Clear-Host` | `cls` |

> **Windows 提示**
>
> 本书默认使用 Linux 命令。Windows 用户可以安装 Git Bash 或 MSYS2 获得接近 Linux 的终端体验；也可以使用 PowerShell，但要注意路径分隔符和命令名不同。

## 0.4.3 PATH 是什么

当你在终端输入 `gcc`，Shell 怎么知道去哪里找这个程序？

答案是 `PATH` 环境变量。它是一组目录，Shell 会按顺序在这些目录里查找同名程序。

Linux 上可以这样查看：

```bash
echo $PATH
```

输出可能类似：

```text
/usr/local/bin:/usr/bin:/bin
```

如果某个程序所在目录不在 `PATH` 里，就会出现“command not found”或“不是内部或外部命令”。

Windows 上可以在 PowerShell 里查看：

```powershell
$env:PATH
```

安装编译器后，如果终端找不到 `gcc`，最常见的原因不是没装，而是安装目录没有加入 `PATH`，或者安装后没有重新打开终端。

## 0.4.4 写 C 会用到的工具

| 工具 | 作用 | 常见例子 |
|------|------|----------|
| 编辑器 | 写源代码 | VS Code、Vim、Nano、CLion |
| 编译器 | 把源代码翻译成目标文件 | GCC、Clang、MSVC |
| 链接器 | 把目标文件和库组合成可执行文件 | GNU ld、LLVM lld、MSVC link |
| 调试器 | 运行程序并观察变量、调用栈 | GDB、LLDB、VS Code 调试器 |
| 构建工具 | 按规则批量编译和链接 | Make、CMake、Ninja |
| 版本控制 | 记录代码变化，方便回退和协作 | Git |
| 终端 | 输入命令、运行程序 | Bash、Zsh、PowerShell |

初学阶段不需要一次学完。大致顺序是：

1. 先会用一个编辑器写 `.c` 文件。
2. 会用编译器把单个文件编译成可执行文件。
3. 会用 `printf` 和调试器定位问题。
4. 项目变大后，用 Make 管理多个文件。
5. 再往后，用 Git 记录版本。

## 0.4.5 工具之间怎样配合

一个典型的开发循环是：

```text
编辑源代码 → 编译 → 运行 → 观察结果 → 修改 → 再编译
```

出错时，根据错误发生在哪一步选择工具：

- 编译报错：看编译器输出的文件名、行号和错误信息。
- 运行崩溃：用调试器看程序停在哪一行、变量的值是什么。
- 结果不对：用 `printf`、断言或调试器逐步检查。
- 文件太多：用 Make 管理编译规则。

第 1 章会安装编译器和编辑器；第 4 章会讲多文件与 Make；第 5、6 章会讲调试和内存检查。

## 0.4.6 小结

- 终端是输入命令的窗口，Shell 负责解释命令。
- `pwd`、`ls`、`cd`、`mkdir`、`cat` 是最常用的几条命令。
- `PATH` 决定 Shell 去哪些目录找程序。
- 编辑器、编译器、链接器、调试器、构建工具、版本控制各负责一件事。
- 现在只需要认识它们，不需要全部安装和掌握。
