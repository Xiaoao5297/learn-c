# 0.2 程序怎样跑起来

上一节说，程序在硬盘上是一个文件，运行起来以后变成内存里的进程。这一节把中间的过程补上。

## 0.2.1 从源代码到可执行文件

用 C 写程序，大致会经历下面几步：

```mermaid
flowchart LR
    A["源代码<br/>hello.c"] --> B["编译器"]
    B --> C["可执行文件<br/>hello 或 hello.exe"]
    C --> D["操作系统加载"]
    D --> E["进程"]
    E --> F["CPU 执行指令"]
```

可以先把它理解成一句话：

> 源代码是给人看的，可执行文件是给机器执行的，编译器负责翻译。

实际过程还会涉及预处理、汇编、链接等步骤，多个源文件的项目还要把目标文件链接在一起。这些细节第 4 章讲多文件工程时再展开。现在先记住三个角色：

- 源代码：你写的 `.c` 文件，本质上是文本。
- 编译器：把源代码翻译成机器能执行的指令。
- 可执行文件：翻译后的结果，Linux 上常见的是 ELF 格式，Windows 上是 PE 格式。

扩展名不是决定因素。Linux 上的可执行文件通常没有 `.exe` 后缀，Windows 上通常有 `.exe`，但真正决定它能不能运行的是文件格式和权限。

## 0.2.2 编译和运行是两件事

假设你有一个源文件 `hello.c`，在终端里可能会这样操作：

```bash
cc hello.c -o hello
./hello
```

第一条命令是编译，第二条命令是运行。这里只是示意，第 1 章会安装编译器并解释每条命令。

这两步失败时，表现完全不同：

| 阶段 | 常见表现 | 例子 |
|------|----------|------|
| 编译 | 编译器报错，程序根本没有生成 | 少写分号、变量名拼错、类型不匹配 |
| 链接 | 编译通过了，但最后找不到函数或符号 | 忘记链接数学库、函数只有声明没有定义 |
| 运行 | 程序启动了，但中途崩溃或结果不对 | 除以零、数组越界、空指针、文件不存在 |

初学者最容易混淆的是“编译通过”和“程序正确”。编译通过只说明语法和类型大致没问题，不代表逻辑正确。

## 0.2.3 程序、进程和内存

这三个词经常被混着用，可以先这样区分：

| 名词 | 含义 |
|------|------|
| 程序 | 硬盘上的可执行文件，是静态的 |
| 进程 | 程序被操作系统加载并运行起来后的实例，是动态的 |
| 内存 | 进程运行时存放指令和数据的地方 |

同一个程序可以同时运行多个副本，每个副本都是一个独立的进程。例如你可以同时打开两个终端窗口，它们可能运行同一个 shell 程序，但属于两个进程。

进程运行时，内存里大致会有这些东西：

- 机器指令：CPU 要执行的代码。
- 全局数据：程序从头到尾都要用到的数据。
- 栈：函数调用时保存局部变量、参数和返回地址。
- 堆：程序运行时按需申请的内存，例如 `malloc` 分配的空间。

现在不需要记住这些区域的细节，只要知道“内存不是一整块随便用的黑板，而是分区域管理的”。第 4 章讲指针、第 6 章讲动态内存时，会重新回到这里。

## 0.2.4 为什么 C 要先编译

有些语言（例如 Python）可以直接把源文件交给解释器运行。C 通常要先编译成机器指令，再执行。

编译型语言的好处是：

- 运行前就能发现一部分错误。
- 执行时不需要每行都重新解释，通常更快。
- 可以生成独立的可执行文件，交给别人运行时不一定需要源代码。

代价是：

- 修改代码后要重新编译。
- 不同操作系统和 CPU 架构通常要分别编译。
- 编译错误对初学者可能比较陌生。

这也是为什么后面要学编译命令、警告选项和调试工具。写 C 不只是写代码，还要会和这套工具链打交道。

## 0.2.5 小结

- 源代码是文本，编译器把它翻译成可执行文件。
- 编译和运行是两个阶段，编译通过不等于程序正确。
- 程序是硬盘上的文件，进程是程序运行起来后的实例。
- 进程运行时，指令和数据都在内存里。
- C 通常需要先编译再运行。

## 练习

1. “编译成功”是否等于“程序一定正确”？为什么？
2. 同一个程序同时打开两个窗口运行，是一个进程还是两个进程？
3. 为什么 Linux 上的可执行文件通常没有 `.exe` 后缀，但仍然可以运行？

<details>
<summary>参考答案</summary>

1. 不等于。编译只检查语法、类型和链接等阶段的问题，逻辑错误、边界错误和运行时错误仍可能存在。
2. 两个进程。同一个可执行文件可以被加载多次，每次运行都是一个独立进程。
3. 文件能否执行取决于文件格式、权限和操作系统支持，不由扩展名决定。Linux 通常用权限位标记可执行文件，不依赖 `.exe`。

</details>
