# 0.5 小结与自测

这一章没有 C 代码，但概念不少。下面用一张表把它们串起来。

## 0.5.1 概念清单

| 概念 | 一句话解释 |
|------|------------|
| CPU | 执行指令、做运算和判断的部件 |
| 内存 | 临时存放正在运行的程序和数据，断电丢失 |
| 硬盘或 SSD | 长期存放文件，断电保留 |
| 固件 | 主板上负责最基础硬件检查和启动的程序 |
| 引导器 | 负责加载操作系统内核 |
| 内核 | 操作系统的核心，管理 CPU、内存、文件和设备 |
| 源代码 | 人写的文本文件，例如 `.c` |
| 编译器 | 把源代码翻译成机器指令 |
| 可执行文件 | 编译后的程序文件 |
| 进程 | 程序被加载运行后的实例 |
| 字节 | 8 个二进制位，文件的基本单位 |
| 编码 | 字符和字节之间的转换规则 |
| UTF-8 | 常用的 Unicode 编码，兼容 ASCII |
| GBK | 常见的中文编码，Windows 旧环境常用 |
| 路径 | 文件在目录结构中的位置 |
| PATH | Shell 查找命令时使用的目录列表 |
| 终端 | 输入命令的窗口 |
| Shell | 解释并执行终端命令的程序 |

## 0.5.2 五个快速自测

先自己回答，再展开对照。

1. 内存和硬盘，哪个断电后数据会丢失？
2. “程序”和“进程”有什么区别？
3. 编译器报错和程序运行时崩溃，是一回事吗？
4. 为什么 UTF-8 文件在 GBK 控制台里可能乱码？
5. `PATH` 的作用是什么？

<details>
<summary>参考答案</summary>

1. 内存断电丢失；硬盘或 SSD 断电保留。
2. 程序是硬盘上的可执行文件，是静态的；进程是程序被加载运行后的实例，是动态的。
3. 不是。编译错误发生在生成可执行文件之前；运行时崩溃发生在程序已经启动之后。
4. 因为文件字节按 UTF-8 保存，控制台却按 GBK 解释，字节和字符的对应关系错位。
5. 告诉 Shell 去哪些目录查找命令。目录不在 `PATH` 中时，即使程序已安装，也可能提示找不到命令。

</details>
