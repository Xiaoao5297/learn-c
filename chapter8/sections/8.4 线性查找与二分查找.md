# 8.4 线性查找与二分查找

排好序的数据最直接的用途就是查得快。这一节学两种查找：线性查找（linear search）从头一个个找，谁都能用；二分查找（binary search）每次砍掉一半，快得飞起——但有一个硬前提：数据必须已经有序。

## 8.4.1 线性查找：从头找到尾

最朴素的查找：从第一个元素开始挨个比较，找到就返回下标，找完整数组都没有就返回 -1。

```c
// 8.4.1 linear_search.c
#include <stdio.h>

int linear_search(const int nums[], int count, int target)
{
	for (int i = 0; i < count; i++) {
		if (nums[i] == target) {
			return i;
		}
	}

	return -1;
}

int main(void)
{
	int scores[6] = {88, 62, 95, 70, 79, 55};

	int index = linear_search(scores, 6, 70);
	if (index >= 0) {
		printf("找到 70，下标是 %d\n", index);
	} else {
		printf("没找到 70\n");
	}

	index = linear_search(scores, 6, 100);
	if (index >= 0) {
		printf("找到 100，下标是 %d\n", index);
	} else {
		printf("没找到 100\n");
	}

	return 0;
}
```

<!-- output: 8.4.1 -->
```text
找到 70，下标是 3
没找到 100
```

三个要点：

1. **用 -1 表示"没找到"**。下标从 0 开始，-1 不可能是合法下标，一个返回值就能同时表达"找到没"和"在哪"。这是 5.5 练习里 `find_contact` 用过的约定，之后写查找函数都照此办理。
2. **参数加 `const`**。查找只读不改，`const int nums[]` 让编译器守住承诺（3.5.3 的规矩）。
3. **数组是否有序无所谓**。线性查找对任何数据都能用，这是它最大的优点，也是它唯一的优点。

最坏情况（目标在最后或不存在）要比 n 次，属于 O(n)。数据有一百万条，最坏就比一百万次。能不能更快？能——前提是有序。

## 8.4.2 二分查找：每次砍掉一半

数组已经从小到大排好时，可以这样找：看**中间**那个元素——如果它就是目标，结束；如果它比目标小，目标只可能在右半边；比目标大，目标只在左半边。**每比较一次，候选范围砍掉一半。**这就是翻字典的方法：查"木"字旁的字，你不会从第一页翻起，而是先翻到中间，看看手上的页码在目标前面还是后面，再把一半字典直接排除掉。

对有序数组 `12 25 38 47 60 83 95`（下标 0 到 6）找 60：

```text
第 1 次：范围 [0,6]，mid = 3，值 47 < 60 → 目标在右半边，范围变 [4,6]
第 2 次：范围 [4,6]，mid = 5，值 83 > 60 → 目标在左半边，范围变 [4,4]
第 3 次：范围 [4,4]，mid = 4，值 60 == 60 → 找到，返回 4
```

7 个元素只比了 3 次。这和"猜数字"游戏一模一样：每猜一次，根据"大了/小了"排除一半可能。

用循环实现：

```c
// 8.4.2 binary_search.c
#include <stdio.h>

int binary_search(const int nums[], int count, int target)
{
	int left = 0;
	int right = count - 1;

	while (left <= right) {
		int mid = left + (right - left) / 2;

		if (nums[mid] == target) {
			return mid;
		} else if (nums[mid] < target) {
			left = mid + 1;
		} else {
			right = mid - 1;
		}
	}

	return -1;
}

int main(void)
{
	int nums[7] = {12, 25, 38, 47, 60, 83, 95};

	int index = binary_search(nums, 7, 60);
	if (index >= 0) {
		printf("找到 60，下标是 %d\n", index);
	} else {
		printf("没找到 60\n");
	}

	index = binary_search(nums, 7, 61);
	if (index >= 0) {
		printf("找到 61，下标是 %d\n", index);
	} else {
		printf("没找到 61\n");
	}

	return 0;
}
```

<!-- output: 8.4.2 -->
```text
找到 60，下标是 4
没找到 61
```

把这段代码的每个部分掰开看清楚，二分的坑全在边界上：

| 代码 | 为什么这样写 |
|------|--------------|
| `left = 0; right = count - 1;` | 闭区间 `[left, right]`：两端都算"还在候选范围内" |
| `while (left <= right)` | 区间里还剩至少一个元素就继续；`left > right` 说明区间空了，没找到 |
| `mid = left + (right - left) / 2` | 中间下标，见 8.4.3 |
| `left = mid + 1` / `right = mid - 1` | `nums[mid]` 已经比过了，砍半时把 mid 也排除掉 |
| `return -1` | 循环退出即区间为空，目标不在数组里 |

最容易错的是后两个赋值。写成 `left = mid` 或 `right = mid` 看似只差 1，却可能死循环：当区间缩到两个相邻元素时，`mid` 取的是左边那个，`left = mid` 会让区间永远不变。**既然 `nums[mid]` 已经比较过，就让它彻底出局**——查过的字要翻过去，不能停在同一页反复看，记住"mid 已用掉，砍半不带 mid"。

找 61 的过程正好演示了"没找到"：61 比 60 大、比 83 小，最后区间缩成空（`left > right`），循环退出返回 -1。

## 8.4.3 mid 为什么不写成 (left + right) / 2

数学上"中间下标"就是 `(left + right) / 2`，但工程上有一个著名的坑：`left + right` 可能先溢出。

`int` 通常最大约 21 亿。假设在一个超大数组的尾部查找，`left` 和 `right` 都是 15 亿级别，`left + right` 是 30 亿——超出了 `int` 的范围，结果是溢出后的负数或错乱的值，`mid` 随之变成非法下标，轻则查找出错，重则越界访问。

`left + (right - left) / 2` 先算差再算一半：`right - left` 不会超过数组长度，完全没有溢出问题。两种写法在数学上等价：

```text
left + (right - left) / 2 = left + right/2 - left/2 = (left + right) / 2
```

本章的数组都很小，两种写法结果一样；但 `mid` 的这一写法是二分查找的标志性习惯，从第一次写就按规范来，以后在真实工程里不会踩坑。

## 8.4.4 先排序，再二分：黄金搭档

二分的前提是有序，而无序数据只能线性查找。这和图书馆一样：书按索书号排好了才能"直奔那一排"；如果书架被推倒重来过，就只能一本一本翻。真实程序里的标准做法：**先花一次成本排序，之后无数次查找全部享受砍半速度**。就像先把字典按页码装订好，之后每次查词都享受"翻中间"的便利。

```c
// 8.4.3 sort_then_search.c
#include <stdio.h>
#include <stdbool.h>

void bubble_sort(int nums[], int count)
{
	for (int i = 0; i < count - 1; i++) {
		bool swapped = false;

		for (int j = 0; j < count - 1 - i; j++) {
			if (nums[j] > nums[j + 1]) {
				int temp = nums[j];
				nums[j] = nums[j + 1];
				nums[j + 1] = temp;
				swapped = true;
			}
		}

		if (!swapped) {
			break;
		}
	}
}

int binary_search(const int nums[], int count, int target)
{
	int left = 0;
	int right = count - 1;

	while (left <= right) {
		int mid = left + (right - left) / 2;

		if (nums[mid] == target) {
			return mid;
		} else if (nums[mid] < target) {
			left = mid + 1;
		} else {
			right = mid - 1;
		}
	}

	return -1;
}

int main(void)
{
	int scores[6] = {88, 62, 95, 70, 79, 55};

	bubble_sort(scores, 6);

	printf("排序后：");
	for (int i = 0; i < 6; i++) {
		printf("%d", scores[i]);
		if (i < 5) {
			printf(" ");
		}
	}
	printf("\n");

	int target = 79;
	int index = binary_search(scores, 6, target);
	if (index >= 0) {
		printf("%d 分的下标是 %d，排名第 %d\n",
		       target, index, index + 1);
	} else {
		printf("没有 %d 分\n", target);
	}

	return 0;
}
```

<!-- output: 8.4.3 -->
```text
排序后：55 62 70 79 88 95
79 分的下标是 3，排名第 4
```

注意一个隐含的代价：排序会打乱元素原本的顺序。这个例子里"排名第 4"恰好等于排序后的位置加 1，是因为分数本身就是排名依据；如果数组里存的是别的含义的顺序（比如录入顺序），排序后就找不回来了。要对"排序前的位置"做查询，就得连下标一起排序——那是结构体和多关键字排序的事，第 10 章的 `qsort` 会再碰到。

## 8.4.5 二分有多快

每次砍一半，n 个元素最多比较约 log₂n 次（2 的多少次方等于 n，就要比多少次）：

| 数据量 n | 线性查找最坏 | 二分查找最坏 |
|----------|--------------|--------------|
| 1 000 | 1 000 次 | 约 10 次 |
| 1 万 | 1 万次 | 约 14 次 |
| 100 万 | 100 万次 | 约 20 次 |
| 10 亿 | 10 亿次 | 约 30 次 |

10 亿条数据，线性查找最坏要比 10 亿次，二分只要约 30 次。数据量翻倍，线性查找的代价翻倍，二分只多比 1 次。程序员把线性查找记作 O(n)，二分查找记作 O(log n)——**数据越大，二分的优势越夸张**。

| 对比项 | 线性查找 | 二分查找 |
|--------|----------|----------|
| 前提 | 无序也行 | **必须有序** |
| 思路 | 从头挨个比 | 每次砍掉一半 |
| 最坏比较次数 | n 次 | 约 log₂n 次 |
| 记法 | O(n) | O(log n) |
| 适合 | 数据少、无序、只查一次 | 数据多、有序、要查很多次 |

一句话决策：数据多又经常查，先排序再二分；数据少或只查一次，线性查找最省事。

## 8.4.6 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| 对无序数组用二分查找 | 结果不可信，可能找到也可能漏掉 | 先排序，或改用线性查找 |
| `int mid = (left + right) / 2;` | 大范围下 `left + right` 溢出 | `left + (right - left) / 2` |
| `while (left < right)`（配闭区间） | 区间剩一个元素时不查，可能漏 | 闭区间配 `left <= right` |
| 砍半时 `left = mid` 或 `right = mid` | 区间可能不再缩小，死循环 | `left = mid + 1` / `right = mid - 1` |
| 查找函数参数不加 `const` | 函数本该只读，却保留了修改能力 | `const int nums[]` |

## 8.4.7 小结

- 线性查找：挨个比，找到返回下标，找不到返回 -1；无序也能用，最坏 O(n)。
- 二分查找的前提是**有序**；循环版用闭区间 `[left, right]`，条件 `left <= right`。
- 砍半必须排除已比较的 mid：`left = mid + 1`、`right = mid - 1`，否则可能死循环。
- `mid` 用 `left + (right - left) / 2` 计算，避免 `left + right` 溢出。
- 二分最坏约 log₂n 次，O(log n)；"先排序、再二分"是数据多、查询多场景的标准组合。

```text
查找 41：下标 4

```

<details>
<summary>参考答案</summary>

1. 合法下标从 0 开始，-1 不可能是查找结果，所以一个返回值就能同时表达"有没有找到"和"在哪里"。用 0 不行：下标 0 是第一个元素，真实存在，会和"没找到"混淆。
2. 前提是数组有序。对无序数组二分，比较中间元素后"目标在左半边/右半边"的推断不成立，可能把目标所在的半边排除掉，返回错误的"没找到"或找到错误的位置——结果不可信。
3. `left=0, right=6`，mid=3，`nums[3]=25`，正好等于目标，一次就找到，返回 3。
4. 以 `nums = {12, 25, 38, 47, 60, 83, 95}` 找 61 为例：`left=0, right=6`，mid=3（47 < 61），`left = mid = 3`；mid=4（60 < 61），`left = mid = 4`；mid=5（83 > 61），`right = mid - 1 = 4`；此时 `left=4, right=4`，mid=4（60 < 61），`left = mid = 4`——区间再也不缩小，死循环。正确写法 `left = mid + 1` 会在几步后让 `left > right` 正常退出。
5. 线性查找最坏 100 万次；二分约 log₂1000000 ≈ 20 次。差距约 5 万倍。
6. 参考代码：

```c
#include <stdio.h>

int binary_search_rec(const int nums[], int left, int right, int target)
{
	if (left > right) {
		return -1;
	}

	int mid = left + (right - left) / 2;

	if (nums[mid] == target) {
		return mid;
	} else if (nums[mid] < target) {
		return binary_search_rec(nums, mid + 1, right, target);
	} else {
		return binary_search_rec(nums, left, mid - 1, target);
	}
}

int main(void)
{
	int nums[7] = {3, 9, 17, 25, 41, 58, 72};

	int index = binary_search_rec(nums, 0, 6, 41);
	if (index >= 0) {
		printf("查找 41：下标 %d\n", index);
	} else {
		printf("查找 41：没找到\n");
	}

	index = binary_search_rec(nums, 0, 6, 100);
	if (index >= 0) {
		printf("查找 100：下标 %d\n", index);
	} else {
		printf("查找 100：没找到\n");
	}

	return 0;
}
```

递归版的出口是 `left > right`（区间空），递归调用时同样要用 `mid + 1` 和 `mid - 1` 排除已比较的 mid。
