# 8.1 冒泡排序

第 3 章的 3.5.5 已经用冒泡排序给数组排过序，也见过 3.5.6 的 `swapped` 提前退出优化。当时它是"数组与函数"的一个应用。这一节把它当正式的排序算法来学：说清每一趟到底发生了什么、为什么这样写是对的，并第一次给算法"数一数工作量"。

排序是把一组数据按某个顺序重新排列。本章默认**从小到大**（升序），其他顺序只是比较条件的方向不同。

## 8.1.1 核心思路：相邻两个比一比，大的往后换

冒泡排序（bubble sort）只做一件事，反复做很多遍：从前往后，把相邻的两个数比较，前面的比后面的大就交换。像体育课排队：老师不从队头跳到队尾，只挨个看相邻的两个人，高个站后面就让两人换位，一排扫下来，最高的那位就一路"换"到了队尾。

用 `5, 2, 9, 1, 7` 模拟第一趟（下标 0 到 4，每步列出比较的两个相邻位置）：

```text
比较 a[0] a[1]：5 和 2，5 > 2，交换 → 2 5 9 1 7
比较 a[1] a[2]：5 和 9，5 < 9，不动 → 2 5 9 1 7
比较 a[2] a[3]：9 和 1，9 > 1，交换 → 2 5 1 9 7
比较 a[3] a[4]：9 和 7，9 > 7，交换 → 2 5 1 7 9
```

一趟下来，最大的 9 被相邻交换一步步"推"到了末尾。这个过程像水里的气泡往上冒，冒泡排序因此得名。

发现规律：**每一趟，都会把未排好部分里最大的数推到这趟范围的末尾归位**。有 n 个数，最多 n − 1 趟——排好 n − 1 个，剩下那一个自然就位。

## 8.1.2 完整地走一遍

对 `5, 2, 9, 1, 7` 全程模拟（竖线右边是已归位的部分）：

```text
原始：  5 2 9 1 7

第 1 趟：2 5 1 7 | 9    9 归位
第 2 趟：2 1 5 | 7 9    7 归位，这趟没碰 9
第 3 趟：1 2 | 5 7 9    5 归位
第 4 趟：1 | 2 5 7 9    2 归位，排序完成
```

注意每趟的范围都在缩短：第 2 趟只比较到下标 3 为止，因为 9 已经归位。就像排队时已经站到队尾的高个同学不用再看，老师接下来只管前面那段——已归位的 `i` 个数不用再碰。这就是代码里内层边界 `count - 1 - i` 那个 `- i` 的来历。

## 8.1.3 基本实现

```c
// 8.1.1 bubble_sort.c
#include <stdio.h>

void bubble_sort(int nums[], int count)
{
	for (int i = 0; i < count - 1; i++) {
		for (int j = 0; j < count - 1 - i; j++) {
			if (nums[j] > nums[j + 1]) {
				int temp = nums[j];
				nums[j] = nums[j + 1];
				nums[j + 1] = temp;
			}
		}
	}
}

void print_array(const int nums[], int count)
{
	for (int i = 0; i < count; i++) {
		printf("%d", nums[i]);
		if (i < count - 1) {
			printf(" ");
		}
	}
	printf("\n");
}

int main(void)
{
	int nums[5] = {5, 2, 9, 1, 7};

	printf("排序前：");
	print_array(nums, 5);

	bubble_sort(nums, 5);

	printf("排序后：");
	print_array(nums, 5);

	return 0;
}
```

<!-- output: 8.1.1 -->
```text
排序前：5 2 9 1 7
排序后：1 2 5 7 9
```

三层结构各管各的：

| 部分 | 职责 | 说明 |
|------|------|------|
| 外层 `i` | 控制趟数 | 一共 `count - 1` 趟 |
| 内层 `j` | 一趟里的相邻比较 | 边界 `count - 1 - i`，每趟缩短 |
| `if` + 三行交换 | 顺序不对就纠正 | 借助 `temp`，顺序不能乱 |

`bubble_sort` 要修改数组，参数不能加 `const`；`print_array` 只读不改，参数加了 `const`——这套纪律是 3.5.3 定下的，从这一章开始所有排序、查找函数都照此办理。数组传参退化为指针，函数里改的就是原数组，所以 `bubble_sort` 没有返回值也能生效（3.5.1 讲过）。

## 8.1.4 交换为什么必须用临时变量

```c
int temp = nums[j];      /* ① 先把 nums[j] 存到临时变量 */
nums[j] = nums[j + 1];   /* ② 此时 nums[j] 被覆盖，旧值已经在 temp 里 */
nums[j + 1] = temp;      /* ③ 把旧值放进 nums[j + 1] */
```

两杯水互换，得先找个空杯子倒一下。直接对倒会混掉。最常见的错误写法是漏掉 `temp`：

```c
nums[j] = nums[j + 1];
nums[j + 1] = nums[j];   /* 错误：nums[j] 已被覆盖，两个位置变成同一个值 */
```

执行完这两行，`nums[j]` 和 `nums[j + 1]` 相同，原来的 `nums[j]` 彻底丢失。编译器不报错，数据悄悄坏掉——这种错误靠运行结果才能发现。

## 8.1.5 提前退出：swapped 标志

3.5.6 已经见过这个优化，这里把它说透。考虑一个场景：数组 `{1, 2, 3, 5, 4}`，只有 4 和 5 两个数逆序，一趟就排好了。但基本版不管这些，剩余的趟数一趟不少全跑完——每次都在做无用功。

办法是给每一趟装一个"哨兵"：某趟**一次交换都没发生**，说明任意相邻两个都有序，整个数组已经排好，后面的趟数全部不用跑——就像排队扫了一整排没人需要换位，老师一看，队伍已经齐了，收工。

```c
// 8.1.2 bubble_sort_opt.c
#include <stdio.h>
#include <stdbool.h>

void bubble_sort(int nums[], int count)
{
	for (int i = 0; i < count - 1; i++) {
		bool swapped = false;

		for (int j = 0; j < count - 1 - i; j++) {
			if (nums[j] > nums[j + 1]) {
				int temp = nums[j];
				nums[j] = nums[j + 1];
				nums[j + 1] = temp;
				swapped = true;
			}
		}

		if (!swapped) {
			break;
		}
	}
}

int main(void)
{
	int sorted[5] = {1, 2, 3, 4, 5};
	int almost[5] = {1, 2, 3, 5, 4};

	bubble_sort(sorted, 5);
	bubble_sort(almost, 5);

	printf("有序数组：");
	for (int i = 0; i < 5; i++) {
		printf("%d", sorted[i]);
		if (i < 4) {
			printf(" ");
		}
	}
	printf("\n");

	printf("近乎有序：");
	for (int i = 0; i < 5; i++) {
		printf("%d", almost[i]);
		if (i < 4) {
			printf(" ");
		}
	}
	printf("\n");

	return 0;
}
```

<!-- output: 8.1.2 -->
```text
有序数组：1 2 3 4 5
近乎有序：1 2 3 4 5
```

两个数组的结果都对。差别在过程：`sorted` 第一趟零交换，`swapped` 保持 `false`，直接 `break`——只跑了 1 趟；`almost` 第一趟发生 1 次交换排好，第二趟零交换退出——只跑了 2 趟，而不是 4 趟。

`swapped` 的用法是 `bool` 类型的典型场景（第 2 章 2.6 讲过规范）：它表达的是"这趟交换过没有"这个判断结果。判断"排好没有"的是**零交换**，不是"有没有交换过奇数次"之类的直觉，记住这个判据就行。

## 8.1.6 冒泡的工作量：第一次数比较次数

排 5 个数感觉不出快慢，把规模放大再数：

```text
第 1 趟比 n - 1 次
第 2 趟比 n - 2 次
……
总比较次数 = (n-1) + (n-2) + ... + 1 = n(n-1)/2，约 n²/2
```

| n | 比较次数约 |
|---|-----------|
| 1 000 | 50 万 |
| 1 万 | 5000 万 |
| 10 万 | 50 亿 |

规模每扩大 10 倍，工作量膨胀约 100 倍。程序员把这类增长记作 O(n²)（n 的平方级）。本章只用"数次数"体会快慢，不展开记号；要记住的感觉是：**n² 级的算法，数据一大就扛不住**——这正是后面要学更快的排序（8.5）和查找（8.4）的原因。

提前退出优化的价值也在这里：它只对"近乎有序"的数据有效，乱序数据该跑的趟数一趟不少。它救不了 O(n²)，只是别让已经排好的数据白跑。

## 8.1.7 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| 交换时漏掉 `temp` | 一个值被覆盖丢失 | 三行交换，`temp` 先存后还 |
| 内层边界写成 `j < count - 1` | 已归位的元素反复比较（结果仍对，但白跑） | `j < count - 1 - i` |
| 外层写成 `i <= count - 1` | 最后一趟只剩一个数，白跑一趟 | `i < count - 1` |
| 比较条件写成 `>=` | 相等也交换，白做功 | 升序用 `>`，降序用 `<` |
| `swapped` 声明在内层循环里 | 每个位置重置，判断的不是整趟 | 声明在内层之前、外层之内 |

## 8.1.8 小结

- 冒泡排序：相邻两两比较，大的往后换；每趟把未排好部分的最大数送到位。
- n 个数最多 n − 1 趟；内层边界 `count - 1 - i`，`- i` 是因为尾部已归位。
- 交换必须借助临时变量，三行顺序不能乱。
- `swapped` 标志实现提前退出：整趟零交换即已有序，直接结束。
- 比较次数约 n²/2，属于 O(n²)；数据一大就慢，这是学后续算法的动机。

6. 编程题：用带提前退出的冒泡排序把 `{64, 25, 90, 12, 88, 33}` 从小到大排序，并在每趟结束后打印一次数组（趟内零交换的趟不算，直接退出）。

<details>
<summary>参考答案</summary>

1. 第 1 趟：`1 2 3` 后接交换过程——依次比较 (3,1) 交换得 `{1,3,2}`，(3,2) 交换得 `{1,2,3}`。第 1 趟结束是 `{1,2,3}`；第 2 趟零交换，提前退出。
2. 每趟结束，末尾 `i` 个元素已经归位，再比较它们纯属浪费。`count - 1 - i` 让比较范围每趟缩短一格。
3. 两处都是原来的 `nums[j + 1]`。第一行把 `nums[j]` 覆盖掉了，旧值丢失，没有临时变量接住它。
4. 把比较条件 `nums[j] > nums[j + 1]` 改成 `nums[j] < nums[j + 1]`。这样小的数被换到后面，大的数往前冒。
5. `swapped` 声明在内层循环体内，每比较一个位置就重置一次，它表示的是"这个位置交换过没有"，不是"这一趟交换过没有"。应在内层之前声明；而且内层里每次比较后都判断 `break`，会在第一次没交换时就退出整趟，逻辑完全错乱。正确写法见 8.1.2：`swapped` 在外层循环体内、内层之前声明，`if (!swapped) break;` 放在内层之后。
6. 参考代码：

```c
#include <stdio.h>
#include <stdbool.h>

int main(void)
{
	int nums[6] = {64, 25, 90, 12, 88, 33};

	for (int i = 0; i < 5; i++) {
		bool swapped = false;

		for (int j = 0; j < 5 - i; j++) {
			if (nums[j] > nums[j + 1]) {
				int temp = nums[j];
				nums[j] = nums[j + 1];
				nums[j + 1] = temp;
				swapped = true;
			}
		}

		printf("第 %d 趟：", i + 1);
		for (int k = 0; k < 6; k++) {
			printf("%d", nums[k]);
			if (k < 5) {
				printf(" ");
			}
		}
		printf("\n");

		if (!swapped) {
			break;
		}
	}

	return 0;
}
```
