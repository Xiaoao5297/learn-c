# 8.2 选择排序

冒泡排序一趟里可能交换很多次——相邻的两个不对就换，一路换过去。如果交换的对象是很大的结构体（比如第 4 章那种几十字节的 `struct student`），每次交换都要整块搬动内存，就显得很浪费。

这一节学选择排序（selection sort）：它把"找"和"换"分开——先在未排好的部分里**找出**最小的，最后只**交换一次**。就像食堂窗口挑餐盘：先绕着餐车把最干净的盘子看一圈、心里记住是哪只，最后一次性伸手拿走，而不是看见一只更干净的就把手里这只扔回去换。

## 8.2.1 核心思路：两段式，每趟挑一个最小

把数组看成两段：左边是已排好区（逐渐变长），右边是未排区（逐渐变短）。就像老师按身高给全班排位：从矮到高，每一轮把剩下的人里最矮的那位叫出来站到队头指定位置。每一趟只做两件事：

1. 在未排区里找出最小的元素，**记住它的下标**（先不交换）；
2. 一趟扫完后，把它和未排区的第一个元素交换——这个最小值就归位了。

对 `5, 2, 9, 1, 7` 模拟（竖线左边是已排好区）：

```text
初始：5 2 9 1 7 | 未排区 {5,2,9,1,7}

第 1 趟：最小是 1（下标 3）→ 和 5 交换 → 1 | 2 9 5 7
第 2 趟：最小是 2（下标 1）→ 已在开头，不换   → 1 2 | 9 5 7
第 3 趟：最小是 5（下标 4）→ 和 9 交换       → 1 2 5 | 9 7
第 4 趟：最小是 7（下标 4）→ 和 9 交换       → 1 2 5 7 | 9
```

这就是选择排序的**不变量（invariant）**——每一趟开始前都成立的性质：

> 竖线左边的部分已经排好，且每个元素都不大于右边的任何元素。

只要每一趟都维护这条性质，n − 1 趟之后右半区只剩一个元素，整个数组必然有序。写循环类算法时先想清楚不变量，边界条件就不容易写错；8.3 的插入排序会再见到一条不同的不变量。

## 8.2.2 实现

```c
// 8.2.1 selection_sort.c
#include <stdio.h>

void selection_sort(int nums[], int count)
{
	for (int i = 0; i < count - 1; i++) {
		int min_index = i;

		for (int j = i + 1; j < count; j++) {
			if (nums[j] < nums[min_index]) {
				min_index = j;
			}
		}

		if (min_index != i) {
			int temp = nums[i];
			nums[i] = nums[min_index];
			nums[min_index] = temp;
		}
	}
}

void print_array(const int nums[], int count)
{
	for (int i = 0; i < count; i++) {
		printf("%d", nums[i]);
		if (i < count - 1) {
			printf(" ");
		}
	}
	printf("\n");
}

int main(void)
{
	int nums[5] = {5, 2, 9, 1, 7};

	printf("排序前：");
	print_array(nums, 5);

	selection_sort(nums, 5);

	printf("排序后：");
	print_array(nums, 5);

	return 0;
}
```

<!-- output: 8.2.1 -->
```text
排序前：5 2 9 1 7
排序后：1 2 5 7 9
```

对照 8.2.1 的思路看代码：

| 部分 | 对应思路 | 说明 |
|------|----------|------|
| `min_index = i` | 假设未排区第一个就是最小 | 初值必须是 `i`，不是 0 |
| 内层 `j` 从 `i + 1` 扫到末尾 | 在未排区找最小 | 只记下标，不交换 |
| `if (min_index != i)` 后交换 | 把最小值换到未排区开头 | 已在开头就不必换 |

两个细节值得专门强调：

1. **`min_index` 的初值必须是 `i`**。写成 0 会跑到已排好区里找最小，把归位过的元素又翻出来，破坏 8.2.1 的不变量。这和 3.1.8 "求最值先把结果设为第一个元素"是同一个套路，只不过"第一个"随着趟数在移动。
2. **找最值阶段只记下标**。找到更小的更新 `min_index`，而不是当场交换——一趟最多一次交换的关键就在这里。就像记住"最矮的是 3 排那个同学"，先不动手，全班看完了再去请他出列。

## 8.2.3 少交换，但没少比较

选择排序省在交换，不省在比较：

- 交换：每趟最多 1 次，全程最多 n − 1 次。
- 比较：每趟都要把未排区完整扫一遍，总次数仍是 (n−1) + (n−2) + … + 1 ≈ n²/2，和冒泡一个级别。

| 对比项 | 冒泡排序 | 选择排序 |
|--------|----------|----------|
| 每趟的保证 | 未排区的最大数冒到末尾 | 未排区的最小数换到开头 |
| 每趟交换次数 | 可能很多次 | 最多 1 次 |
| 每趟比较次数 | `count - 1 - i` | 一样，`count - 1 - i` |
| 对近乎有序的数据 | 加 `swapped` 后提前退出 | 没有收益，照常扫完 |
| 不变量 | 尾部 `i` 个元素已归位 | 前部 `i` 个元素已归位且都不大于后部 |

所以选择排序适合**交换很贵**的场景：数据是很大的结构体、或者在慢速存储上，搬运一次代价高，它尽量少搬。就像搬的是一整箱书而不是一张纸条——每搬一次都要出大力，那就先看准、少搬几次。但比较次数没省，整体仍是 O(n²)；对已经接近有序的数据也没有冒泡加 `swapped` 后那种加速。

## 8.2.4 变一变方向：从大到小

把内层比较从 `nums[j] < nums[min_index]` 改成 `nums[j] > nums[min_index]`（找最大的），交换后就是降序：

```c
// 8.2.2 selection_desc.c
#include <stdio.h>

void selection_sort_desc(int nums[], int count)
{
	for (int i = 0; i < count - 1; i++) {
		int max_index = i;

		for (int j = i + 1; j < count; j++) {
			if (nums[j] > nums[max_index]) {
				max_index = j;
			}
		}

		if (max_index != i) {
			int temp = nums[i];
			nums[i] = nums[max_index];
			nums[max_index] = temp;
		}
	}
}

int main(void)
{
	int nums[6] = {64, 25, 90, 12, 88, 33};

	selection_sort_desc(nums, 6);

	for (int i = 0; i < 6; i++) {
		printf("%d", nums[i]);
		if (i < 5) {
			printf(" ");
		}
	}
	printf("\n");

	return 0;
}
```

<!-- output: 8.2.2 -->
```text
90 88 64 33 25 12
```

排序算法改方向几乎都只动比较条件，这一点和 3.5.5 的冒泡一样。

## 8.2.5 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `int min_index = 0;` | 跑进已排好区找最小，破坏不变量 | `int min_index = i;` |
| 内层从 `j = i` 开始 | 多比较一次自己和自己（结果对，白费） | `j = i + 1` |
| 找到更小的当场交换 | 退化成一趟多次交换，失去选择排序的意义 | 只记下标，扫完再换 |
| 交换不判 `min_index != i` | 自己和自己交换（结果对，白做） | 先判断再交换 |
| 外层写成 `i <= count - 1` | 最后一趟未排区只剩一个数，白跑 | `i < count - 1` |

## 8.2.6 小结

- 选择排序：每趟在未排区找最小的下标，和未排区开头交换；一趟最多一次交换。
- 不变量：前 `i` 个元素已排好，且都不大于未排区的任何元素。
- `min_index` 初值必须是 `i`；找最值只记下标，扫完再换。
- 交换少（最多 n − 1 次）但比较不省（仍约 n²/2，O(n²)），适合交换代价高的场景。
- 升序改降序只需把比较条件反过来。


<details>
<summary>参考答案</summary>

1. 每趟开始前，数组前 `i` 个元素已经排好序，并且每一个都不大于未排区里的任何元素。每趟挑选并交换后，这个性质对 `i + 1` 仍然成立。
2. 第 1 趟：最小是 1，和 4 交换 → `1 2 5 4 3`；第 2 趟：未排区 `{2,5,4,3}` 最小是 2，已在开头 → `1 2 5 4 3`；第 3 趟：最小是 3，和 5 交换 → `1 2 3 4 5`；第 4 趟：最小是 4，已在开头 → `1 2 3 4 5`。
3. 会在已排好区里找最小。已排好区的元素都不大于未排区的元素，所以"最小"几乎总落在已排好区的前几个位置，交换会把已归位的小元素换到未排区开头，再把某个大元素换进已排好区，排序结果错乱。例如 `{1, 2, 9, 5, 7}`：第 2 趟未排区是 `{2,9,5,7}`，最小是 2（下标 1），但初值 0 让它找到 `nums[0] = 1`，把 1 和 2 交换，得到 `{2, 1, 9, 5, 7}`，前两个元素反而乱了。
4. 交换次数少：全程最多 n − 1 次交换，冒泡最坏要接近 n²/2 次交换。当元素是很大的结构体、交换代价高时，这个差别是实在的。
5. 它把"找最值"和"交换"揉在了一起：未排区里任何比 `nums[i]` 小的元素都当场和开头交换。这不是选择排序（一趟多次交换，类似冒泡的行为），也不是完整排序思路的正确实现——不过这个写法实际上能把数组排对（它每次都把当前最小换到位置 `i`），只是交换次数远多于选择排序，失去了"一趟最多交换一次"的特点。要按 8.2.2 的写法：先记下标，扫完再交换。
