# 8.3 插入排序

打扑克摸牌时，你不会把整手牌重排一遍：摸到一张新牌，从右往左看手里的牌，把比它大的都往右挪一格，空出位置，把新牌插进去。这个人人都会的动作就是插入排序（insertion sort）。

它的招牌特性：**数据越接近有序，它越快**——这是冒泡和选择都做不到的。

## 8.3.1 核心思路：手里的牌已经有序，新牌插进来

把数组分成两段：左边是"手里的牌"（已排好区），右边是"还没摸的牌"。一开始只有 `a[0]` 算手里的——单个元素天然有序。然后从 `a[1]` 开始，把每个元素当新牌，插进左边：

```text
初始：5 | 2 9 1 7        只有 a[0] 在手里

插入 2：2 5 | 9 1 7
插入 9：2 5 9 | 1 7
插入 1：1 2 5 9 | 7
插入 7：1 2 5 7 9        完成
```

插入排序的不变量和选择排序不同，注意差别：

> 每轮插入之前，前 `i` 个元素**内部已经排好**；但它们不一定就等于整个数组里最小的 `i` 个——右边还可能藏着更小的。

选择排序的不变量是"前 `i` 个已经是最终结果"，插入排序的不变量只是"前 `i` 个内部有序"。所以插入排序途中，已排好区里的元素还会往后挪（被更大的"新牌"挤），而选择排序里归位的元素永远不动。

## 8.3.2 实现

插一张牌分三步：**拿出新牌 → 挪出空位 → 放进去**。

```c
// 8.3.1 insertion_sort.c
#include <stdio.h>

void insertion_sort(int nums[], int count)
{
	for (int i = 1; i < count; i++) {
		int key = nums[i];
		int j = i - 1;

		while (j >= 0 && nums[j] > key) {
			nums[j + 1] = nums[j];
			j--;
		}

		nums[j + 1] = key;
	}
}

void print_array(const int nums[], int count)
{
	for (int i = 0; i < count; i++) {
		printf("%d", nums[i]);
		if (i < count - 1) {
			printf(" ");
		}
	}
	printf("\n");
}

int main(void)
{
	int nums[5] = {5, 2, 9, 1, 7};

	printf("排序前：");
	print_array(nums, 5);

	insertion_sort(nums, 5);

	printf("排序后：");
	print_array(nums, 5);

	return 0;
}
```

```text
排序前：5 2 9 1 7

```

逐行对着思路看：

| 代码 | 作用 |
|------|------|
| `for (int i = 1; ...)` | 新牌从 `a[1]` 开始摸，`a[0]` 一开始就在手里 |
| `int key = nums[i];` | 把新牌拿在手上（这一步必须先做，见下） |
| `int j = i - 1;` | 从手里最右边的牌开始往左看 |
| `while (j >= 0 && nums[j] > key)` | 比 key 大的牌往右挪一格，空出位置 |
| `nums[j + 1] = key;` | 把新牌放进空位 |

一个容易被忽略的点：`key` 必须在挪动**之前**取出来。`nums[i]` 这个位置会被挪动的元素覆盖（当 `j + 1 == i` 时），不先存到 `key` 里，新牌的值就丢了——和 8.1.4 交换要临时变量是同一个道理。

## 8.3.3 两个边界条件：j >= 0 和 a[j] > key

`while` 的两个条件一个都不能少，各防一种情况。

**`j >= 0` 防越界。** 新牌是最小值时，比它大的牌会一路挪到最前面，`j` 一路减到 −1。没有 `j >= 0`，就会访问 `nums[-1]`——3.1.4 讲过的越界，未定义行为。追一遍把 1 插进 `{2, 5, 9}`：

```text
key = 1
j = 2：nums[2] = 9 > 1 → 挪，空位到下标 2
j = 1：nums[1] = 5 > 1 → 挪，空位到下标 1
j = 0：nums[0] = 2 > 1 → 挪，空位到下标 0
j = -1：j >= 0 不成立 → 停
nums[j + 1] = nums[0] = key   → 新牌放在最前面
```

`j` 变成 −1 后，`nums[j + 1]` 恰好是 `nums[0]`——不需要任何特判，循环退出时的位置就是新牌该在的地方。想通这一步，插入排序就算真正懂了。

**`nums[j] > key` 决定挪不挪。** 等到 `nums[j] <= key` 就停。用 `>` 而不是 `>=` 还有一个附带的好处：相等时新牌插在相等元素的后面，不会越过它——排序是稳定的（相等元素之间的先后顺序保持不变）。本章的冒泡和插入都有这个性质，选择排序没有。

## 8.3.4 数据越有序，它越快

冒泡和选择无论数据什么状况，比较次数都死死固定在约 n²/2。插入排序不一样，它的工作量取决于**每张新牌要往前挪多远**：

- **完全逆序**：每张牌都要挪到最前面，最坏约 n²/2 次，和另外两个一个级别。
- **已经有序**：每张牌一下就停，外层跑 n − 1 轮、每轮比较 1 次，总共约 n 次——O(n)。
- **近乎有序**：只有少数牌挪几步，远快于 n²。

第 7 章递归学的分而治之思想、以及工业级排序的实现里，常见的一个组合就是：大数据先用快速排序粗排，最后一段"近乎有序"的小区间交给插入排序收尾——它正是为这种数据而生的。8.5 学完快速排序再回头看这句话会有体会。

## 8.3.5 三种排序对比

把前三节放进一张表：

| 对比项 | 冒泡排序 | 选择排序 | 插入排序 |
|--------|----------|----------|----------|
| 核心动作 | 相邻比较交换，大数后移 | 找最小下标，一次交换 | 挪出空位，插入新牌 |
| 不变量 | 尾部 `i` 个已归位 | 前 `i` 个是最终结果 | 前 `i` 个内部有序 |
| 比较次数 | 固定约 n²/2 | 固定约 n²/2 | 最好约 n，最坏约 n²/2 |
| 交换（挪动）次数 | 最坏约 n²/2 | 最多 n − 1 | 最坏约 n²/2 |
| 近乎有序的数据 | 加 `swapped` 后快 | 没有收益 | **特别快（约 O(n)）** |
| 稳定性 | 稳定 | 不稳定 | 稳定 |
| 记忆点 | 气泡上浮 | 挑水果 | 理扑克牌 |

三者都是 O(n²) 级别，数据一大都扛不住；但插入排序对"近乎有序"数据的敏感，让它在小规模或基本有序场景里依然实用。突破 O(n²) 要换思路——用"砍半"的分治，那是 8.5 快速排序的事。

## 8.3.6 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| 外层从 `i = 0` 开始 | 第一张"新牌"和空手比较，白跑一轮 | 从 `i = 1` 开始 |
| 挪动之后才取 `key` | `nums[i]` 被覆盖，新牌丢失 | 先 `key = nums[i]` 再挪 |
| `while` 只写 `nums[j] > key` | 新牌最小时 `j` 减到 −1，越界 | `j >= 0 && nums[j] > key` |
| `while` 只写 `j >= 0` | 所有牌一路挪到头，数组变逆序 | 两个条件都要 |
| 放回写成 `nums[j] = key` | 差一格，覆盖掉不该覆盖的元素 | `nums[j + 1] = key` |

## 8.3.7 小结

- 插入排序：把每个元素当新牌，往已排好的前缀里插；外层从 1 开始。
- 三步：`key = nums[i]` 拿出新牌 → `while` 把更大的元素右挪 → `nums[j + 1] = key` 放入空位。
- 不变量：前 `i` 个元素内部有序（和选择排序的不变量不同，归位不是终态）。
- `j >= 0` 防越界、`nums[j] > key` 决定挪动，缺一不可；新牌最小则落在 `nums[0]`，无需特判。
- 最好情况约 O(n)，近乎有序时特别快；最坏和冒泡、选择一样约 O(n²)。
