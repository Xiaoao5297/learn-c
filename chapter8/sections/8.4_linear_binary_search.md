# 8.4 顺序查找 & 二分查找

> 💬 **节前语：**
>
> 数据排好序了，现在该"找东西"了。
>
> 想象你在玩一个游戏：心里想一个 1~1000 的数，让我猜。
>
> - 我**从 1 猜到 1000**：运气最差要猜 1000 次——这是**顺序查找**
> - 我每次都猜**中间的数**，你告诉我"大了/小了"，我一次就能**排除一半**——最多猜 10 次（2¹⁰=1024）！这就是**二分查找**
>
> 一个要 1000 次，一个只要 10 次——差 100 倍！这一节我们就把这两种查找都写出来，并亲手感受"砍半"的威力。准备好了吗？开始吧！

---

## 8.4.1 顺序查找：一个个看过去

最朴素的查找：**从第一个开始，挨个比，找到就返回位置，找到头都没有就返回"没找到"。** 数组是否有序无所谓。

```c
#include <stdio.h>

// 顺序查找：找到返回下标，没找到返回 -1
int linearSearch(int a[], int n, int target) {
    for (int i = 0; i < n; i++) {
        if (a[i] == target) {
            return i;        // 找到了，立刻返回下标
        }
    }
    return -1;               // 整个数组都看完了，没有
}

int main() {
    int a[] = {88, 62, 95, 70, 79};
    int n = 5;

    int idx = linearSearch(a, n, 70);
    if (idx != -1) {
        printf("找到了 70，下标是 %d\n", idx);
    } else {
        printf("没找到 70\n");
    }
    return 0;
}
```

输出：
```
找到了 70，下标是 3
```

> 📌 **返回值用 -1 表示"没找到"**：因为下标从 0 开始，-1 不可能是合法下标——一眼就能分辨"找到了第几个"还是"没有"。这是我们项目里反复用到的"哨兵值"约定。

### ⏱️ 顺序查找有多慢？

运气最差（目标在最后、或根本不存在），要比较 **n 次**。数据有一百万个，最坏就要比一百万次。能不能更快？——能，前提是**数组有序**，然后就能用二分查找！

## 8.4.2 二分查找：猜数字游戏

### 💡 规则

假设数组已经从小到大排好，比如：

```
下标：  0   1   2   3   4   5   6
数值：  12  25  38  47  60  83  95
```

要找 60。我们不再从头扫，而是**每次盯住中间**：

```
第1次：范围 [0,6]，中间下标 3（值 47）
       47 < 60 → 目标一定在右半边！范围缩小成 [4,6]
第2次：范围 [4,6]，中间下标 5（值 83）
       83 > 60 → 目标一定在左半边！范围缩小成 [4,4]
第3次：范围 [4,4]，中间下标 4（值 60）
       60 == 60 → 找到了！返回下标 4
```

**只比了 3 次！** 每次比较都能**排除掉一半**的候选。

> 🎯 **和猜数字一模一样：** "大了？那我把上界挪下来；小了？那我把下界提上去。" 只要记住三个量：**下界 low、上界 high、中间 mid = (low+high)/2**。

### 📝 递归版代码（用上第7章的功夫！）

查找本身是典型的递归结构——"在 [low, high] 里找"可以拆成"看中间 → 到左半边找 / 到右半边找"：

```c
#include <stdio.h>

// 二分查找（递归版）：在 a[low]~a[high] 里找 target，找到返回下标，找不到返回 -1
int binarySearch(int a[], int low, int high, int target) {
    if (low > high) {                    // 出口：范围空了，说明没找到
        return -1;
    }
    int mid = (low + high) / 2;          // 取中间
    if (a[mid] == target) {
        return mid;                      // 猜中了！
    } else if (a[mid] < target) {
        return binarySearch(a, mid + 1, high, target);   // 目标在右半边
    } else {
        return binarySearch(a, low, mid - 1, target);    // 目标在左半边
    }
}

int main() {
    int a[] = {12, 25, 38, 47, 60, 83, 95};
    int n = 7;

    int idx = binarySearch(a, 0, n - 1, 60);
    if (idx != -1) {
        printf("找到了 60，下标是 %d\n", idx);
    } else {
        printf("没找到 60\n");
    }
    return 0;
}
```

输出：
```
找到了 60，下标是 4
```

### 🔍 对着"递归三步法"看这段代码

| 步骤 | 回答 |
|------|------|
| ① 出口 | 范围空了（`low > high`）→ 没找到，返回 -1 |
| ② 递推 | 看中间：相等→返回；比 target 小→到右半边找；比 target 大→到左半边找 |
| ③ 参数在变小 | 每次递归，范围 `high - low` 都在缩小（砍掉一半）|

> 📌 **`low > high` 这个出口想通了吗？** 当范围里已经没有任何数（比如都砍到 `low` 超过了 `high`），说明 target 不在数组里，返回 -1。试着追一遍"找 61"：最后范围会变成空的 → 返回 -1，完美。

## 8.4.3 排序 + 二分 = 黄金搭档

二分查找的前提是**数组有序**。那真实场景怎么办？——先用第 8.1/8.2 的排序把数组排好，再二分查找！来个完整的例子：

```c
#include <stdio.h>

// 借用上一节的冒泡排序
void bubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                int tmp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = tmp;
            }
        }
    }
}

int binarySearch(int a[], int low, int high, int target) {
    if (low > high) return -1;
    int mid = (low + high) / 2;
    if (a[mid] == target) return mid;
    if (a[mid] < target) return binarySearch(a, mid + 1, high, target);
    return binarySearch(a, low, mid - 1, target);
}

void printArray(int a[], int n) {
    for (int i = 0; i < n; i++) printf("%d ", a[i]);
    printf("\n");
}

int main() {
    int a[] = {88, 62, 95, 70, 79, 55};
    int n = 6;

    printf("排序前：");
    printArray(a, n);

    bubbleSort(a, n);                    // ① 先排序
    printf("排序后：");
    printArray(a, n);

    int target = 79;
    int idx = binarySearch(a, 0, n - 1, target);   // ② 再二分查找
    if (idx != -1) {
        printf("找到 %d，下标是 %d\n", target, idx);
    } else {
        printf("没找到 %d\n", target);
    }
    return 0;
}
```

输出：
```
排序前：88 62 95 70 79 55
排序后：55 62 70 79 88 95
找到 79，下标是 3
```

> 💡 **这就是为什么"排序"值得做：** 排序的成本是一次性的，之后无数次查找都能享受"二分"的闪电速度。程序里常常"多排一次序，少跑无数遍查找"。

---

## 8.4.4 二分有多快？数给你看 ⏱️

每次砍一半，n 个数最多要猜多少次？答案是**约 log₂n 次**（对数），因为 2^几次方 = n。

| 数据量 n | 顺序查找最坏 | 二分查找最坏 |
|---------|-------------|-------------|
| 1000 | 1000 次 | 约 10 次 |
| 1 万 | 1 万次 | 约 14 次 |
| 100 万 | 100 万次 | 约 20 次 |
| 10 亿 | 10 亿次 | 约 30 次 |

> 📌 **感受一下差距：** 10 亿条数据（很大很大），顺序查找要猜 10 亿次，二分只猜约 30 次——快了 **3 千多万倍**！这就是"砍半"思想的威力。程序员把顺序查找叫 O(n)，二分查找叫 O(log n)。**数据越大，二分的优势越夸张。**

> 🧠 **小贴士：** 上面 `mid = (low + high) / 2` 对超大数据可能溢出（low+high 太大）。更保险的写法是 `mid = low + (high - low) / 2`。现阶段数组不大，两种都对，知道有这个讲究即可。

## 8.4.5 顺序 vs 二分：怎么选？

| | 顺序查找 | 二分查找 |
|---|---------|---------|
| 前提 | 无序也行 | **必须有序** |
| 思路 | 从头一个个比 | 每次砍一半 |
| 最快/最坏 | 1 次 / n 次 | 约 1 次 / log₂n 次 |
| 代码 | 一个 for | 递归（或循环）稍绕 |
| 适合 | 数据少、或无序、只查一次 | 数据多、有序、要查很多次 |

> 📌 **一句话决策：** 数据多又经常查 → 先排序，再二分；数据少或只查一次 → 顺序查找最省事。

## 8.4.6 本节小结

这一节我们学了：

✅ **顺序查找：** 从头到尾一个个比，找到返回下标，找不到返回 -1；无序也行

✅ **二分查找：** 数组有序，每次看中间，大了去左边、小了去右边，**一次砍一半**

✅ **递归实现：** 出口 `low > high` → -1；递推看 `a[mid]` 决定进哪半边

✅ **黄金搭档：** 先排序再二分，一次排序、无数次快查

✅ **快慢对比：** 二分约 log₂n 次 vs 顺序 n 次；10 亿数据 ≈ 30 次 vs 10 亿次

> 💡 **记住："砍半"是这个世界上最优雅的提速思路之一——查找用它，8.5 的快速排序也用它！**

### 三、改错题

**8. 以下递归二分查找有 3 个错误：**

```c
#include <stdio.h>

int binarySearch(int a[], int low, int high, int target) {
    if (low < high) return -1;                 // 错误区①：范围"空了"的判断对吗？
    int mid = (low + high) / 2;
    if (a[mid] == target) return mid;
    if (a[mid] < target) {
        return binarySearch(a, low, mid, target);     // 错误区②：右半边该去哪一段？（还带着 mid）
    } else {
        return binarySearch(a, low, mid, target);     // 错误区③：左半边该到 mid-1，别把 mid 也带上
    }
}

int main() {
    int a[] = {12, 25, 38, 47, 60};
    int n = 5;
    printf("%d\n", binarySearch(a, 0, n - 1, 60));  // 期望 4
    printf("%d\n", binarySearch(a, 0, n - 1, 99));  // 期望 -1
    return 0;
}
```

> 提示：①空范围的标志是 low 超过 high；②去右半边应该排除掉中间的 mid（low 要 +1）；③去左半边 high 要 = mid-1。
