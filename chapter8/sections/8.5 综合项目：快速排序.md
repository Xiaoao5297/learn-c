# 8.5 综合项目：快速排序

三种 O(n²) 排序的共同瓶颈：一趟只解决一个元素。二分查找教了我们"砍半"——每比较一次排除一半。第 7 章的汉诺塔教了我们分而治之：把问题拆成小一号的同类问题，递归解决。

把这两个思想合到排序上，就是本节的快速排序（quick sort）：平均工作量 O(n log n)，数据一大，和 O(n²) 拉开几十万倍的差距。

## 8.5.1 项目设计：基准、分区、递归

快速排序分三步：

1. **挑基准（pivot）**：从区间里选一个元素作参照，这里选区间最后一个。
2. **一趟分区（partition）**：把区间重排成"比基准小的在左、比基准大的在右"，基准落到它最终的位置上。
3. **递归**：对基准左、右两个子区间各自再做快速排序。区间只剩 0 或 1 个元素时天然有序，递归结束。

整个过程像按身高给全班分两队再各排各的：先随便叫一位同学（基准）站到中间当标尺，比他矮的全站左边、比他高的全站右边（分区）——这一步结束，他自己的位置就定死了；然后左边一队、右边一队各自照同样的办法再分再排（递归），队伍小到只剩一个人时就不用排了。

| 角色 | 对应代码 |
|------|----------|
| 总调度 | `quick_sort(nums, left, right)`：出口 + 分区 + 两次递归 |
| 分区 | `partition`：一趟重排，返回基准的最终下标 |
| 递归出口 | `left >= right`：0 或 1 个元素的区间不用排 |

先只看一趟分区能干什么，递归放到 8.5.3。

## 8.5.2 一趟分区：Lomuto 写法

对 `5 3 8 4 2 7`，选最后一个 7 当基准。目标：扫完之后，比 7 小的都在左边，7 卡在中间。

技巧是用两个下标：`j` 从左到右巡逻每个元素；`i` 始终指向"小于等于基准的那一段"的右边界。凡是 `nums[j] <= pivot` 的，就把 `i` 右移一格、把 `nums[j]` 换进去——相当于把它收编进左边队伍：`j` 像点名老师挨个过人，`i` 是左队的排尾，够条件的就让他站进队尾。

```text
初始：5 3 8 4 2 7    pivot = 7，i = -1

j=0：5 <= 7 → i=0，交换 a[0] a[0] → 5 3 8 4 2 7
j=1：3 <= 7 → i=1，交换 a[1] a[1] → 5 3 8 4 2 7
j=2：8 >  7 → 不动
j=3：4 <= 7 → i=2，交换 a[2] a[3] → 5 3 4 8 2 7
j=4：2 <= 7 → i=3，交换 a[3] a[4] → 5 3 4 2 8 7

扫完后：a[0..3] 都 <= 7，a[4..4] 都 > 7
最后把基准换到边界后一格：交换 a[4] a[5] → 5 3 4 2 7 8
                                                    ↑
                                            基准 7 归位（下标 4）
```

分区结束后，**基准已经待在它最终该在的位置**：左边全比它小，右边全比它大。左右两边内部乱不乱无所谓——那是两次递归的事。这种"巡逻收编"的分区写法叫 Lomuto 分区，是最容易写对的一种。

```c
// 8.5.1 partition.c
#include <stdio.h>

void swap_int(int *a, int *b)
{
	int temp = *a;
	*a = *b;
	*b = temp;
}

int partition(int nums[], int left, int right)
{
	int pivot = nums[right];
	int i = left - 1;

	for (int j = left; j < right; j++) {
		if (nums[j] <= pivot) {
			i++;
			swap_int(&nums[i], &nums[j]);
		}
	}

	swap_int(&nums[i + 1], &nums[right]);
	return i + 1;
}

int main(void)
{
	int nums[6] = {5, 3, 8, 4, 2, 7};

	int p = partition(nums, 0, 5);

	printf("分区结果：");
	for (int i = 0; i < 6; i++) {
		printf("%d", nums[i]);
		if (i < 5) {
			printf(" ");
		}
	}
	printf("\n");
	printf("基准 7 归位到下标 %d\n", p);

	return 0;
}
```

<!-- output: 8.5.1 -->
```text
分区结果：5 3 4 2 7 8
基准 7 归位到下标 4
```

这里用上了第 4 章的指针参数：`swap_int` 接收两个元素的**地址**，函数内通过 `*a`、`*b` 交换原数据——普通变量按值传递交换不了调用方的东西（4.1 讲过），所以交换函数的参数必须是指针。`&nums[i]` 取下标元素的地址，也是第 4 章"指针与数组"的常规操作。

代码里两处 `swap_int` 的分工：循环内是把"小于等于基准"的元素收进左队；循环外那一次是**把基准从最右端放进分界处**，它就是"基准归位"的动作，返回的 `i + 1` 就是基准的最终下标。

## 8.5.3 加上递归，快排完成

分区返回基准下标 `p` 之后，`p` 位置的元素已经是最终结果，不再参与后续排序。剩下的就是把 `[left, p-1]` 和 `[p+1, right]` 两个子区间交给递归：

```c
// 8.5.2 quick_sort.c
#include <stdio.h>

void swap_int(int *a, int *b)
{
	int temp = *a;
	*a = *b;
	*b = temp;
}

int partition(int nums[], int left, int right)
{
	int pivot = nums[right];
	int i = left - 1;

	for (int j = left; j < right; j++) {
		if (nums[j] <= pivot) {
			i++;
			swap_int(&nums[i], &nums[j]);
		}
	}

	swap_int(&nums[i + 1], &nums[right]);
	return i + 1;
}

void quick_sort(int nums[], int left, int right)
{
	if (left >= right) {
		return;
	}

	int p = partition(nums, left, right);
	quick_sort(nums, left, p - 1);
	quick_sort(nums, p + 1, right);
}

int main(void)
{
	int nums[6] = {5, 3, 8, 4, 2, 7};

	printf("排序前：");
	for (int i = 0; i < 6; i++) {
		printf("%d", nums[i]);
		if (i < 5) {
			printf(" ");
		}
	}
	printf("\n");

	quick_sort(nums, 0, 5);

	printf("排序后：");
	for (int i = 0; i < 6; i++) {
		printf("%d", nums[i]);
		if (i < 5) {
			printf(" ");
		}
	}
	printf("\n");

	return 0;
}
```

<!-- output: 8.5.2 -->
```text
排序前：5 3 8 4 2 7
排序后：2 3 4 5 7 8
```

对照第 7 章递归三步法检查这段代码：

| 步骤 | 回答 |
|------|------|
| ① 出口 | `left >= right`：区间剩 0 或 1 个元素，天然有序，直接返回 |
| ② 递推 | 分区让基准归位，再排左半边 `[left, p-1]` 和右半边 `[p+1, right]` |
| ③ 参数在变小 | 每次递归的区间都至少比原来短一个元素（基准出列了） |

对照第 7 章的分而治之：分区就是"分"，两次递归就是"治"，左右排好摞在一起就是"合"——和把一摞试卷分给几个组长先各自整理、最后收齐一模一样。这里也需要一次**信仰之跃**（7.4 讲过）：不必追着递归一层层想"左边到底怎么排好的"。只要分区正确、递归调用的是同一种排序、区间在缩小，左边和右边就各自有序；加上基准本身的位置正确，整个区间必然有序。

注意 `quick_sort` 和 `partition` 的参数是**区间下标**而不是数组长度——快排天然工作在数组的任意一段上，和 8.4 递归二分的 `left`/`right` 一个道理。

## 8.5.4 快排为什么快：数一数工作量

理想情况下，每次分区都把区间对半切开：第一层 n 个元素各比一次，第二层两个区间共 n 次……一共约 log₂n 层，每层总比较约 n 次：

| n | 冒泡/选择/插入约 n²/2 | 快排约 n log₂n |
|---|----------------------|----------------|
| 1 万 | 5000 万 | 约 13 万 |
| 100 万 | 5000 亿 | 约 2000 万 |
| 10 亿 | 5 × 10¹⁷ | 约 300 亿 |

n = 100 万时差了约 2.5 万倍，n 越大差距越夸张。把它记作 O(n log n)。

快排也有软肋：如果每次挑的基准都恰好是区间最大或最小值，分区就会切得极偏（一边 0 个、另一边 n − 1 个），退化到 O(n²)。就像按身高分队时每次偏偏都叫到最矮的那位：一边站全班、一边空无一人，分队就白分了。最典型的触发方式：**数组已经有序，还总拿最后一个元素当基准**。工程上的对策是随机选基准、三数取中等，思想都是“别让基准每次都撞上极端值”。

## 8.5.5 标准库里的 qsort

快速排序思想最重要的落地，就是 C 标准库的 `qsort` 函数（在 `stdlib.h` 里）：任何类型的数组、任意大小，传进数组指针、元素个数、单个元素大小和一个**比较函数**，它替你排好。真实的 `qsort` 通常是快排的改良版（混合了插入排序等技巧），这正是 8.3.4 说的"插入排序收尾"的典型例子。

比较函数长这样（示意，看个印象即可）：

```c
int compare_int(const void *a, const void *b)
{
	int x = *(const int *)a;
	int y = *(const int *)b;

	return (x > y) - (x < y);
}
```

这里只提三件事，细节留给第 10 章专门讲：

1. `const void *` 是"指向任意类型、只读"的指针，用之前要转换回具体类型（4.6 露过面）。
2. 比较函数返回负数、0、正数表示"小于、等于、大于"。
3. **返回值不要写成 `x - y`**。两个 int 相减可能溢出（比如 x 是 20 亿、y 是 -20 亿，差超出 int 范围），结果符号错乱，排序随之出错。`(x > y) - (x < y)` 这个写法把比较结果规约成 -1、0、1，永远不会溢出——从现在起就按这个套路写。

## 8.5.6 综合项目：成绩排序加查找小系统

把本章全部本领串起来：一组乱序成绩，先快排，再二分查找某个分数的排名，并处理"查不到"的情况。

```c
// 8.5.3 score_system.c
#include <stdio.h>

#define MAX_SCORES 100

void swap_int(int *a, int *b)
{
	int temp = *a;
	*a = *b;
	*b = temp;
}

int partition(int nums[], int left, int right)
{
	int pivot = nums[right];
	int i = left - 1;

	for (int j = left; j < right; j++) {
		if (nums[j] <= pivot) {
			i++;
			swap_int(&nums[i], &nums[j]);
		}
	}

	swap_int(&nums[i + 1], &nums[right]);
	return i + 1;
}

void quick_sort(int nums[], int left, int right)
{
	if (left >= right) {
		return;
	}

	int p = partition(nums, left, right);
	quick_sort(nums, left, p - 1);
	quick_sort(nums, p + 1, right);
}

int binary_search(const int nums[], int count, int target)
{
	int left = 0;
	int right = count - 1;

	while (left <= right) {
		int mid = left + (right - left) / 2;

		if (nums[mid] == target) {
			return mid;
		} else if (nums[mid] < target) {
			left = mid + 1;
		} else {
			right = mid - 1;
		}
	}

	return -1;
}

void print_array(const int nums[], int count)
{
	for (int i = 0; i < count; i++) {
		printf("%d", nums[i]);
		if (i < count - 1) {
			printf(" ");
		}
	}
	printf("\n");
}

int main(void)
{
	int scores[MAX_SCORES] = {88, 62, 95, 70, 79};
	int count = 5;

	printf("排序前：");
	print_array(scores, count);

	quick_sort(scores, 0, count - 1);

	printf("快排后：");
	print_array(scores, count);

	int target = 79;
	int index = binary_search(scores, count, target);
	if (index >= 0) {
		printf("%d 分的下标是 %d，从低到高排第 %d\n",
		       target, index, index + 1);
	} else {
		printf("没有 %d 分\n", target);
	}

	int miss = 100;
	index = binary_search(scores, count, miss);
	if (index >= 0) {
		printf("%d 分的下标是 %d\n", miss, index);
	} else {
		printf("没有 %d 分（查找返回 -1）\n", miss);
	}

	return 0;
}
```

<!-- output: 8.5.3 -->
```text
排序前：88 62 95 70 79
快排后：62 70 79 88 95
79 分的下标是 2，从低到高排第 3
没有 100 分（查找返回 -1）
```

这个程序是本章的缩影：

1. `quick_sort`、`partition` 负责排序，`binary_search` 负责查找，`print_array` 负责展示——每个函数只做一件事（第 2 章的分工原则）。
2. 只读的函数（`binary_search`、`print_array`）参数加 `const`；要修改数组的（`quick_sort`、`partition`）不加。
3. 数组按 `MAX_SCORES` 声明上限，实际个数记在 `count` 里——3.5.7 的标准做法。
4. "先排序、再二分"正是 8.4.5 的黄金搭档；排名输出在排序之后，因此顺序含义以排序结果为准。

> **Windows 提示**：中文输出乱码时，确认源文件以 UTF-8 保存，或在 `main` 开头执行 `system("chcp 65001");`（需要 `#include <stdlib.h>`）。Linux 终端默认 UTF-8，一般无需处理。

## 8.5.7 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| 递归出口写成 `left > right` 才返回，或漏写出口 | 区间剩 1 个元素时继续分区，可能死递归爆栈 | `if (left >= right) return;` |
| 内层巡逻写成 `j <= right` | 基准自己和自己分区，逻辑错乱 | `j < right`，基准最后单独归位 |
| 归位写成 `swap_int(&nums[i], &nums[right])` | 基准落到错误位置，排序结果错 | `swap_int(&nums[i + 1], &nums[right])` |
| 递归写成 `quick_sort(nums, left, p)` | 基准又被拉进子区间，死递归 | `quick_sort(nums, left, p - 1)` 和 `quick_sort(nums, p + 1, right)` |
| 交换函数用普通 `int` 参数 | 按值传递，交换不到调用方的数据 | 参数用 `int *`，调用时取地址 |
| 有序数组也拿末尾当基准 | 每次切偏，退化 O(n²) | 随机基准、三数取中（进阶内容） |

## 8.5.8 小结

- 快排三步：挑基准 → 一趟分区（左小右大，基准归位）→ 递归排左右子区间。
- Lomuto 分区：`i` 是"小于等于基准"段的边界，`j` 巡逻；扫完后把基准换到 `i + 1` 归位，返回该下标。
- 递归出口 `left >= right`；递归调用跳过基准（`p - 1` 和 `p + 1`），保证区间在缩小。
- 平均 O(n log n)；基准总撞极端值时退化 O(n²)，对策是随机基准、三数取中。
- 标准库 `qsort` 是这一思想的工业化版本，比较函数返回值用 `(a > b) - (a < b)` 规约到 -1/0/1，避免相减溢出；第 10 章详细展开。
- 排序 + 二分查找，一次排序、无数次快查——本章的两个主角合体。

## 练习

1. 一趟分区结束后，能保证什么、不能保证什么？
2. 对 `4 1 3 2`（以最后一个 2 为基准）手动模拟一趟 Lomuto 分区，写出每次交换后的数组和最后的归位结果。
3. 快排的递归调用为什么是 `quick_sort(nums, left, p - 1)` 而不是 `quick_sort(nums, left, p)`？
4. 数组已经从小到大有序时，用"末尾元素当基准"的快排会发生什么？分区每趟各切出多大的子区间？
5. 比较函数写成 `return x - y;` 在什么情况下会出错？`(x > y) - (x < y)` 为什么不会？
6. 编程题：用快排把 `{7, 2, 9, 4, 6, 1, 8}` 从小到大排序并打印。

<summary>参考答案</summary>

1. 保证：基准在它的最终位置，左边所有元素 ≤ 基准，右边所有元素 > 基准。不能保证：左右两边内部各自有序——那要靠递归解决。
2. pivot = 2，i 从 left−1 = −1 开始：j=0 时 4 > 2 不动；j=1 时 1 ≤ 2，i=0，交换 a[0]、a[1] → `1 4 3 2`；j=2 时 3 > 2 不动。扫完后交换 a[1]、a[3] → `1 2 3 4`，基准 2 归位到下标 1，返回 1。
3. `p` 位置的元素是基准，分区后已经是最终结果，必须排除在子区间之外。带上 `p` 会把已归位的基准再卷进分区，区间不再保证缩短，可能无限递归。右半边同理用 `p + 1`。
4. 每趟分区里所有元素都 ≤ 基准（其余元素全比末尾的小），全部被收进左队，右队为空。切出来的子区间一边是 n − 1 个、另一边是 0 个，递归深度达到 n 层，工作量退化到约 n²/2，快排退化成冒泡级别的慢。
5. 当 `x - y` 超出 `int` 范围时结果溢出，符号可能与真实大小关系相反。比如 x = 2000000000、y = -2000000000，真实关系是 x > y，但相减得到 40 亿，超出 int 上限约 21 亿，实际得到一个负数，比较函数反而报告"x 小于 y"，排序结果错乱。`(x > y) - (x < y)` 不做减法，只把两个 0/1 比较结果相减，取值只可能是 -1、0、1，永远不会溢出。
