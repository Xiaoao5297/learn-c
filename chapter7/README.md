# 第 7 章：函数进阶与递归

从第 2 章起我们就一直在写函数：把一段代码打包，给它起个名字，随时调用。这一章要回答一个当时没有展开的问题——**一个函数能不能调用它自己？**

能。这种写法叫递归（recursion）。它是这一章的主角，也是后面排序、二叉树等内容的思维地基。

本章会学到：

- 递归三要素：基线条件、递归步骤、规模收敛，以及写递归前的三个自查问题。
- 函数调用栈：递归为什么能“一去一回”，栈溢出是怎么回事。
- 斐波那契数列：递归写法的简洁，与朴素递归的重复计算代价。
- 汉诺塔：递归的经典应用，分而治之思想的入门。
- 用递归操作链表：正序与逆序打印、计数求和、查找、整链释放。

## 前置知识

- 第 2 章：函数定义、参数传递、`return`。
- 第 4 章：指针、`struct`。
- 第 6 章：`malloc`、`free`、链表节点。7.5 会用到，其余小节不需要。

## 学完这一章，你应该能

1. 说出递归三要素，并用三个自查问题检查一段递归代码。
2. 画出 `fact(3)` 这样的递归调用过程中栈的变化，说清楚递去与归来两个阶段。
3. 解释栈溢出的成因，知道递归深度为什么不能无限大。
4. 写出阶乘、各位数字之和、最大公约数等基础递归函数。
5. 说清楚朴素递归斐波那契为什么慢，并用记忆化或循环解决。
6. 用递归解出汉诺塔，并验证最少步数是 2^n − 1。
7. 用递归完成链表的打印、计数、查找和释放，并判断什么时候该换成循环。

## 本章工程支线

前几章的工程支线是“怎么把代码写安全”，本章的工程支线是“怎么给算法估成本”：

- **7.3 的调用计数**：给 `fib` 加一个计数变量，实测朴素递归的调用次数随 n 指数增长。写算法前先估规模，这个习惯会贯穿第 8 章的排序与查找。
- **7.3 的记忆化**：算过的结果存进数组，同样的子问题只算一次。这是第 8 章“用空间换时间”思路的第一次登场。
- **7.5 的递归释放**：`free` 的顺序不对就是悬垂访问。递归写法把“先释放后面的，再释放自己”表达得很自然，但顺序依然是生命线。

## 预计时间

- 只读一遍：3 到 4 小时。
- 做完每节练习和章末测试：6 到 8 小时。
- 建议分 3 次学习：7.1 和 7.2 是概念地基，值得多花时间；7.3 重点是实测数据；7.4、7.5 各是一次完整的实战。

## 学习建议

- 递归是思维方式的转变，不是新语法。每看到一个递归函数，先问三件事：出口在哪？参数怎么变小？递推式对不对？
- 一定动笔画调用栈。7.2 的栈变化图最好自己照着画一遍，比空想有效得多。
- 7.3 的程序都很容易跑，改几个数字，亲眼看调用次数怎么涨上去。
- 7.5 假定你做过第 6 章的链表练习。如果节点、`next` 这些词已经模糊，先回去复习 6.3。
