# 7.2 递归的"后台"：函数调用栈

## 7.2.1 函数调用时发生了什么？

先不看递归，回忆普通函数调用（第2章）：

```c
void hello() {
    printf("你好\n");
}

int main() {
    printf("开始\n");
    hello();              // 调用 hello
    printf("结束\n");     // 调用完，回到这一行继续
    return 0;
}
```

当 `main` 调用 `hello()` 时，程序要"跳"去执行 hello 的代码；可等 hello 执行完，程序**怎么知道要回到 main 里继续执行哪一行？** 而且 `main` 里的变量，怎么保证不被 `hello` 弄乱？

### 📋 "记账本"：栈（Stack）

C程序用一块叫**栈**的内存来记账。每次调用一个函数，系统就在栈顶压入一张"**小纸条**"，上面写着：

| 小纸条上记着什么 | 干什么用 |
|------------------|---------|
| 参数的值 | 函数要用到的输入 |
| 局部变量的值 | 函数自己的临时空间 |
| **回到哪里继续执行**（返回地址） | 函数结束后的"下一站" |

这张"小纸条"学名叫 **栈帧（Stack Frame）** 或"活动记录"。函数调用 → 压栈（push）；函数返回 → 弹栈（pop）。

> 📌 **栈的规矩：后进先出（LIFO）。** 先被调用的函数先压栈、后出栈；后调用的函数反而先出栈。就像摞盘子——**先放的盘子在最底下，最后才能拿出来**。

```
  栈（从下往上升）：
  ┌─────────────┐  ← 栈顶
  │ hello 的纸条 │     （hello 的局部变量 + 返回地址）
  ├─────────────┤
  │ main 的纸条  │     （main 的局部变量，被压在最底下）
  └─────────────┘
```

等 `hello()` 执行完 `return`，它的纸条被弹出，程序照纸条上记的"返回地址"回到 main，接着往下执行。**main 的纸条始终没被动过**——所以 main 里的变量毫发无损。

> 💡 **这就是为什么每个函数都有自己的"独立空间"：** 不是变量会分身，而是每个函数调用都有自己专属的一张纸条（栈帧），谁也不碰谁。

## 7.2.2 递归时，栈里发生了什么？

普通函数调用会压一张纸条；递归只是**连续压了好几张结构一样的纸条**。以 `fact(3)` 为例，一步步看栈的变化：

```c
int fact(int n) {
    if (n == 0) return 1;
    return n * fact(n - 1);
}
```

### 🎬 第一步：一路"递"下去（压栈）

```
调用 fact(3)：
  栈：┌ fact(3): n=3 ┐      ← 等 fact(2) 的结果
      └ main ────────┘
  fact(3) 算不出结果 → 需要先算 fact(2)，于是继续调用……

调用 fact(2)：
  栈：┌ fact(2): n=2 ┐      ← 等 fact(1) 的结果
      ├ fact(3): n=3 ┤      ← 它的 n=3 还好好存在自己的纸条里！
      └ main ────────┘

调用 fact(1)：
  栈：┌ fact(1): n=1 ┐      ← 等 fact(0) 的结果
      ├ fact(2): n=2 ┤
      ├ fact(3): n=3 ┤
      └ main ────────┘

调用 fact(0)：
  栈：┌ fact(0): n=0 ┐      ← 到底了！
      ├ fact(1): n=1 ┤
      ├ fact(2): n=2 ┤
      ├ fact(3): n=3 ┤
      └ main ────────┘
  fact(0): n==0 → 直接 return 1
```

> 📌 **注意：** 栈里**同时存在 4 个 `fact` 的纸条**，每张纸条上的 `n` 各不相同（3、2、1、0）。这就是为什么 `fact(1)` 算的时候，`fact(3)` 的 `n=3` 不会被覆盖——它们住在不同的纸条里！

### 🎬 第二步：一路"归"回来（弹栈、组装答案）

```
fact(0) return 1          → 栈弹出 fact(0) 的纸条，回到 fact(1)
fact(1) = 1 * 1 = 1       → 弹出，回到 fact(2)
fact(2) = 2 * 1 = 2       → 弹出，回到 fact(3)
fact(3) = 3 * 2 = 6       → 弹出，回到 main
```

### 🧭 两个阶段：递去 与 归来

观察整个过程，递归其实是两个阶段：

| 阶段 | 名字 | 干什么 | 栈的状态 |
|------|------|--------|---------|
| ① | **递去**（压栈） | 一路拆问题，一路调用更小的自己，直到命中出口 | 栈越摞越高 |
| ② | **归来**（弹栈） | 从出口一层层返回，把答案"组装"成大问题的答案 | 栈越来越矮 |

> 💡 **记住：递归是"先去后回"。** 先一路冲到底，再一路算回来。任何递归代码，执行到"递归调用那一行之后"的语句，都是在**归来的路上**才执行的！

## 7.2.3 小魔法：打印放在哪，顺序就反了

既然"递归调用之后的代码，是归来时才执行的"，那我们就能玩一个花样：

```c
#include <stdio.h>

// 先递归、后打印 → 归来时打印 → 从小到大（正序）
void printUp(int n) {
    if (n == 0) return;
    printUp(n - 1);          // 先冲到底
    printf("%d ", n);        // 回来路上才打印 → 1 2 3 4 5
}

// 先打印、后递归 → 递去时打印 → 从大到小（倒序）
void printDown(int n) {
    if (n == 0) return;
    printf("%d ", n);        // 去的时候打印 → 5 4 3 2 1
    printDown(n - 1);        // 再往下递
}

int main() {
    printf("printUp  ：");
    printUp(5);
    printf("\nprintDown：");
    printDown(5);
    printf("\n");
    return 0;
}
```

输出：
```
printUp  ：1 2 3 4 5
printDown：5 4 3 2 1
```

### 🔍 同一个函数体，为什么结果相反？

看 `printUp(5)` 怎么跑：

```
printUp(5)：先调 printUp(4)……（一路到底）
printUp(0)：return（开始归来）
printUp(1)：回来路上打印 1
printUp(2)：回来路上打印 2
printUp(3)：回来路上打印 3
printUp(4)：回来路上打印 4
printUp(5)：回来路上打印 5
```

而 `printDown(5)`：

```
printDown(5)：去的时候打印 5 → 再调 printDown(4)
printDown(4)：去的时候打印 4 → 再调 printDown(3)
……
printDown(1)：打印 1 → 调 printDown(0)
printDown(0)：return，一路直接返回，什么都不打印
```

> 📌 **一句话总结：** `printf` 放在递归调用**之前** = "递去"时执行；放在递归调用**之后** = "归来"时执行。想倒着处理数据（比如倒序打印链表），这招特别好用！

## 7.2.4 来几道"热身菜"练手

### 🍲 例1：从 1 加到 n

```c
#include <stdio.h>

int sum(int n) {
    if (n == 0) return 0;         // 出口：加 0 个数的和是 0
    return n + sum(n - 1);        // 递推：1+2+...+n = n + (1+2+...+n-1)
}

int main() {
    printf("1+2+...+100 = %d\n", sum(100));
    return 0;
}
```

输出：
```
1+2+...+100 = 5050
```

> 💡 出口用 `sum(0) = 0`，那么 `sum(1)` 会自动算成 `1 + 0 = 1`，很整齐。

### 🍲 例2：求 2 的 n 次方

```c
#include <stdio.h>

int power2(int n) {
    if (n == 0) return 1;         // 出口：2^0 = 1
    return 2 * power2(n - 1);     // 递推：2^n = 2 * 2^(n-1)
}

int main() {
    printf("2^10 = %d\n", power2(10));
    return 0;
}
```

输出：
```
2^10 = 1024
```

### 🍲 例3：求一个数的各位数字之和（如 2026 → 2+0+2+6 = 10）

怎么"拆"一个数？——用第2章学过的 `%` 和 `/`：

```
2026 % 10 = 6   （拿到个位）
2026 / 10 = 202 （砍掉个位，剩 202）
```

于是："2026 的各位和 = 6 + 202 的各位和"，问题变小了！

```c
#include <stdio.h>

int digitSum(int n) {
    if (n == 0) return 0;                 // 出口：0 的各位和是 0
    return n % 10 + digitSum(n / 10);     // 递推：个位 + 剩下部分的各位和
}

int main() {
    printf("2026 各位之和 = %d\n", digitSum(2026));
    return 0;
}
```

输出：
```
2026 各位之和 = 10
```

> 🧩 **看！这三个例子的"套路"一模一样：** 找到怎么把 n 变成更小的 n（`n-1`、`n/10`……），然后"小的答案 + 一步"，就是大的答案。这就是递归的"万能配方"。

## 7.2.5 递归太深会怎样？—— 栈溢出

还记得 7.1 说的"忘了出口会崩溃"吗？现在能解释原因了：

每调用一次函数就**压一张纸条**，递归多深，栈就摞多高。但栈这块内存是**有上限**的。如果递归层数太多，纸条摞到放不下，就会把栈"撑爆"——这叫 **栈溢出（Stack Overflow）**，程序直接崩溃。

```c
int forever(int n) {        // 没有出口
    return forever(n + 1);  // 每调用一次压一张纸条……直到栈满
}
```

> 📌 **栈的大小的感觉：** 一般情况下递归几万层以内没事，但**无限递归**几毫秒就能把栈撑爆。这也提醒我们：递归虽好，深度要控制；有些问题用循环反而更稳妥（7.4 我们会仔细对比）。

## 7.2.6 本节小结

这一节我们学了：

✅ **函数调用靠栈：** 每次调用压入一张"栈帧"（参数 + 局部变量 + 返回地址），返回时弹出

✅ **递归的栈：** 每一层递归都有自己独立的纸条，各自的变量互不干扰

✅ **两个阶段：** "递去"（压栈冲到底）→ "归来"（弹栈组装答案）

✅ **顺序魔法：** 代码放递归调用之前 = 递去时执行；放之后 = 归来时执行 → 正序 / 倒序打印

✅ **万能配方：** 把 n 变成更小的自己（n-1、n/10…），"小答案 + 一步" = 大答案

✅ **栈溢出：** 递归太深（或无限递归）会把栈撑爆，程序崩溃

> 💡 **记住：递归的每层调用都有自己的"隔间"。想通"递去/归来"，你就看懂了递归的一半！**
