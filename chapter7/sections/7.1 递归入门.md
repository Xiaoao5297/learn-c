# 7.1 递归入门

第 2 章学函数时有一个默认约定：main 调用别的函数，别的函数不调用 main，各管各的。这一节打破这个约定——一个函数的函数体里，可以出现对它自己的调用。

这就是递归（recursion）。它不是新语法，用的还是普通函数；难的只是换个角度看问题。生活中你早就用过它：让一排同学传话，每个人只负责"喊给下一个人听"；或者拆俄罗斯套娃——打开一个，里面还是套娃，只是小一号，直到拆到最里面那个实心的为止。

## 7.1.1 第一个递归程序

从一个倒计时开始。要求：从 n 开始倒数，数到 0 打印“发射！”：

```c
// 7.1.1 countdown.c
#include <stdio.h>

void count_down(int n)
{
	if (n == 0) {
		printf("发射！\n");
		return;
	}
	printf("%d ", n);
	count_down(n - 1);
}

int main(void)
{
	count_down(3);

	return 0;
}
```

<!-- output: 7.1.1 -->
```text
3 2 1 发射！
```

`count_down` 的函数体里调用了 `count_down` 自己——这就是递归。它的逻辑用一句话就能说清：

1. 数到 0 了，打印“发射！”，结束。
2. 还没到 0，先打印当前的数，然后去数“小一号的问题”——从 n − 1 倒数。

第 2 步里“从 n − 1 倒数”和原问题“从 n 倒数”是同一件事，只是规模小了 1。**把大问题拆成一个结构相同、规模更小的自己，是递归的全部秘密。**套娃也一样：拆当前这层（递归步骤）和"拆到最小那层就停手"（基线条件），就构成了整个游戏。

## 7.1.2 递归三要素

看任何一段递归代码，都能拆出三个部分：

| 要素 | 含义 | `count_down` 中的对应 |
|------|------|----------------------|
| 基线条件 | 问题小到可以直接给出结果、不再递归的分支 | `if (n == 0)` 打印后直接 `return` |
| 递归步骤 | 函数调用规模更小的自己 | `printf` 之后调用 `count_down(n - 1)` |
| 规模收敛 | 每次递归调用，参数都要朝基线条件靠近 | 传的是 `n - 1`，每次减 1 |

三个要素缺一不可：

- 没有基线条件，递归停不下来——套娃没有"最小那层"，就一直拆个没完。
- 基线条件永远达不到（参数不收敛），同样停不下来——你手里那层永远拆不出更小的，游戏卡死。
- 递归步骤写错，拆出来的就不是“同一种小问题”，答案自然不对。

写递归之前，先在纸上回答三个问题：

1. **规模最小的情况是什么？这时答案是什么？**（写基线条件）
2. **规模为 n 的答案，怎么由规模更小的答案得来？**（写递归步骤）
3. **参数怎么变化，才能保证最终到达基线条件？**（检查收敛）

三个问题都有答案了，代码往往几分钟就写完。

## 7.1.3 阶乘：返回值的递归

`count_down` 只打印、不返回结果。更常见的递归通过 `return` 把“小问题的答案”组装成“大问题的答案”，最经典的例子是阶乘：

```text
5! = 5 × 4 × 3 × 2 × 1 = 120
```

观察规律：5! 里藏着 4!，4! 里藏着 3!——

```text
n! = n × (n-1)!    （当 n ≥ 1）
0! = 1             （数学约定，也是递归的基线条件）
```

这正是递归需要的全部：递推关系有了，基线条件有了。按 7.1.2 的三个问题走一遍：

1. 最小规模是 n = 0，答案约定为 1。
2. n! = n × (n−1)!。
3. 参数每次减 1，必然到达 0。

翻译成代码：

```c
// 7.1.3 factorial.c
#include <stdio.h>

int fact(int n)
{
	if (n == 0) {
		return 1;
	}
	return n * fact(n - 1);
}

int main(void)
{
	printf("5! = %d\n", fact(5));

	return 0;
}
```

<!-- output: 7.1.3 -->
```text
5! = 120
```

关键的一行是 `return n * fact(n - 1);`。它先**等** `fact(n - 1)` 算出结果，再乘上 n。整个计算从基线条件开始往回组装：

```text
fact(0) = 1
fact(1) = 1 × fact(0) = 1
fact(2) = 2 × fact(1) = 2
fact(3) = 3 × fact(2) = 6
fact(4) = 4 × fact(3) = 24
fact(5) = 5 × fact(4) = 120
```

有一点现在只能先记住：`fact(1)` 在计算时，`fact(3)` 那次调用里的 n 还好好保存着，没有被覆盖。它们各自有独立的“小隔间”，下一节会打开看。

## 7.1.4 两个基础例：求和与幂

用同样的三步法，再写两个递归。

**从 1 加到 n**：最小规模 n = 0 时和为 0；sum(n) = n + sum(n−1)；参数每次减 1。

**2 的 n 次方**：最小规模 n = 0 时 2^0 = 1；2^n = 2 × 2^(n−1)；参数每次减 1。

```c
// 7.1.4 sum_power.c
#include <stdio.h>

int sum_to(int n)
{
	if (n == 0) {
		return 0;
	}
	return n + sum_to(n - 1);
}

int power2(int n)
{
	if (n == 0) {
		return 1;
	}
	return 2 * power2(n - 1);
}

int main(void)
{
	printf("1 + 2 + ... + 100 = %d\n", sum_to(100));
	printf("2 的 10 次方 = %d\n", power2(10));

	return 0;
}
```

<!-- output: 7.1.4 -->
```text
1 + 2 + ... + 100 = 5050
2 的 10 次方 = 1024
```

这两个问题的套路一模一样：找到“怎么把 n 变成更小的 n”，再写“小答案如何拼成大答案”。求和、幂、阶乘、各位数字之和（7.2 会见到），全是这个配方。

和第 3 章的循环写法对比：`for` 循环从 1 加到 n，是你亲手推着变量一步步走；递归是你只描述"大 = 小 + 一步"，剩下的交给函数自己。就像传话游戏：循环是你自己跑完全程挨个通知，递归是你只告诉下一个人"把剩下的人通知到"，然后等着结果传回来。写递归的一大难关是“不敢信任它”——认准两件事：**出口正确、参数在变小**，就可以放心让函数调用自己。

## 7.1.5 反面教材：缺要素的递归

递归代码写错，最常见就是缺三要素之一。下面两个反例都不要照抄运行，看懂问题在哪即可。

**反例一：没有基线条件。**

```c
/* 错误示范：没有出口 */
int bad(int n)
{
	return n * bad(n - 1);
}
```

调用 `bad(3)` 会一直递归下去，n 变成负数也停不下来。每调用一次函数，系统就要为它保留一块记录参数和返回地址的内存（下一节细讲），无限递归最终会把这块内存耗尽，程序崩溃。

**反例二：参数不收敛。**

```c
/* 错误示范：参数不变小 */
int bad2(int n)
{
	if (n == 0) {
		return 1;
	}
	return n * bad2(n);
}
```

出口写得很正确，但递归调用传的还是 `n`，参数纹丝不动，永远到不了 `n == 0`——和反例一同样的下场。

用 7.1.2 的三个自查问题检验这两段代码，立刻就能发现问题。养成习惯：每写完一个递归函数，先别急着编译，把三个问题在纸上过一遍。

## 7.1.6 常见错误

| 错误 | 后果 | 纠正 |
|------|------|------|
| 忘写基线条件 | 无限递归，栈溢出崩溃 | 先写出口，再写递归步骤 |
| 递归调用传参不变 | 基线条件永远达不到 | 检查参数是否朝出口靠近 |
| 基线条件的返回值写错 | 结果整体偏差，如 `sum(0)` 写成返回 1 | 最小规模的答案要单独核实 |
| 出口条件用 `n <= 0` 却处理负数输入 | 有的输入绕过出口或逻辑错乱 | 想清楚参数的取值范围 |
| 认为“递归一定比循环高级” | 该用循环的地方硬写递归，又慢又绕 | 7.3、7.4 会专门对比 |

## 7.1.7 小结

- 递归是函数调用自己，把大问题拆成结构相同、规模更小的子问题。
- 递归三要素：基线条件（出口）、递归步骤（调用更小的自己）、规模收敛（参数朝出口靠近）。
- 写递归前三问：最小规模是什么？大答案怎么由小答案拼出来？参数怎么变化？
- 阶乘 `fact(n) = n × fact(n-1)`，出口 `fact(0) = 1`；求和、幂是同一配方。
- 缺基线条件或参数不收敛，都会无限递归直到崩溃。

## 练习

1. 递归三要素是什么？分别对应 `fact` 函数里的哪一行？
2. 写出递归计算 `1 × 2 × ... × n`（即 n!）的基线条件和递推关系。
3. 下面函数想计算 n!，错在哪？

```c
int fact(int n)
{
	if (n == 0) {
		return 1;
	}
	return n * fact(n);
}
```

4. 写出下面程序的输出（先手算，再编译验证）。

```c
int f(int n)
{
	if (n == 1) {
		return 1;
	}
	return n + f(n - 1);
}

int main(void)
{
	printf("%d\n", f(4));
	return 0;
}
```

5. 用递归写一个函数 `int power(int base, int n);`，计算 base 的 n 次方（n ≥ 0），并在 main 里打印 `3 的 4 次方 = 81`。

6. 编程题：用递归打印 1 到 5（输出 `1 2 3 4 5`，正序）。提示：想让数字从小到大出来，`printf` 应该放在递归调用之前还是之后？如果一时想不通，先随便放一个位置跑一次，看看结果，7.2 会解释原因。
