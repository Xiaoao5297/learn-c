# 7.2 调用栈与栈溢出

上一节留了一个问题：`fact(3)` 调用 `fact(2)` 时，`fact(3)` 里的 `n` 去哪了？为什么 `fact(2)` 用自己的变量，不会把 `fact(3)` 的弄丢？这一节回答它，顺带解释无限递归为什么会“崩”。

## 7.2.1 栈：函数的记账本

先看普通的函数调用（第 2 章）：main 调用 `greet`，`greet` 执行完，程序怎么知道该回到 main 的哪一行？main 里的变量怎么保证没被 `greet` 改坏？

答案是程序用一块叫**栈（stack）**的内存来“记账”。每次调用函数，系统就在栈顶压入一条记录，上面写着这次调用的参数、局部变量，以及执行完要回到哪里。这条记录叫**栈帧（stack frame）**。函数返回时，它的栈帧弹出，程序按记录的返回地址继续执行。

栈的规矩是后进先出：最后被调用的函数最先返回，像食堂里自动叠盘子的弹簧餐盘架——最后放上去的盘子，最先被人取走；也像你叠课堂作业本，收在最上面的那份，最先被抽出来改。

```text
main 调用 greet 时：

    ┌──────────────────┐ ← 栈顶
    │ greet 的栈帧      │   参数、局部变量、返回地址
    ├──────────────────┤
    │ main 的栈帧       │   原封不动地压在下面
    └──────────────────┘
```

`greet` 返回时，它的栈帧弹出，main 的栈帧露出，接着往下执行。每个函数调用都有自己独立的栈帧，这就是为什么各函数的局部变量互不干扰。

## 7.2.2 递归时栈的变化

递归没有特殊性：每调用一层，就压一个栈帧。以 `fact(3)` 为例，看栈怎么变（每一层一个栈帧，各自的 `n` 互不相干）：

```text
调用 fact(3)：

    fact(3): n=3        ← 压入，它调用了 fact(2)，暂停等待
    main

调用 fact(2)：

    fact(2): n=2        ← 压入
    fact(3): n=3        ← n=3 还完好地保存在自己的栈帧里
    main

调用 fact(1)：

    fact(1): n=1
    fact(2): n=2
    fact(3): n=3
    main

调用 fact(0)：

    fact(0): n=0        ← 到底了，命中基线条件，返回 1
    fact(1): n=1
    fact(2): n=2
    fact(3): n=3
    main
```

此刻栈里同时有 4 个 `fact` 的栈帧，4 个 `n` 分别是 0、1、2、3。可以想成 4 个同学站成一排传话：每人手里都攥着自己的数字，谁也不会把谁的弄丢。这就是 7.1.3 留下的问题的答案：**每一层递归都有自己的栈帧，谁也覆盖不了谁。**

`fact(0)` 返回 1 之后，进入“归来”阶段，一路弹栈、一路组装答案：

```text
fact(0) 返回 1        弹出，回到 fact(1)
fact(1) = 1 × 1 = 1   弹出，回到 fact(2)
fact(2) = 2 × 1 = 2   弹出，回到 fact(3)
fact(3) = 3 × 2 = 6   弹出，回到 main
```

所以递归的执行分两个阶段：

| 阶段 | 别名 | 发生什么 | 栈的变化 |
|------|------|----------|---------|
| 一路调用 | 递去 | 层层压栈，直到命中基线条件 | 越摞越高 |
| 一路返回 | 归来 | 层层弹栈，把小答案组装成大答案 | 越弹越矮 |

## 7.2.3 打印放在哪，顺序就反了

“递归调用之后的语句，要等归来时才执行”——这条规则有一个立刻能用的推论：**同一段递归，把 `printf` 挪个位置，输出顺序就反过来了。**

```c
// 7.2.3 print_order.c
#include <stdio.h>

void print_up(int n)
{
	if (n == 0) {
		return;
	}
	print_up(n - 1);
	printf("%d ", n);
}

void print_down(int n)
{
	if (n == 0) {
		return;
	}
	printf("%d ", n);
	print_down(n - 1);
}

int main(void)
{
	print_up(5);
	printf("\n");
	print_down(5);
	printf("\n");

	return 0;
}
```

<!-- output: 7.2.3 -->
```text
1 2 3 4 5
5 4 3 2 1
```

两个函数的代码几乎一样，只有 `printf` 和递归调用的先后不同：

- `print_down`：先打印再递归——打印发生在**递去**的路上，先印 5、再印 4……
- `print_up`：先递归再打印——一直压到 `n == 0` 才回头，打印发生在**归来**的路上，从最深层往上依次印 1、2、3……

7.1 练习里“正序打印 1 到 5”的谜底就在这里。想让递归“倒着处理数据”（比如倒序打印链表，7.5 会用），把处理代码写在递归调用**之后**就行，不需要额外的数组。

## 7.2.4 拆数字：各位和与倒序打印

第 2 章学过 `%` 和 `/` 这对搭档：

```text
2026 % 10 = 6     拿到个位
2026 / 10 = 202   砍掉个位
```

“砍掉个位之后还是个非负整数”——问题变小了，这正好是递归的形状。

**各位数字之和**：digit_sum(2026) = 6 + digit_sum(202)；基线条件是 `n == 0` 时和为 0。

**倒序打印每一位**：先打印个位 6，再递归处理 202。打印放在递归之前，就是 7.2.3 里的“递去时打印”。

```c
// 7.2.4 digits.c
#include <stdio.h>

int digit_sum(int n)
{
	if (n == 0) {
		return 0;
	}
	return n % 10 + digit_sum(n / 10);
}

void print_digits(int n)
{
	if (n == 0) {
		return;
	}
	printf("%d ", n % 10);
	print_digits(n / 10);
}

int main(void)
{
	printf("2026 各位之和 = %d\n", digit_sum(2026));
	print_digits(2026);
	printf("\n");

	return 0;
}
```

<!-- output: 7.2.4 -->
```text
2026 各位之和 = 10
6 2 0 2
```

注意这两个函数的递归调用传的是 `n / 10`，不是 `n - 1`——参数怎么变小没有标准答案，只要每次都朝基线条件靠近就行。

## 7.2.5 最大公约数：另一条收敛路径

辗转相除法（欧几里得算法）：gcd(a, b) = gcd(b, a % b)，当 b 等于 0 时 a 就是答案。比如 gcd(48, 18)：

```text
gcd(48, 18) = gcd(18, 48 % 18) = gcd(18, 12)
            = gcd(12, 18 % 12) = gcd(12, 6)
            = gcd(6, 12 % 6)  = gcd(6, 0)
            = 6
```

```c
// 7.2.5 gcd.c
#include <stdio.h>

int gcd(int a, int b)
{
	if (b == 0) {
		return a;
	}
	return gcd(b, a % b);
}

int main(void)
{
	printf("gcd(48, 18) = %d\n", gcd(48, 18));

	return 0;
}
```

<!-- output: 7.2.5 -->
```text
gcd(48, 18) = 6
```

这个例子的价值在于：基线条件不一定长得像 `n == 0`，收敛方式也不一定是减 1。判断标准始终是 7.1.2 的第三问——**参数是否必然到达基线条件**。`gcd` 里每轮 `b` 都严格变小且非负，必然到达 0。

## 7.2.6 栈溢出

现在可以准确解释无限递归为什么会崩了。

栈的容量是有限的（常见系统上只有几 MB）。每层递归调用压一个栈帧，递归多深，栈就摞多高——就像往弹簧盘架上不停摞盘子，架子再高也有上限，盘太多堆塌了，一架子盘子全摔了。层数太多，栈放不下，程序崩溃——这叫**栈溢出（stack overflow）**。

看一个概念示意，**不要编译运行**：

```c
/* 概念示意：无出口的递归，运行会崩溃 */
int forever(int n)
{
	return forever(n + 1);
}
```

正常规模的递归（几百、几千层）完全没问题；但无限递归几毫秒就能把栈撑爆。这也提示我们：设计递归时要掂量问题的规模。有些问题（比如朴素的斐波那契，下一节的主角）递归层数本身不高，但调用次数爆炸；有些问题（比如处理几十万个节点的链表，7.5 会提）递归深度本身就足以爆栈，用循环更稳妥。

## 7.2.7 常见错误

| 错误 | 后果 | 纠正 |
|------|------|------|
| 递归调用写 `f(n--)` | 传进去的还是旧值 n，永不收敛 | 写 `f(n - 1)`；`n--` 是“先取旧值再自减” |
| 想“倒着输出”却把打印放在递归前 | 输出顺序没变 | 打印放递归调用**之后**（7.2.3） |
| 对负数输入不设防，`n == 0` 永远错过 | 栈溢出 | 基线条件用 `n <= 0`，或先检查输入合法性 |
| 无限递归程序拿去跑，“试试看会不会自己停” | 必然崩溃 | 栈不会自动恢复，崩溃就是结局 |

## 7.2.8 小结

- 每次函数调用在栈上压一个栈帧（参数、局部变量、返回地址），返回时弹出。
- 递归每层有自己的栈帧，所以各层的参数互不覆盖；这就是递归能“一去一回”的机制。
- 递归执行分两个阶段：递去（压栈到底）与归来（弹栈组装答案）。
- `printf` 放在递归调用之前 = 递去时执行（正着来）；放在之后 = 归来时执行（倒着来）。
- 参数变小的方式不限于减 1：`n / 10`、`a % b` 都行，关键是不管怎么变都要到达基线条件。
- 栈容量有限，递归太深或无限递归会栈溢出崩溃。
