# 7.1 认识递归：函数自己调用自己

> 💬 **节前语：**
>
> 从第2章起，我们就学会了"函数"——把一段代码打包成盒子，随时调用。
>
> 但你有没有想过：**一个函数，能不能调用它自己？**
>
> ```c
> void tellStory() {
>     printf("从前有座山，山里有座庙……");
>     tellStory();   // 咦？故事里又讲了个故事？
> }
> ```
>
> 看起来像在"死循环"，但其实——**允许函数调用自己**，正是C语言最强大的能力之一。这种写法叫 **递归（Recursion）**。
>
> 生活中，递归是"套娃"、"照镜子"、"词典套词典"；程序里，递归是**把一个大问题，拆成一个结构一样但更小的自己，直到小到直接能答出来**。
>
> 这一节我们先搞懂三件事：递归长什么样、它为什么能"停下来"、怎么写出第一个递归。准备好了吗？开始吧！

---

## 7.1.1 生活中的递归：先找感觉

### 🪆 俄罗斯套娃

一个大娃娃里装着一个略小的娃娃，小娃娃里又装着一个更小的……最小的娃娃里是空的。

"打开娃娃 → 里面有个更小的娃娃 → 再打开……"——这个"动作"重复出现，而且每次处理的对象都**小一号**。这就是递归的结构。

### 📖 查词典

你查"递归"这个词，解释里出现了"调用"；你又去查"调用"，里面又出现了"函数"；再去查"函数"……好在查到最后，总有一些**基础词**（比如"计算"），它的解释不再让你继续查下去。

- 那些"还要继续查的词" = 还要继续拆的问题
- 那些"不用再查的基础词" = **能直接回答的问题（出口）**

### 🪞 两面镜子

两面镜子对着放，镜子里永远有镜子……如果没有尽头，就永远看不到底。**递归如果没有"出口"，也会永远停不下来。**

> 📌 **生活给我们的启发：** 递归不是简单的"无限循环"，而是"**大的拆小的，小的拆更小的，直到小到不用拆**"。

---

## 7.1.2 递归长什么样：第一个递归程序

先看一个最简单的递归——**倒计时发射**：

```c
#include <stdio.h>

void countDown(int n) {
    if (n == 0) {              // 基线条件（出口）：数到 0 就停
        printf("发射！\n");
        return;                // return 不再往下走，递归在这里"刹车"
    }
    printf("%d ", n);          // 先报数
    countDown(n - 1);          // 递归：数下一个（问题变小了一号！）
}

int main() {
    countDown(3);
    return 0;
}
```

输出：
```
3 2 1 发射！
```

看 `countDown` 这个函数：它的函数体里，**出现了对 `countDown` 自己的调用**。这就是递归。

### 🔍 它是怎么"停"下来的？

关键就在开头的 `if`：

- 只要 `n != 0`，就继续调用 `countDown(n - 1)` —— 参数**变小**
- 一旦 `n == 0`，走 `if` 分支，`printf("发射！")` 后 `return` —— 不再调用自己，**递归结束**

> 📌 **递归函数必须有两部分：**
>
> | 部分 | 作用 | 对应本例 |
> |------|------|---------|
> | ① **基线条件（出口）** | 问题小到不用再拆，直接给出答案并返回 | `if (n == 0)` |
> | ② **递归步骤** | 把问题拆成"更小的自己"，并**确保参数越来越接近出口** | `countDown(n - 1)` |
>
> 缺了① → 无限递归，程序栈溢出崩溃；缺了② → 参数不变，永远到不了出口，同样崩溃。

### 🎬 一步步看执行过程

```
main 调 countDown(3)
    countDown(3): n=3 ≠ 0 → 打印 "3 " → 调 countDown(2)
        countDown(2): n=2 ≠ 0 → 打印 "2 " → 调 countDown(1)
            countDown(1): n=1 ≠ 0 → 打印 "1 " → 调 countDown(0)
                countDown(0): n==0 → 打印 "发射！" → return（回到上一层）
            countDown(1) 结束，return
        countDown(2) 结束，return
    countDown(3) 结束，return
回到 main，程序结束
```

注意最后一层 `countDown(0)` 结束之后，程序会**一层一层往回返**——就像楼梯走到底，还要再爬回来。这个"一去一回"的过程，我们下一节仔细看。

## 7.1.3 经典的"返回值"递归：阶乘

倒计时只打印、不返回结果。递归更常见的是**通过 return 把"小问题的答案"组装成"大问题的答案"**。最经典的例子就是**阶乘（factorial）**：

```
5! = 5 × 4 × 3 × 2 × 1 = 120
```

### 找规律：递推关系

发现了吗？`5!` 里藏着 `4!`：

```
5! = 5 × 4!
4! = 4 × 3!
3! = 3 × 2!
2! = 2 × 1!
1! = 1
```

写成一般规律：

```
n! = n × (n-1)!          （当 n ≥ 1）
1! = 1                   （出口：最小的情况，答案一眼看出）
```

数学上习惯定义 `0! = 1`（为了让公式更整齐），所以出口也可以写成：

```
0! = 1
```

### 🧱 用"递归三步法"写代码

> 写递归别急着敲键盘，先走这三步：

| 步骤 | 思考 | 阶乘的回答 |
|------|------|-----------|
| ① 找出口 | 最小的情况是什么？答案直接是多少？ | `n == 0` 时，答案是 `1` |
| ② 找递推 | 大问题 = 怎么由小一号的问题算出来？ | `n! = n * (n-1)!` |
| ③ 写代码 | `if 出口 return 出口答案;` + `return 递推(小一号);` | 见下 |

```c
#include <stdio.h>

// 计算 n 的阶乘
int fact(int n) {
    if (n == 0) {              // ① 出口：0! = 1
        return 1;
    }
    return n * fact(n - 1);    // ② 递推：n! = n * (n-1)!
}

int main() {
    printf("5! = %d\n", fact(5));
    return 0;
}
```

输出：
```
5! = 120
```

> 💡 **读懂 `return n * fact(n - 1);`：** 这行代码先**等** `fact(n-1)` 把结果算出来，再用 `n` 去乘。所以 `fact(5)` 会一路等下去，直到 `fact(0)` 直接返回 `1`，然后一路乘回来：

```
fact(0) = 1
fact(1) = 1 * fact(0) = 1 * 1 = 1
fact(2) = 2 * fact(1) = 2 * 1 = 2
fact(3) = 3 * fact(2) = 3 * 2 = 6
fact(4) = 4 * fact(3) = 4 * 6 = 24
fact(5) = 5 * fact(4) = 5 * 24 = 120
```

## 7.1.4 递归的"思维方式"：大事化小

递归的本质，可以浓缩成一个成语：**大事化小，小事化了**。

比如要解决"算 5 个人排成一排有几种站法"（5!），我们不直接想 5 个人，而是想：

- 先让 1 个人站到最前面（有 5 种选择）
- 剩下的 4 个人怎么站？——这正是"算 4 个人站法"（4!）这个小一号的问题！

所以：

```
5 人的站法 = 5 × 4 人的站法
4 人的站法 = 4 × 3 人的站法
……
1 人的站法 = 1          （出口：就 1 种）
```

**你不必每一步都想清楚，只要相信"小一号的问题会被函数自己解决"。** 这正是递归和循环最大的不同：

| | 循环 | 递归 |
|---|------|------|
| 思路 | 我手动一步步"推着"往前走 | 我描述"大 = 小 + 一步"，剩下的交给函数自己 |
| 关键 | 控制变量和结束条件 | 找对**出口**和**递推关系** |
| 代码风格 | 适合"重复做同一件事" | 适合"套娃式的结构问题" |

> 🎯 **判断标准：** 如果一个任务"处理完一部分，剩下的是**同一件事但规模更小**"，那它天生就适合递归。

## 7.1.5 反面教材：写错递归会怎样？

### ❌ 忘了出口 → 栈溢出

```c
int bad(int n) {
    return n * bad(n - 1);   // ❌ 没有出口！n 一路变小但永远回不来
}
```

调用 `bad(3)` 会无限调用下去，直到把程序内存（栈）耗尽崩溃。这就像两面镜子照到**没有尽头**，最后系统"内存用光"。

### ❌ 参数没有变小 → 死递归

```c
int bad2(int n) {
    if (n == 0) return 1;    // 出口存在……
    return n * bad2(n);      // ❌ 但参数一直是 n，永远到不了 n==0！
}
```

出口写得再对，如果每次调用参数**不变小**，也永远走不到出口。**出口正确 + 参数越来越接近出口，两个条件缺一不可。**

> 🚨 **铁律：** 每次递归调用，都必须让问题**向出口方向缩小一步**。检验方法：盯着递归调用的参数，看它是不是比刚才"小"。

## 7.1.6 本节小结

这一节我们学了：

✅ **递归是什么：** 函数调用自己，把大问题拆成"更小的一号自己"

✅ **生活中的递归：** 套娃、查词典、镜子——"大的拆小的，小到不用拆"

✅ **两大部件：** ① 基线条件（出口）② 递归步骤（让参数变小去接近出口）

✅ **递归三步法：** 找出口 → 找递推关系 → 写成 `if 出口 return 答案; return 递推(小一号);`

✅ **阶乘：** `fact(n) = n * fact(n-1)`，出口 `fact(0) = 1`

✅ **反面教材：** 忘了出口、参数不变小 → 栈溢出 / 死递归

> 💡 **记住：递归不是"魔法"，是"套娃"。写递归先问自己两句——最小的情况答案是什么？大问题怎么由小一号算出来？**

```c
#include <stdio.h>
```
