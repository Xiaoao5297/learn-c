# 7.4 汉诺塔与分治

上一节的结论是“递推简单的问题别硬用递归”。那递归的高光时刻在哪里？就在汉诺塔：这个问题用循环写极其痛苦，用递归却短得像一行诗。这一节解出它，并认识背后的通用思路——分而治之。

## 7.4.1 游戏规则

三根柱子 A、B、C。A 柱上从下到上摞着 n 个盘子，大的在下、小的在上。目标：把全部盘子移到 C 柱。规则只有两条：

1. 一次只移动一个盘子。
2. 任何时刻，大盘子不能压在小盘子上面。

```text
初始：              目标：
    A               C
   [1]               [1]
  [ 2 ]             [ 2 ]
 [  3  ]           [  3  ]
═════════          ═════════
A   B   C          A   B   C
```

n = 3 时最少要 7 步。n 个盘子最少要 2^n − 1 步，这个结论 7.4.4 会用程序验证。

## 7.4.2 换个思路：只管最大的盘子

如果盯着“第 1 步搬哪个盘子”，很快就会晕。换一个视角——只看**最大的那个盘子**，就像整理一堆试卷时先别管小题，只抓最重要那份：

> 最大的盘子要从 A 移到 C，前提是 A 上它上面的 n − 1 个盘子全都让开，而且 C 顶上没有东西压着它。让开的地方只能是 B。

于是“移 n 个盘子”被拆成三幕：

```text
第 1 幕：把上面 n-1 个盘子从 A 移到 B（C 可以当中转）   ← 规模小一号的汉诺塔
第 2 幕：把最大的盘子从 A 移到 C                        ← 就一步
第 3 幕：把 B 上的 n-1 个盘子从 B 移到 C（A 可以当中转） ← 又是小一号的汉诺塔
```

第 1 幕和第 3 幕和原问题结构完全相同，只是盘子少了一个、柱子的角色换了个名。这正是 7.1 说的“大问题里装着更小的自己”，于是递归呼之欲出：

1. 基线条件：只剩 1 个盘子时，直接把它移过去。
2. 递归步骤：两次调用 `hanoi(n - 1, ...)`，中间夹一次单盘移动。
3. 规模收敛：n 每层减 1，必然到达 1。

## 7.4.3 递归解法

```c
// 7.4.3 hanoi.c
#include <stdio.h>

int steps = 0;

void hanoi(int n, char from, char helper, char to)
{
	if (n == 1) {
		steps++;
		printf("第 %d 步：盘子 1 %c -> %c\n", steps, from, to);
		return;
	}
	hanoi(n - 1, from, to, helper);
	steps++;
	printf("第 %d 步：盘子 %d %c -> %c\n", steps, n, from, to);
	hanoi(n - 1, helper, from, to);
}

int main(void)
{
	hanoi(3, 'A', 'B', 'C');
	printf("共 %d 步，正好是 2^3 - 1 = 7\n", steps);

	return 0;
}
```

<!-- output: 7.4.3 -->
```text
第 1 步：盘子 1 A -> C
第 2 步：盘子 2 A -> B
第 3 步：盘子 1 C -> B
第 4 步：盘子 3 A -> C
第 5 步：盘子 1 B -> A
第 6 步：盘子 2 B -> C
第 7 步：盘子 1 A -> C
共 7 步，正好是 2^3 - 1 = 7
```

对照三幕读一遍输出：前 3 步把盘子 1、2 挪到 B（第 1 幕），第 4 步把盘子 3 从 A 挪到 C（第 2 幕），后 3 步把盘子 1、2 挪到 C（第 3 幕）。

函数签名值得看一眼：`hanoi(n, from, helper, to)` 的后三个参数是“三根柱子的角色”，而不是固定的 A、B、C。第 1 幕调用 `hanoi(n - 1, from, to, helper)`——目标是 helper，原来的目标柱 `to` 降级当中转。角色在递归中轮换，这是汉诺塔解法的精髓，纸上把 n = 3 的三幕各柱子内容推一遍就明白了。

还有一个词必须说：**信仰之跃**。写这段代码时，你没有（也不该）去推演“`hanoi(2, A, C, B)` 内部每一步怎么走”，你只是相信：**只要函数能移 n − 1 个盘子，它就能完成第 1 幕和第 3 幕**。这就像把整理试卷的任务交给组长：你只需要确认"他收到的任务说明和你的完全一样，只是试卷更少"，不必盯着他一笔一笔怎么改。基线条件保证递归会终止，参数收敛保证会到达基线条件——剩下的交给递归。人肉模拟深几层就会晕，这个“不追问内部细节、只信任接口”的心态，是从“会写递归”到“用好递归”的关键一步。

## 7.4.4 验证步数公式

汉诺塔的递推很清楚：移 n 个盘子 = 移两次 n−1 个盘子 + 移一次大盘 = 2 × f(n−1) + 1。从 f(1) = 1 开始：3、7、15、31……正是 2^n − 1。

写个程序同时用递归数步数、按公式算步数，两边对照：

```c
// 7.4.4 hanoi_formula.c
#include <stdio.h>

int move_count = 0;

void hanoi(int n, char from, char helper, char to)
{
	if (n == 1) {
		move_count++;
		return;
	}
	hanoi(n - 1, from, to, helper);
	move_count++;
	hanoi(n - 1, helper, from, to);
}

int main(void)
{
	for (int n = 1; n <= 10; n++) {
		move_count = 0;
		hanoi(n, 'A', 'B', 'C');

		int formula = 1;
		for (int i = 0; i < n; i++) {
			formula = formula * 2;
		}

		printf("n = %d：实际 %d 步，公式 2^%d - 1 = %d\n",
		       n, move_count, n, formula - 1);
	}

	return 0;
}
```

<!-- output: 7.4.4 -->
```text
n = 1：实际 1 步，公式 2^1 - 1 = 1
n = 2：实际 3 步，公式 2^2 - 1 = 3
n = 3：实际 7 步，公式 2^3 - 1 = 7
n = 4：实际 15 步，公式 2^4 - 1 = 15
n = 5：实际 31 步，公式 2^5 - 1 = 31
n = 6：实际 63 步，公式 2^6 - 1 = 63
n = 7：实际 127 步，公式 2^7 - 1 = 127
n = 8：实际 255 步，公式 2^8 - 1 = 255
n = 9：实际 511 步，公式 2^9 - 1 = 511
n = 10：实际 1023 步，公式 2^10 - 1 = 1023
```

两列完全一致。顺便感受指数增长的威力：n = 64 时步数是 2^64 − 1，约 1844 亿亿。就算一秒移一个盘子，也需要五千多亿年——传说里“移完世界就毁灭”，数学上是站得住的。

## 7.4.5 分而治之

汉诺塔的解法展示了一个通用套路——**分而治之（divide and conquer）**。生活原型是老师批一摞试卷：一个人从头改到尾太慢，就把试卷分给几个组长，每人先把自己的那摞改好（治），最后摞在一起（合）。每个组长手里又是一摞试卷，还能再往下分——这正是"结构相同、规模更小"。

| 步骤 | 含义 | 汉诺塔中的体现 |
|------|------|---------------|
| 分（divide） | 把大问题切成几个结构相同的小问题 | n 个盘子 → 两次 n−1 个盘子 + 一次单盘移动 |
| 治（conquer） | 递归解决每个小问题 | `hanoi(n - 1, ...)` 自己搞定 |
| 合（combine） | 把小问题的解按顺序拼起来 | 三幕依次执行，就是完整解 |

再补一个更轻量的例子，把“分”的形状看得更清楚——递归求数组前 n 个元素的和：

```c
// 7.4.5 array_sum.c
#include <stdio.h>

int array_sum(const int a[], int n)
{
	if (n == 0) {
		return 0;
	}
	return a[n - 1] + array_sum(a, n - 1);
}

int main(void)
{
	int a[4] = {3, 5, 7, 9};

	printf("总和：%d\n", array_sum(a, 4));

	return 0;
}
```

<!-- output: 7.4.5 -->
```text
总和：24
```

“前 n 个的和 = 最后一个元素 + 前 n−1 个的和”，出口是“0 个元素的和为 0”。它一次只切掉一个元素，还称不上真正的分治；但它演示了分治的骨架。真正的分治会把问题**对半切**——第 8 章的快速排序、归并排序，第 9 章的二叉树，都是这条路，到时候你会不断想起汉诺塔。

## 7.4.6 递归还是循环

至此可以对第 7 章见过的例子做个总账：

| 问题 | 结构 | 用什么 | 理由 |
|------|------|--------|------|
| 数组求和、找最值 | 顺序重复 | 循环 | 简单直接，没有递归的必要 |
| 斐波那契 | 递推，会重复计算 | 循环，或递归加记忆化 | 朴素递归代价是指数级的（7.3） |
| 汉诺塔 | 嵌套：解里装着两个同构的子问题 | 递归 | 循环要自己维护“每层去哪”的状态，递归让调用栈替你记 |
| 链表操作 | 嵌套：链 = 头 + 剩下的链 | 递归或循环都行 | 下一节展开 |

判断口诀：**问题能不能拆成“结构相同的更小问题”？** 能，而且循环要自己记一堆状态——用递归，让栈替你记账；只是从头走到尾的重复——用循环；递归最清晰但重复计算多——递归加记忆化。

## 7.4.7 小结

- 汉诺塔规则：一次移一盘、大盘不能压小盘；n 个盘子最少 2^n − 1 步。
- 三幕拆解：移 n − 1 个到中转柱、移最大盘到目标柱、再把 n − 1 个移到目标柱——两幕是同构的小问题。
- 递归解法核心是“柱子角色轮换”：`hanoi(n - 1, from, to, helper)` 和 `hanoi(n - 1, helper, from, to)`。
- 信仰之跃：只信任“函数能解小一号的问题”，不人肉模拟内部细节。
- 分而治之：分、治、合三步。汉诺塔是完整版，数组求和是最小版，快排和二叉树是后续。
- 选择递归还是循环，看问题的结构，而不是看个人口味。

## 练习

1. n = 4 时汉诺塔最少要多少步？用 2^n − 1 和“2 × f(n−1) + 1”两种方式各算一遍。
2. 手动模拟 `hanoi(2, 'A', 'B', 'C')`（借助 A 中转时柱子角色怎么换），写出三步输出。
3. 把 7.4.3 的基线条件改成 `if (n == 0)` 且什么都不打印，`hanoi(3, ...)` 的输出会发生什么变化？
4. 下面代码想解汉诺塔，有两处错误，请指出并改正：

```c
void hanoi(int n, char from, char helper, char to)
{
	if (n == 0) {
		printf("盘子 1：%c -> %c\n", from, to);
		return;
	}
	hanoi(n - 1, from, helper, to);
	printf("盘子 %d：%c -> %c\n", n, from, to);
	hanoi(n - 1, helper, from, to);
}
```

5. 编程题：仿照 7.4.3 打印 `hanoi(4, 'A', 'B', 'C')` 的完整过程，数一数是不是 15 行，并说明其中第 8 步是什么（提示：最大的盘子在哪一步动）。
6. 编程题：写一个递归函数 `int power(int base, int n);`，利用分治思想：n 为偶数时算 `power(base, n / 2)` 的平方，n 为奇数时多乘一个 base。用它算 2^10 和 3^5。

<details>
<summary>参考答案</summary>

1. 2^4 − 1 = 15；递推：f(1) = 1，f(2) = 3，f(3) = 7，f(4) = 2 × 7 + 1 = 15。一致。
2. 调用 `hanoi(2, 'A', 'B', 'C')`：第 1 幕 `hanoi(1, A, C, B)`——盘子 1 从 A 到 B；第 2 幕——盘子 2 从 A 到 C；第 3 幕 `hanoi(1, B, A, C)`——盘子 1 从 B 到 C。输出：

```text
盘子 1：A -> B
盘子 2：A -> C
盘子 1：B -> C
```

3. 输出不变，仍是同样的 7 步。`n == 0` 时问题为空、无事可做，直接返回即可；单盘移动交给 `n == 1` 之外的普通路径打印。这正是练习 4 考察的写法之一。
4. 两处错误：其一，基线条件写成 `n == 0` 却打印移动，`hanoi(0, ...)` 会被多打一次移动，而且这个出口含义错乱——0 个盘子无事可做，应改为 `if (n == 0) return;`；其二，第 1 幕写成了 `hanoi(n - 1, from, helper, to)`，目标写成了 `to`，中转没换——应为 `hanoi(n - 1, from, to, helper)`（先借助 `to` 把 n − 1 个挪到 `helper`）。改正后：

```c
void hanoi(int n, char from, char helper, char to)
{
	if (n == 0) {
		return;
	}
	hanoi(n - 1, from, to, helper);
	printf("盘子 %d：%c -> %c\n", n, from, to);
	hanoi(n - 1, helper, from, to);
}
```

5. 共 15 行（2^4 − 1）。第 8 步是 `盘子 4 A -> C`——最大的盘子在第 2 幕、恰好一半的位置移动；它动之前 7 步是“把上面 3 个让开”，动之后 7 步是“把 3 个再盖上”，所以大盘永远在第 2^n − 1 步的正中央。
6. 参考代码：

```c
#include <stdio.h>

int power(int base, int n)
{
	if (n == 0) {
		return 1;
	}
	int half = power(base, n / 2);
	if (n % 2 == 0) {
		return half * half;
	}
	return half * half * base;
}

int main(void)
{
	printf("2 的 10 次方 = %d\n", power(2, 10));
	printf("3 的 5 次方 = %d\n", power(3, 5));

	return 0;
}
```

输出 `2 的 10 次方 = 1024`、`3 的 5 次方 = 243`。每次把指数减半，调用深度从 n 降到约 log2(n)——比 7.1 的逐个减 1 更快，这就是分治在指数问题上的省力之处。
