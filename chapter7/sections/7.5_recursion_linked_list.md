## 7.5.1 为什么说链表天生适合递归？

看一个链表：

```
head → 10 → 20 → 30 → NULL
```

如果从 `head` 看，它是"10 开头的一条链表"；但如果我们把眼光移到第二个节点，`20 → 30 → NULL` **也是一条合法的链表**（只是短一点）。再往后，`30 → NULL` 还是链表，`NULL` 是"空链表"。

于是任何链表都能写成：

```
链表 = 一个节点 + 一条（更短的）链表
空链表（NULL）= 出口
```

> 📌 **这就是递归需要的全部！** 一个链表天然就是"大问题（整条链） = 一步（头节点）+ 更小的问题（剩下的链）"的结构。出口也很明确：链表走到 `NULL` 就是空，不用再拆了。

| 链表 | 递归视角 |
|------|---------|
| 10 → 20 → 30 → NULL | 节点10 + 链表(20 → 30 → NULL) |
| 20 → 30 → NULL | 节点20 + 链表(30 → NULL) |
| 30 → NULL | 节点30 + 链表(NULL) |
| NULL | **空链表 = 出口** |

## 7.5.2 递归版遍历打印：printListRec

先拿最简单的"正序打印"开刀。第6章我们用 `while` 循环顺着走；递归版思路是：

> 打印链表 = 打印头节点 + 打印"剩下的链表"；遇到空链表（NULL）就停。

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int data;
    struct Node *next;
} Node;

Node *createNode(int value) {          // 第6章的老朋友，造节点
    Node *node = (Node *)malloc(sizeof(Node));
    if (node == NULL) return NULL;
    node->data = value;
    node->next = NULL;
    return node;
}

// 递归版正序打印：10 -> 20 -> 30 -> NULL
void printListRec(Node *head) {
    if (head == NULL) {                // 出口：空链表
        printf("NULL\n");
        return;
    }
    printf("%d -> ", head->data);      // 先打印自己
    printListRec(head->next);          // 再打印"剩下的链表"
}
```

> 💡 **和第6章循环版对比：** 循环版要手动维护一个 `cur` 指针，还得写三条语句：
>
> ```c
> for (Node *cur = head; cur != NULL; cur = cur->next) {
>     printf("%d -> ", cur->data);
> }
> ```
>
> 递归版连 `cur` 都不用建——**"下一个要处理的节点"就写在递归参数里**，由调用栈自动帮我们记着走。

## 7.5.3 逆序打印：递归的"杀手锏" 🎯

想从最后一个节点**倒着**打印（`30 -> 20 -> 10 -> NULL`），循环版要怎么办？得先把所有 data 存进数组，再反过来输出，麻烦。

而递归版呢？还记得 7.2 的"顺序魔法"吗——**把打印挪到递归调用之后**，就变成"归来"时打印，顺序自然反了！

```c
// 递归版逆序打印：30 -> 20 -> 10 -> NULL
void printReverseRec(Node *head) {
    if (head == NULL) {                // 出口：空链表，什么都不打印
        return;
    }
    printReverseRec(head->next);       // 先递归到底
    printf("%d -> ", head->data);      // 归来路上才打印 → 从后往前
}
```

### 🔍 为什么几行代码就搞定了？

`printReverseRec(head)` 的执行顺序：

```
printReverseRec(10)：先不管自己，去处理 10 后面的链表（20 → 30）
    printReverseRec(20)：先处理 20 后面的（30）
        printReverseRec(30)：先处理 30 后面的（NULL）
            printReverseRec(NULL)：出口，直接 return
        归来：打印 30
    归来：打印 20
归来：打印 10
```

**调用栈自动帮我们把"后面的节点"先处理完，回来时自然就是从后往前。** 循环想做到这一点，往往得借助额外的数组或栈——递归一句话就省掉了。

> 📌 **记住这个套路：** "想要倒着处理一个序列" → 让递归先往下走，处理代码写在**递归调用之后**。这个思路以后写二叉树（先左子树再右子树……）还会反复用到！

## 7.5.4 数节点 & 求和：把"答案"从尾部传回来

### 🔢 数一数有多少个节点：countNodes

> 节点数 = 0（空链表） + 否则 = 1 + 后面链表的节点数

```c
int countNodes(Node *head) {
    if (head == NULL) return 0;                    // 出口：空链表 0 个
    return 1 + countNodes(head->next);             // 递推：自己 1 个 + 后面的个数
}
```

### ➕ 求所有节点的和：sumList

```c
int sumList(Node *head) {
    if (head == NULL) return 0;                    // 出口：空链表和为 0
    return head->data + sumList(head->next);       // 递推：自己的 data + 后面的和
}
```

**递推过程（以 `10 → 20 → 30` 为例）：**

```
countNodes(NULL) = 0                      sumList(NULL) = 0
countNodes(30)   = 1 + 0 = 1              sumList(30)   = 30 + 0 = 30
countNodes(20)   = 1 + 1 = 2              sumList(20)   = 20 + 30 = 50
countNodes(10)   = 1 + 2 = 3              sumList(10)   = 10 + 50 = 60
```

> 💡 看到没？"答案"是在**归来的路上**一步步算出来的：先算最小的空链表，再往上把每个节点的值"加"进来。

## 7.5.5 递归释放整条链：freeListRec

第6章的 `freeList` 用循环释放，还特别强调"先记下一个再 free 当前的"。递归版更省心：

```c
void freeListRec(Node *head) {
    if (head == NULL) return;          // 出口：空链表，没有要释放的
    freeListRec(head->next);           // ① 先释放"后面的链表"
    free(head);                        // ② 再释放自己
}
```

### 🔍 为什么先递归、后 free？

注意顺序：先递归处理 `head->next`，**等它整条都释放完了**，才 `free(head)`。这样保证：`free(head)` 的时候，`head->next` 那段已经没了，但当前这个 `head` 还没被读过——**绝不会去碰已释放的内存**（第6章讲的悬垂陷阱）。

> ⚠️ 反过来（先 `free(head)` 再递归 `head->next`）就错了——`free(head)` 之后再去读 `head->next`，读的是已释放的内存！顺序是递归版的"生命线"。

调用 `freeListRec(head)` 后，别忘了在 main 里把 `head = NULL`（好习惯，防止悬垂）。

## 7.5.6 综合实战：一个"递归版链表工具箱"

把前面几个函数拼起来，做一个完整演示：

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int data;
    struct Node *next;
} Node;

Node *createNode(int value) {
    Node *node = (Node *)malloc(sizeof(Node));
    if (node == NULL) return NULL;
    node->data = value;
    node->next = NULL;
    return node;
}

void push_back(Node **head, int value) {       // 尾插（第6章），保持顺序
    Node *node = createNode(value);
    if (node == NULL) return;
    if (*head == NULL) {
        *head = node;
        return;
    }
    Node *tail = *head;
    while (tail->next != NULL) {
        tail = tail->next;
    }
    tail->next = node;
}

// ---- 以下全是递归版操作 ----
void printListRec(Node *head) {                // 正序打印
    if (head == NULL) {
        printf("NULL\n");
        return;
    }
    printf("%d -> ", head->data);
    printListRec(head->next);
}

void printReverseRec(Node *head) {             // 逆序打印
    if (head == NULL) return;
    printReverseRec(head->next);
    printf("%d -> ", head->data);
}

int countNodes(Node *head) {
    if (head == NULL) return 0;
    return 1 + countNodes(head->next);
}

int sumList(Node *head) {
    if (head == NULL) return 0;
    return head->data + sumList(head->next);
}

void freeListRec(Node *head) {                 // 递归释放整条链
    if (head == NULL) return;
    freeListRec(head->next);
    free(head);
}

int main() {
    Node *head = NULL;

    push_back(&head, 10);
    push_back(&head, 20);
    push_back(&head, 30);

    printf("正序：");
    printListRec(head);

    printf("逆序：");
    printReverseRec(head);
    printf("NULL\n");

    printf("节点数：%d\n", countNodes(head));
    printf("总和：%d\n", sumList(head));

    freeListRec(head);          // 递归释放
    head = NULL;                // 释放后置 NULL，好习惯
    return 0;
}
```

输出：
```
正序：10 -> 20 -> 30 -> NULL
逆序：30 -> 20 -> 10 -> NULL
节点数：3
总和：60
```

> 🎉 跑起来了吗？短短几个递归函数，就把链表的打印（正/逆）、统计、释放全搞定了——**每段核心代码就 3~5 行**！

## 7.5.7 递归 vs 循环：到底选谁？

学了这么多，我们来做个"终极对决"：

| 对比项 | 递归版 | 循环版 |
|--------|--------|--------|
| 代码长度 | 短，贴近问题结构 | 略长，要手动维护指针 |
| 逆序处理 | **天然支持**（调用后写代码） | 麻烦，要额外数组/栈 |
| 会不会重复算 | 可能（如斐波那契） | 一般不会 |
| 栈开销 | 每层压栈帧，**递归太深会栈溢出** | 几乎没有额外内存 |
| 出错风险 | 忘出口/参数不变 → 崩 | 循环条件写错 → 死循环 |

**给链表的建议：**

- 链表不长（几百几千个节点）：递归版**又短又清晰**，放心用 ✅
- 链表特别长（比如几万、几十万个节点）：递归层数太多可能爆栈，用循环更稳妥 ⚠️

> 📌 **一句话决策：** 递归帮你"看清结构"，循环帮你"省内存"。**结构复杂、深度不大** → 递归；**单纯要遍历很长的链** → 循环。

## 7.5.8 本节小结

这一节我们学了：

✅ **链表是递归结构：** 链表 = 头节点 + 更短的链表；NULL = 出口

✅ **递归打印：** 打印自己 + 递归打印剩下的；`printf` 放递归前 = 正序

✅ **递归逆序：** `printf` 放递归**后**，归来时打印 → 自动倒序，省掉额外数组

✅ **数节点 / 求和：** 答案从尾部（空链表=0）一路传回来累加

✅ **递归释放：** 先递归释放后面，再 free 自己——顺序是生命线

✅ **选型判断：** 深度不大、结构套娃 → 递归；链表超长 → 循环防爆栈

> 💡 **记住：当你学会"把问题看成套娃"，链表操作就没有难的了。** 下一章我们把这个本事带进"算法世界"——排序与查找（快排、归并都靠递归大显身手）！

### 三、改错题

**8. 以下递归版"求链表节点数"有 3 个错误：**

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int data;
    struct Node *next;
} Node;

int countNodes(Node *head) {
    return 1 + countNodes(head->next);    // 错误区①：缺出口 → 访问 NULL->next 崩溃！
}

void badFree(Node *head) {
    if (head == NULL) return;
    free(head);                            // 错误区②：先 free 再递归 → 读已释放内存
    badFree(head->next);                   // 错误区③：free 之后 head->next 还能读吗？
}

int main() {
    Node *n1 = (Node *)malloc(sizeof(Node));
    Node *n2 = (Node *)malloc(sizeof(Node));
    n1->data = 1; n1->next = n2;
    n2->data = 2; n2->next = NULL;

    printf("%d\n", countNodes(n1));        // 期望输出 2
    badFree(n1);
    return 0;
}
```

> 提示：`countNodes` 应加"空链表返回 0"的出口；`badFree` 的两个错误都在顺序上。
