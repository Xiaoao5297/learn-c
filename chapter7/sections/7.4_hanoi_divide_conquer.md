# 7.4 汉诺塔与分而治之

> 💬 **节前语：**
>
> 上一节我们用斐波那契看清了递归的"代价"——它告诉我们：**递推简单的问题，别拿递归硬扛。**
>
> 那递归的"高光时刻"在哪？——就是像 **汉诺塔** 这样，**结构天生一层套一层**、用循环写起来痛不欲生的问题。
>
> 传说古印度有个神庙，有 64 片金盘从大到小摞在一根柱子上，僧侣们要把它全部移到另一根柱子，规则只有两条：**一次搬一片、大盘不能压小盘**。传说"搬完世界就毁灭"——因为 64 片至少要搬 **2⁶⁴−1 ≈ 1844 亿亿步**，根本搬不完 😂
>
> 这一节，我们不光用递归三行代码解出汉诺塔，还会悟出一个大智慧：**分而治之（Divide and Conquer）**——它将是以后快速排序、二叉树的"思想源头"。准备好了吗？开始吧！

---

## 7.4.1 规则长这样

有三根柱子 A、B、C，A 柱上从小到大摞着 n 个盘子（下面大、上面小）。规则只有两条：

1. **一次只能搬一个盘子**
2. **大盘子永远不能压在小盘子上面**

目标：把 n 个盘子从 A 全部搬到 C（可以借助 B）。

```
初始：          目标：
    |            |            |              |            |            |
   [1]           |            |              |            |           [1]
  [ 2 ]          |            |              |            |          [ 2 ]
 [  3  ]         |            |              |            |         [  3 ]
  ──A────        ──B────      ──C────        ──A────      ──B────    ──C────
```

n = 3 时最少要搬 7 步；n 个盘子最少要搬 **2ⁿ − 1** 步。

---

## 7.4.2 别想"第 1 步搬哪个"，想"拆解"

如果只盯着"第1步搬哪个盘子"，你的头会炸。换个思路——**把最大的盘子单独拎出来看**：

> 最大的盘子（第 n 个）**只能在所有小盘子都让开之后，才能搬一次**。

于是"搬 n 个盘子"被拆成三幕：

```
第 1 幕：把上面的 n-1 个盘子，从 A 搬到 B（借助 C）   ← 小一号的汉诺塔！
第 2 幕：把最大的盘子，从 A 搬到 C                    ← 一步搞定
第 3 幕：把 B 上的 n-1 个盘子，从 B 搬到 C（借助 A）   ← 又是小一号的汉诺塔！
```

注意第 1 幕和第 3 幕，**结构跟原问题一模一样，只是盘子少了 1 个、柱子换了换**。这不就是第 7.1 节说的"大问题里装着更小的自己"吗？

> 📌 **三步中，两步是"小一号的自己"，一步是"平凡动作"**——这正是递归的完美猎物：出口（只剩 1 个盘子） + 递推（n-1 的自己）。

---

## 7.4.3 递归代码（简短得不可思议）

```c
#include <stdio.h>

// 把 n 个盘子从 from 借助 helper 搬到 to
void hanoi(int n, char from, char helper, char to) {
    if (n == 1) {                          // 出口：只剩 1 个盘子，直接搬
        printf("把第 1 个盘子：%c → %c\n", from, to);
        return;
    }
    // 第 1 幕：上面 n-1 个，从 from 搬到 helper（借助 to）
    hanoi(n - 1, from, to, helper);
    // 第 2 幕：最大的盘子，从 from 搬到 to
    printf("把第 %d 个盘子：%c → %c\n", n, from, to);
    // 第 3 幕：n-1 个，从 helper 搬到 to（借助 from）
    hanoi(n - 1, helper, from, to);
}

int main() {
    printf("—— 3 个盘子的搬家过程 ——\n");
    hanoi(3, 'A', 'B', 'C');
    return 0;
}
```

输出：
```
—— 3 个盘子的搬家过程 ——
把第 1 个盘子：A → C
把第 2 个盘子：A → B
把第 1 个盘子：C → B
把第 3 个盘子：A → C
把第 1 个盘子：B → A
把第 2 个盘子：B → C
把第 1 个盘子：A → C
```

> 🎉 一共 7 步，完美！有没有发现——**要写出这么漂亮的解法，根本不需要"人肉模拟"每一步**。你只需要相信三件事：出口对、参数在变小、那两句 `hanoi(n-1, ...)` 会自己把剩下的活干完。

### 🔍 想"少走两步"？那就必须信仰递归

如果心里一直嘀咕"`hanoi(2, A, C, B)` 到底怎么搬的？我得跟一遍……"，你会在第 3 层递归就晕掉。

**停！这正是递归最大的思维转变——"信仰之跃"：**

> 当你写 `hanoi(n-1, from, to, helper);` 时，不要去想它内部怎么一步步搬——你只要相信：**既然函数能把 n-1 个盘子从任意一根柱子搬到任意另一根（借助第三根），那么这一行就已经完成了第 1 幕。** 至于具体过程，递归会自己搞定。

就像查词典——你不需要把整本词典背下来，只要相信"基础词能查到解释"就行。**先假设"小一号的问题已经解决"，用它拼出大问题的解法。** 这是递归最核心的心智模型，以后写树的遍历、快排，全靠它。

## 7.4.4 背后的大智慧：分而治之

汉诺塔和阶乘，其实共享一个更广的思路——**分而治之**：

| 步骤 | 含义 | 汉诺塔的例子 |
|------|------|-------------|
| ① **分（Divide）** | 把大问题切成几个小问题 | 把"n 个盘子"切成"n-1 个 + 1 个" |
| ② **治（Conquer）** | 递归解决每个小问题 | 那 n-1 个盘子交给 `hanoi(n-1,...)` |
| ③ **合（Combine）** | 把小问题的答案拼成答案 | 三段顺序拼起来就是完整解法 |

> 💡 **分而治之是很多高级算法（快速排序、归并排序、二叉树）的地基**，这里先让你"尝尝味道"。举一个身边的例子：**用递归给数组求和**。

```c
#include <stdio.h>

// 求数组 a 前 n 个元素的和
int arrSum(int a[], int n) {
    if (n == 0) return 0;              // 出口：0 个元素和是 0
    return a[n - 1] + arrSum(a, n - 1); // 治：最后一个元素 + 前 n-1 个元素的和
}

int main() {
    int a[] = {3, 5, 7, 9};
    printf("总和：%d\n", arrSum(a, 4));
    return 0;
}
```

输出：
```
总和：24
```

> 📌 这就是"分而治之"的雏形：把数组拆成"最后一个元素"和"前 n-1 个"，分别解决再合并。到了第8章讲快速排序时，你会发现**把数组对半切、分别排好、再合并**，能让排序快一个量级！

## 7.4.5 递归 vs 循环：完整适用清单

学完斐波那契（递归不太好用）和汉诺塔（递归堪称神器），来一次最终总结：

| | 适合递归 | 适合循环 |
|---|---------|---------|
| 问题结构 | 天生"套娃"：大问题里装着结构相同的更小问题 | 单纯的"重复 N 次" |
| 例子 | 汉诺塔、树、链表逆序、文件夹遍历 | 计数、累加、扫描数组 |
| 代码 | 循环很难写或很绕，递归一清二楚 | 循环直白；递归有调用开销 |
| 风险 | 递归太深会栈溢出；可能重复计算 | 基本无风险 |

> 📌 **判断口诀：** 先想——问题能不能拆成"结构相同的更小号自己"？
> - 能，且拆完递归代码明显更清晰 → **用递归**（如汉诺塔）
> - 只是"从头到尾走一遍" → **用循环**
> - 像斐波那契这样又简单又会重复算 → **用循环更省心**

---

## 7.4.6 本节小结

这一节我们学了：

✅ **汉诺塔规则：** 一次搬一片、大盘不能压小盘

✅ **三幕拆解：** ①搬 n-1 个 ②搬最大盘 ③再搬 n-1 个——两步是"小一号的自己"

✅ **递归代码：** 出口 `n==1` + 两句 `hanoi(n-1,...)`，三行搞定

✅ **信仰之跃：** 相信"小一号的问题已被解决"，用它拼出大问题，别去人肉模拟

✅ **分而治之：** 分（切小）→ 治（递归解决）→ 合（拼答案）；数组求和就是雏形

✅ **适用清单：** 结构套娃 → 递归；单纯重复 → 循环

> 💡 **记住：递归最强的时刻，是"问题结构天生递归"的时候——比如我们下一节的主角：链表！**

### 三、改错题

**8. 以下汉诺塔代码有 2 处错误：**

```c
#include <stdio.h>

void hanoi(int n, char from, char helper, char to) {
    if (n == 0) {                          // 错误区①：出口应该剩几个盘子？
        printf("把第 1 个盘子：%c → %c\n", from, to);
        return;
    }
    hanoi(n - 1, from, helper, to);        // 错误区②：第 1 幕应该"借助"哪根柱子？
    printf("把第 %d 个盘子：%c → %c\n", n, from, to);
    hanoi(n - 1, helper, from, to);
}

int main() {
    hanoi(3, 'A', 'B', 'C');
    return 0;
}
```

> 提示：①只剩 1 个盘子（n==1）就"直接搬"，写成 n==0 会多搬一步/死循环；②对照 7.4.3：第 1 幕要把 n-1 个搬到 helper，得"借助" to 柱子。
