# 5.1 错误处理

>
> 那C程序员怎么办？——靠一套"约定俗成"的方法，用**返回值**和**状态码**把错误一层层传出去。

## 5.1.1 程序为什么会出错？

### 🤔 错误的来源

| 来源 | 例子 |
|------|------|
| 🎯 用户乱来 | 输入了年龄 -5、除数为 0 |
| 📂 环境问题 | 要读的文件不存在、磁盘满了 |
| 🐛 代码bug | 数组越界、空指针、逻辑写错 |

其中前两类是"不可控"的——程序必须学会**优雅地处理**，而不是直接崩溃。

### 📌 C语言的态度：自己检查，自己处理

别的语言：出错了会"抛出异常"，程序跳到专门的处理代码。

C语言：**函数出错时，返回一个"错误信号"，由调用者检查并处理。**

```
调用者 ──调用──→ 函数
   ↑                │
   │        成功？返回结果 / 失败？返回错误信号
   │                ↓
   检查返回值，决定怎么处理
```

> 📌 **核心思想：函数"报告"错误，调用者"处理"错误。**
> 
> 所以C代码里到处是 `if (xxx == NULL) { ... }`、`if (返回值 == -1) { ... }`——这就是C程序员在"接住错误"。

## 5.1.2 约定一：用"状态码 + 指针参数"报告错误

还记得"函数只能返回一个值"吗？那怎么既返回结果、又返回"是否成功"呢？

**答案：返回值用来报告"成没成功"，结果用指针带出去。**

### 📝 设计一个"安全除法"

```c
#include <stdio.h>

// 返回值：0 表示成功，-1 表示出错（除以0）
// 成功时，把结果存进 *result 带出去
int safeDivide(int a, int b, int *result) {
    if (b == 0) {
        return -1;       // 出错信号：除数不能为0
    }
    *result = a / b;     // 结果通过指针"带"出去
    return 0;            // 成功信号
}

int main() {
    int result;
    
    // 第一次：正常情况
    if (safeDivide(10, 2, &result) == 0) {
        printf("10 / 2 = %d\n", result);
    } else {
        printf("出错了！\n");
    }
    
    // 第二次：出错情况
    if (safeDivide(10, 0, &result) == 0) {
        printf("10 / 0 = %d\n", result);
    } else {
        printf("出错了！除数不能为0\n");
    }
    
    return 0;
}
```

输出：
```
10 / 2 = 5
出错了！除数不能为0
```

**这个模式非常经典：**
1. 返回值 `0` 表示成功，`-1`（或别的数）表示失败
2. 真正想要的结果，通过**指针参数** `*result` 带回去
3. 调用方先检查返回值，成功了才放心用结果

> 📌 这样，错误就不会被"悄悄吞掉"了。调用者必须在每个可能出错的地方做检查。

## 5.1.3 约定二：用"哨兵值"表示特殊情况

有时候，某些值天然表示"没有/失败"。比如"在数组里找某个数"：

> 找到 → 返回它的下标（0~n-1）
> 没找到 → 返回 -1（**不可能是合法下标**，用它当"没找到"的暗号）

```c
#include <stdio.h>

int indexOf(int arr[], int n, int target) {
    for (int i = 0; i < n; i++) {
        if (arr[i] == target) {
            return i;        // 找到了，返回下标
        }
    }
    return -1;               // 没找到，返回哨兵值 -1
}

int main() {
    int scores[] = {85, 92, 78, 100, 60};
    int n = 5;
    
    int pos = indexOf(scores, n, 100);
    if (pos >= 0) {
        printf("找到了！100 在第 %d 个位置\n", pos);
    } else {
        printf("没找到！\n");
    }
    
    pos = indexOf(scores, n, 42);
    if (pos >= 0) {
        printf("找到了！42 在第 %d 个位置\n", pos);
    } else {
        printf("没找到！\n");
    }
    
    return 0;
}
```

输出：
```
找到了！100 在第 3 个位置
没找到！
```

> 📌 **哨兵值（sentinel）**：用一个"平时不会出现"的值来代表"没找到/失败"。
> - `indexOf` 用 `-1` 表示"没找到"
> - 后面学的文件读取会用 `EOF`（文件结束标记）做哨兵
> 
> 注意：哨兵值要选得合理——既然下标不可能为负，`-1` 就是安全的"暗号"。

## 5.1.4 约定三：检查"空指针" NULL

还记得4.1节的 `NULL` 吗？很多C函数失败时会返回 `NULL` 表示"没弄到东西"。

比如下一节要学的打开文件 `fopen`——如果文件不存在，它会返回 `NULL`：

```c
FILE *fp = fopen("不存在的文件.txt", "r");

if (fp == NULL) {          // 必须检查！
    printf("打开文件失败！\n");
} else {
    // 才能放心使用 fp
    fclose(fp);
}
```

> ⚠️ **血的教训：不检查就使用，会崩溃！**
> 
> ```c
> FILE *fp = fopen("不存在的文件.txt", "r");
> // 忘记检查 fp 是否为 NULL...
> fscanf(fp, "%d", &x);    // 🚨 fp 是 NULL，直接崩溃（段错误）！
> ```

> 📌 **C语言的"铁律"：凡是可能返回 NULL 的函数，使用前必须检查。** 后面学文件、学动态内存分配（malloc）时都要遵守。

## 5.1.5 防御式编程：好习惯让bug无处藏身

### 🧱 什么是"防御式编程"？

**假设所有输入都可能是坏的**，处处设防。就像过安检：每个人都检查，坏人自然进不来。

| 防线 | 例子 |
|------|------|
| 🛡️ 检查函数返回 | `if (fp == NULL) return;` |
| 🛡️ 检查用户输入 | 除数是否为0、年龄是否为正 |
| 🛡️ 检查边界 | 数组下标不越界、字符串留足空间 |
| 🛡️ 约定返回值 | 成功返回0，失败返回-1，调用方判断 |

### 📝 一个"处处设防"的函数

```c
#include <stdio.h>

// 从数组里找最大值，返回 0 成功 / -1 失败（数组无效）
int getMax(int arr[], int n, int *maxOut) {
    if (arr == NULL || n <= 0) {     // 防御①：数组无效
        return -1;
    }
    
    int max = arr[0];
    for (int i = 1; i < n; i++) {
        if (arr[i] > max) {
            max = arr[i];
        }
    }
    
    *maxOut = max;                    // 结果带出去
    return 0;
}

int main() {
    int scores[] = {85, 92, 78, 100, 60};
    int max;
    
    if (getMax(scores, 5, &max) == 0) {
        printf("最大值：%d\n", max);
    } else {
        printf("参数有问题！\n");
    }
    
    if (getMax(NULL, 5, &max) == 0) {    // 故意传 NULL
        printf("最大值：%d\n", max);
    } else {
        printf("参数有问题！\n");
    }
    
    return 0;
}
```

输出：
```
最大值：100
参数有问题！
```

> 💡 **面对"程序崩溃"和"报个错"，我们当然选报错。** 函数一进来自查一遍参数（`arr == NULL`、`n <= 0`），比用的时候莫名其妙崩掉强一万倍。

## 5.1.6 一个实用的"错误处理清单"

写C程序时，遇到下面这些情况**必须停下来想一想**：

| 场景 | 该检查什么 | 怎么做 |
|------|-----------|--------|
| 打开文件 | 返回的 `FILE *` 是否为 `NULL` | `if (fp == NULL) { 报错并退出 }` |
| 除法/取余 | 除数是否为 0 | 先判断再算 |
| 数组下标 | 是否在 0 ~ n-1 | 循环条件写对 |
| 字符串 | 目标数组空间够不够 | 用足够大的数组 |
| 自己写的函数 | 是否可能失败 | 用返回值0/-1、指针带结果 |

> 📌 **记不住没关系，重点是养成条件反射：** 每次调用"可能失败"的函数，第一反应就是 `if (返回值 == 出错值)`。

## 5.1.7 本节小结

这一节我们学了：

✅ **C语言没有异常机制：** 函数返回"错误信号"，调用者负责检查处理

✅ **约定一：状态码+指针：** 返回值报告成败，结果用 `*out` 带出去

✅ **约定二：哨兵值：** 用 `-1`、`EOF` 等"不可能的值"表示没找到/结束

✅ **约定三：检查 NULL：** 会返回 NULL 的函数，用之前必须检查

✅ **防御式编程：** 假设输入是坏的，处处设防，函数先自检参数

> 💡 **记住：C程序员不"怕"错误，而是"接"错误——每一个可能出错的地方，都要有处理！**

### 三、改错题

**6. 以下程序想安全地打开一个文件，有4个错误，请找出并改正：**

```c
#include <stdio.h>

int openLogFile(FILE **out) {    // 目标：成功返回0，失败返回-1
    FILE *fp = fopen("log.txt", "w");
    if (fp != NULL) {            // 错误区①：条件写反了？其实应该"成功才往下走"
        *out = fp;
        return -1;               // 错误区②：成功却返回-1！
    }
    return 0;                    // 错误区③：失败却返回0！
}

int main() {
    FILE *fp;
    
    if (openLogFile(&fp) == 0) {   // 错误区④：调用也没检查？——其实是检查了
        printf("成功\n");
    } else {
        printf("失败\n");
    }
    return 0;
}
```

> 提示：主要是成功/失败的返回值和检查逻辑弄反了，理清"成功=0、失败=-1"。
