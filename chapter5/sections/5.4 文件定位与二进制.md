# 5.4 文件定位与二进制

前面几节都是从文件头读到尾，顺序前进。这一节加两个新能力：用 `fseek`/`ftell`/`rewind` 在文件里随意跳转；用 `fwrite`/`fread` 把结构体整块存进二进制文件、整块读回来。

## 5.4.1 文件位置：ftell、fseek、rewind

每个打开的文件内部都有一个**当前位置**，读一个字符它就前进一步——就像书里夹着的那根书签，你看完一页它就往后挪一页，告诉你下次从哪里接着看。可以查它、改它：

| 函数 | 作用 |
|------|------|
| `ftell(fp)` | 返回当前位置（距文件开头多少字节） |
| `fseek(fp, 偏移, 起点)` | 把当前位置移到指定字节 |
| `rewind(fp)` | 回到文件开头（等价于 `fseek(fp, 0, SEEK_SET)`） |

`fseek` 的"起点"用三个常量表示：

| 常量 | 含义 |
|------|------|
| `SEEK_SET` | 从文件开头算偏移 |
| `SEEK_CUR` | 从当前位置算偏移 |
| `SEEK_END` | 从文件末尾算偏移（这时偏移通常是 0 或负数） |

一个经典组合是 `fseek(fp, 0, SEEK_END)` 跳到末尾，再用 `ftell` 问当前位置——得到的就是**文件大小**：

```c
// 5.4.1 fseek_ftell.c
#include <stdio.h>

int main(void)
{
	FILE *fp = fopen("digits.txt", "w");
	if (fp == NULL) {
		return 1;
	}
	fprintf(fp, "0123456789");
	fclose(fp);

	fp = fopen("digits.txt", "r");
	if (fp == NULL) {
		return 1;
	}

	fseek(fp, 0, SEEK_END);
	long size = ftell(fp);
	printf("文件大小是 %ld 字节\n", size);

	rewind(fp);
	int ch = fgetc(fp);
	printf("回到开头，第一个字符是 %c\n", ch);

	fseek(fp, 2, SEEK_SET);
	ch = fgetc(fp);
	printf("跳到第 2 个字节，读到 %c\n", ch);

	fclose(fp);

	return 0;
}
```

<!-- output: 5.4.1 -->
```text
文件大小是 10 字节
回到开头，第一个字符是 0
跳到第 2 个字节，读到 2
```

三点说明：

1. `ftell` 返回 `long`，所以用 `long` 接，打印用 `%ld`。
2. "跳到第 2 个字节"读到的是 `2`：位置从 0 开始数，字节 0、1、2 存的是 `0`、`1`、`2`。
3. 定位函数操作的是**字节**。对文本文件按字节数跳不一定正好落在某个字符开头（比如含中文的 UTF-8 文件），`fseek` 最可靠的用途是回到开头、跳到末尾、或在二进制文件里按记录大小跳。

## 5.4.2 文本模式和二进制模式

到目前为止用的 `"r"`、`"w"`、`"a"` 都是**文本模式**。加上 `b` 就成了二进制模式：`"rb"`、`"wb"`、`"ab"`、`"r+b"` 等。

在 Linux 和 macOS 上，两种模式几乎没有区别。差别主要在 Windows：文本模式下 `\n` 会被自动换成 `\r\n` 存盘，读回时再换回来；二进制模式则原样搬运字节，一个都不动。

| 对比项 | 文本模式 `"r"` `"w"` | 二进制模式 `"rb"` `"wb"` |
|--------|----------------------|--------------------------|
| 存的内容 | 一行行文字，人能直接看 | 和内存里一模一样的字节 |
| 换行处理 | Windows 上 `\n` 和 `\r\n` 自动转换 | 原样读写，不转换 |
| 适合 | 配置、日志、要人看的报告 | 结构体、图片、音频等整块数据 |
| 用文本编辑器打开 | 能看懂 | 多半是乱码（正常现象） |

写什么样的数据，就配什么模式：`fprintf`/`fgets` 配文本模式，`fwrite`/`fread` 配二进制模式。

## 5.4.3 fwrite 和 fread：整块读写

文本方式存结构体得一个字段一个字段拼格式，读的时候还得逐个拆，很烦。二进制方式简单粗暴：**把内存里那一段字节原样写进文件，读回来再原样放回内存**。就像搬家时不拆不装，把整个房间原样吊走、原样放回——省事，但只有原样放回才对得上。

```c
fwrite(数组地址, 每个元素的字节数, 元素个数, fp);
fread(数组地址, 每个元素的字节数, 元素个数, fp);
```

两者都返回**实际写入/读出的元素个数**，理想情况等于请求的个数。

```c
// 5.4.2 fwrite_fread.c
#include <stdio.h>

struct point {
	int x;
	int y;
};

int main(void)
{
	struct point points[3] = {
		{1, 2},
		{3, 4},
		{5, 6},
	};

	FILE *fp = fopen("points.bin", "wb");
	if (fp == NULL) {
		printf("写入打开失败\n");
		return 1;
	}

	size_t written = fwrite(points, sizeof(struct point), 3, fp);
	if (written != 3) {
		printf("写入不完整，只写了 %zu 个\n", written);
		fclose(fp);
		return 1;
	}
	fclose(fp);

	struct point loaded[3];
	fp = fopen("points.bin", "rb");
	if (fp == NULL) {
		printf("读取打开失败\n");
		return 1;
	}

	size_t read = fread(loaded, sizeof(struct point), 3, fp);
	if (read != 3) {
		printf("读取不完整，只读了 %zu 个\n", read);
		fclose(fp);
		return 1;
	}
	fclose(fp);

	for (int i = 0; i < 3; i++) {
		printf("(%d, %d)\n", loaded[i].x, loaded[i].y);
	}

	return 0;
}
```

<!-- output: 5.4.2 -->
```text
(1, 2)
(3, 4)
(5, 6)
```

用 `points.bin` 的名字是有意的：这个文件用文本编辑器打开基本是乱码，因为它存的就是内存字节，不是文字。它像一本只有本班同学看得懂的暗号本——符号是你们班自己约定的，别的班（别的程序、别的电脑）拿去读，多半读出一堆莫名其妙的字。

两个返回值都检查了：`fwrite`/`fread` 返回实际搬运的元素个数，磁盘满了、文件被截断了，返回值就会小于请求值。不检查的话，坏数据会伪装成好数据继续往下走。

> **重要警告：二进制文件不可移植**
>
> `fwrite` 把结构体的内存字节原样存盘，因此文件格式完全依赖"写它的那个程序"：
>
> - **结构体有填充字节（padding）**。为了对齐访问速度，编译器可能在字段之间插入看不见的字节，插入多少因编译器、编译选项而异，甚至同一个编译器换个版本都会变。
> - **端序（byte order）不同**。有的 CPU 把整数高位放前面，有的放后面；x86 的电脑和某些手机、单片机的字节顺序可能相反。
> - **类型大小不同**。`int` 在不同平台上不保证同样宽。
>
> 结论：**这份 `points.bin` 只能由同一个平台、同一个编译器编译出的程序可靠地读回来。** 把它拷到另一种电脑上读，可能得到错误数据甚至崩溃。暗号只有本班认识：填充字节、端序、类型大小这些"约定"每台机器各不相同，出了班就全对不上了。需要跨平台、跨程序交换数据时，用文本格式（像 5.5 那样）或专门的交换格式。自己程序在本机存配置、缓存，用二进制完全没问题——这正是它的舒适区。

## 5.4.4 常见错误

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `fwrite(list, sizeof(struct point *), 2, fp);` | 第二个参数写成了指针大小 | `sizeof(struct point)`（一个元素多大） |
| `fwrite` 后不看返回值 | 磁盘满等错误被掩盖 | `if (fwrite(...) != 个数) { ... }` |
| 文本模式写、二进制模式读 | Windows 上换行转换可能对不上 | 写和读用同一种模式 |
| `long size = ftell(fp); printf("%zu", size);` | 格式符不匹配 | `printf("%ld", size);` |
| 拿二进制文件换台电脑读 | 布局、端序可能不同，数据不可靠 | 跨平台交换用文本格式 |

## 5.4.5 小结

- `ftell` 查当前位置，`fseek(fp, 偏移, SEEK_SET/CUR/END)` 移动位置，`rewind` 回开头。
- `fseek(fp, 0, SEEK_END)` + `ftell(fp)` 可以求文件大小；`ftell` 返回 `long`，打印用 `%ld`。
- 模式加 `b` 是二进制模式，字节原样读写；文本模式在 Windows 上会转换换行。
- `fwrite`/`fread` 整块搬内存字节，返回实际搬运的元素个数，**必须检查**。
- 二进制文件受填充字节、端序、类型大小影响，**不能跨平台跨编译器移植**；跨程序交换数据用文本格式。

#### 一、选择题

1. C。末尾位置到文件开头的距离就是全部内容的大小，这是"不求人"测文件大小的标准做法。
2. A。`rewind` 就是"拨回开头"，等价于`fseek(fp, 0, SEEK_SET);`。

#### 二、填空题

4. `"wb"`（读则用`"rb"`）。文本模式和二进制模式的处理方式不同，整块搬字节要用二进制模式。
5. 大小。

#### 三、改错题

6. 三处错误：

- 第一处：`fopen` 返回值没检查。打开失败时`fp` 是`NULL`，`fwrite` 会崩溃。
- 第二处：写二进制文件应该用 `"wb"` 模式，`"w"` 是文本模式。
- 第三处：`fwrite` 的第二个参数写成了`sizeof(struct point *)`，这是一个指针的大小（通常是 8 字节），不是结构体的大小。应为`sizeof(struct point)`，否则写入的字节远少于一个完整元素。

修正后的完整程序：

```c
#include <stdio.h>

struct point {
	int x;
	int y;
};

int main(void)
{
	struct point pts[3] = {{1, 2}, {3, 4}, {5, 6}};

	FILE *fp = fopen("points.bin", "wb");
	if (fp == NULL) {
		return 1;
	}

	fwrite(pts, sizeof(struct point), 3, fp);
	fclose(fp);

	return 0;
}
```

7. 参考代码：

```c
#include <stdio.h>

int main(void)
{
	int nums[4] = {10, 20, 30, 40};

	FILE *fp = fopen("data.bin", "wb");
	if (fp == NULL) {
		return 1;
```
