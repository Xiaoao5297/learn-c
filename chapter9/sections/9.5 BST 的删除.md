# 9.5 BST 的删除

9.4 的 BST 会插入、会查找了，但有一个大难题一直绕着走：**删除**。链表删除只要接回一个指针；BST 删除的难处在于——删掉一个节点之后，剩下的树必须**仍然满足"左小右大"**。这一节把删除按三种情况拆开，一种一种解决。

## 9.5.1 删除的验收标准

先定一个"金标准"：**删完之后，中序遍历仍然从小到大，而且只少了目标那一个值**。家规没被破坏，删除才算对。

以 9.4 建好的这棵树为战场：

```text
        50
       /  \
     30    70
    /  \   /  \
  20   40 60   80
```

中序输出 `20 30 40 50 60 70 80`。每删一个数，我们都用中序复查一遍。

删一个节点，按它有几个孩子分三种情况：

| 情况 | 例子 | 处理办法 |
|------|------|----------|
| 叶子（两个孩子都没有） | 20、40、60、80 | 直接摘掉，父亲那边指回 NULL |
| 只有一个孩子 | 独苗节点 | 让唯一的孩子顶上自己的位置 |
| 有两个孩子 | 50、30、70 | 找"替身"顶班（下面细讲） |

## 9.5.2 情况一：删叶子

删 20。它没有孩子，摘掉不影响任何人——free 掉节点，让父亲的 `left` 指回 `NULL`：

```text
        50                        50
       /  \                      /  \
     30    70       删 20       30    70
    /  \   /  \     ────►     /  \   /  \
  20   40 60   80                40  60   80
```

## 9.5.3 情况二：删"独子"节点

删 40（假设 40 的两个孩子里只剩一个）。注意不能一 free 了之：40 下面还挂着一棵子树，free 了它，子树就跟断了。正确做法是**让唯一的孩子顶上自己的位置**：

```text
        50                        50
       /  \                      /  \
     30    70       删 40       30    70
    /  \   /  \     ────►      /     /  \
  20   [40] 60   80          20     60   80
         \
          45   ← 40 的独子
```

40 消失，45 从"40 的孩子"变成"30 的孩子"。家规依然成立：45 比 30 大（它在 30 的右子树里），比 50 小。其实无论这棵子树长得多高，整体挂在 30 的右边，和家规都不冲突。

## 9.5.4 情况三：删"双子"节点——找替身

删 50。左孩子 30、右孩子 70 都在，让谁顶上都不行：30 顶上来，右子树里还有比它大的数乱入左边；70 顶上来，左子树里还有比它小的数。家规两头都顾不住。

需要一个"替身"，条件是：**比左子树所有值都大，比右子树所有值都小**——正好补进 50 的空位，两边都不越界。谁符合？**右子树里最小的那个节点**（术语叫"后继"）：它比 50 大，又是右子树里最小的，所以它比右子树其他所有值都小。

看 50 的右子树 `{60, 70, 80}`，最小的是 60（从 70 一路往左走到底就是它）。删除 50 拆成三步：

```text
第一步：找到替身——右子树最小的节点 60
第二步：把 60 的值抄进 50 的位置（这棵树根上的 50 变成了 60）
第三步：去右子树里把原来的 60 删掉

        50                        60
       /  \                      /  \
     30    70       删 50       30    70
    /  \   /  \     ────►      /     /  \
  20   40 60   80            20   40      80
```

妙处在于：**替身节点必然是叶子或"独子"**——它是右子树最小的，左边一定没有孩子；所以第三步删它时必然落回情况一或情况二，递归到此收口，不会没完没了。

为什么 60 顶上去家规不破？左子树 `{30, 20, 40}` 全比 60 小（它们本来就都比 50 小）；右子树剩下的 `{70, 80}` 全比 60 大（60 本来就是里面最小的）。两头都严丝合缝。

"一路往左走到底"找最小节点，是 BST 的固定动作：

```c
struct tree_node *find_min(struct tree_node *root)
{
	while (root->left != NULL) {
		root = root->left;
	}
	return root;
}
```

## 9.5.5 完整实现：一个函数吃下三种情况

把三种情况装进一个递归函数。设计仍沿用 9.4 的套路：**函数返回"删除之后这棵子树的根"**，每一层用 `root->left = delete_node(root->left, value)` 把新根接回去——这正是任务要求讲清楚的"返回新子树根"方案。另一种写法是给函数传二级指针、直接改父亲的指针成员（第 6 章删除链表头节点用过 `struct node **head`），两种都行，本书统一用返回新根，理由是它和插入函数的形状完全一样，好记也好查错。

```c
// 9.5.1 bst_delete.c
#include <stdio.h>
#include <stdlib.h>

struct tree_node {
	int data;
	struct tree_node *left;
	struct tree_node *right;
};

struct tree_node *create_node(int value)
{
	struct tree_node *node = malloc(sizeof(struct tree_node));
	if (node == NULL) {
		return NULL;
	}
	node->data = value;
	node->left = NULL;
	node->right = NULL;
	return node;
}

struct tree_node *insert(struct tree_node *root, int value)
{
	if (root == NULL) {
		return create_node(value);
	}
	if (value < root->data) {
		root->left = insert(root->left, value);
	} else if (value > root->data) {
		root->right = insert(root->right, value);
	}
	return root;
}

struct tree_node *find_min(struct tree_node *root)
{
	while (root->left != NULL) {
		root = root->left;
	}
	return root;
}

struct tree_node *delete_node(struct tree_node *root, int value)
{
	if (root == NULL) {
		return NULL;    /* 没找到，树不变 */
	}

	if (value < root->data) {
		root->left = delete_node(root->left, value);
	} else if (value > root->data) {
		root->right = delete_node(root->right, value);
	} else {
		/* 找到了，按孩子个数分三种情况 */
		if (root->left == NULL && root->right == NULL) {
			free(root);           /* 情况一：叶子，直接摘 */
			return NULL;
		} else if (root->left == NULL) {
			struct tree_node *child = root->right;
			free(root);           /* 情况二：只有右孩子，孩子顶上 */
			return child;
		} else if (root->right == NULL) {
			struct tree_node *child = root->left;
			free(root);           /* 情况二：只有左孩子 */
			return child;
		} else {
			/* 情况三：两个孩子，找右子树最小的当替身 */
			struct tree_node *successor = find_min(root->right);
			root->data = successor->data;
			root->right = delete_node(root->right, successor->data);
		}
	}

	return root;
}

void inorder(const struct tree_node *root)
{
	if (root == NULL) {
		return;
	}
	inorder(root->left);
	printf("%d ", root->data);
	inorder(root->right);
}

void free_tree(struct tree_node *root)
{
	if (root == NULL) {
		return;
	}
	free_tree(root->left);
	free_tree(root->right);
	free(root);
}

int main(void)
{
	struct tree_node *root = NULL;

	int values[] = {50, 30, 70, 20, 40, 60, 80};
	for (int i = 0; i < 7; i++) {
		root = insert(root, values[i]);
	}

	printf("原始树：");
	inorder(root);
	printf("\n");

	root = delete_node(root, 20);
	printf("删 20（叶子）：");
	inorder(root);
	printf("\n");

	root = delete_node(root, 50);
	printf("删 50（双子）：");
	inorder(root);
	printf("\n");

	root = delete_node(root, 99);
	printf("删 99（没有）：");
	inorder(root);
	printf("\n");

	free_tree(root);
	root = NULL;

	return 0;
}
```

<!-- output: 9.5.1 -->
```text
原始树：20 30 40 50 60 70 80
删 20（叶子）：30 40 50 60 70 80
删 50（双子）：30 40 60 70 80
删 99（没有）：30 40 60 70 80
```

逐行核对"金标准"：

- **删 20（叶子）**：free 后向上层返回 `NULL`，`30->left` 被接成 `NULL`——摘得干干净净。中序少了 20，其余仍升序。
- **删 50（双子）**：替身 60 抄进根，`60->left` 接住原来的左子树，右子树里递归删掉原来的 60（它是叶子，落回情况一）。中序少了 50，其余仍升序。
- **删 99**：一路走下来没找到，返回 `NULL` 没人接、返回原根没变化，树纹丝不动。**"没找到"也是一种正确结果**，不能崩、不能删错人。

函数开头的 `if (root == NULL) return NULL;` 身兼两职：既是递归走到空位的安全出口，也是"没找到"的天然结局——空树安全，这是 6.3 起一以贯之的纪律。

追踪一下"删 30"这一步。原始树里 30 只有一个右孩子 40（它的左孩子位置是空的），命中"情况二：只有右孩子"——40 顶上 30 的位置，中序从 `30 40 50 60 70` 变成 `40 50 60 70`。紧接着"删 50"：50 有两个孩子 40 和 70，替身是右子树 `{70, 60}` 里最小的 60，抄上去再从右子树里删掉原 60。每删一步，中序仍然升序——家规从未破坏。

删到最后，剩下的输出越来越短。**中序遍历是删除操作的随身检测仪**：只要中序持续升序且总数在减少，删除就一定是对的；一旦乱序，立刻回查代码。

## 9.5.7 三种结构对比：数组、链表、BST

数据结构学到这儿，三大件齐了。它们不是"谁最好"，而是"各管一摊"：

| 对比项 | 数组 | 链表 | 二叉查找树 |
|--------|------|------|------------|
| 内存布局 | 连续一整块 | 靠 `next` 相连 | 靠 `left`/`right` 分叉 |
| 按值查找 | 无序 O(n)，有序二分 O(log n) | O(n) | 匀称时 O(log n) |
| 插入 | 中间插入要挪后面 | 找到位置后改两个指针 | 走到空位即插入，O(log n) |
| 删除 | 挪位补洞 | 改指针摘节点 | 三种情况，递归接回 |
| 排序 | 要单独排序 | 要单独排序 | 中序遍历自动升序 |
| 软肋 | 大小固定、插删要挪 | 访问慢、只能一条线 | 会退化成链 |

选型的直觉：**查询多、插入少，用有序数组配二分；插删频繁，用链表或 BST；既要查得快又要插删快，BST（配上防退化的平衡手段）胜出**。真实工程里数据库索引、内存管理器的底层，都是 BST 家族的远亲。BST 的软肋"会退化成链"，工程上靠"平衡树"（AVL、红黑树）自动旋转来防——那是下一阶段的内容，你现在打的地基已经够读懂它们了。

## 9.5.8 小结

- 删除的验收标准：删后中序仍升序，且只少目标一个值。
- 三种情况：叶子直接摘；独子让孩子顶上；双子找右子树最小值（后继）当替身。
- 替身抄值进根，再去右子树里删替身——替身必是叶子或独子，递归自然收口。
- 统一设计：函数返回"删除后的子树根"，`root->left = delete_node(...)` 接回去，与插入同一套路；传二级指针是等价方案。
- 数组、链表、BST 各有长处和软肋，按场景选，不迷信单一结构。

#### 一、选择题

1. B。叶子没有孩子，摘掉后父亲指针指回 NULL 即可，树的其他部分不受影响。

#### 二、填空题

#### 三、改错题

6. 三处错误：

- 第一处：`delete_node` 没有 `root == NULL` 的出口。删除一个不存在的值时，递归会走进空指针，第一句 `value < root->data` 就解引用 NULL 崩溃。应在函数开头加 `if (root == NULL) { return NULL; }`。
- 第二处：命中目标后直接 `free(root); root = NULL;`，没有处理"有孩子"的情况。删 20 恰好是叶子侥幸对，但只要删的是有孩子的节点，它的整棵子树就会跟着断线丢失。应按三种情况处理：叶子返回 NULL，独子返回孩子，双子找替身。
- 第三处：`main` 里 `free_tree` 没有定义却被需要——程序没释放树（严格说这一处是"缺失"而非"写错"，一并补上才算完整、无泄漏的程序）。

8. 参考代码（`create_node`、`insert`、`inorder`、`free_tree`、`find_min` 同上，只列改动的 `delete_node` 和 main）：

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

struct tree_node {
	int data;
	struct tree_node *left;
	struct tree_node *right;
};

struct tree_node *create_node(int value)
{
	struct tree_node *node = malloc(sizeof(struct tree_node));
	if (node == NULL) {
		return NULL;
	}
	node->data = value;
	node->left = NULL;
	node->right = NULL;
	return node;
}

struct tree_node *insert(struct tree_node *root, int value)
{
	if (root == NULL) {
		return create_node(value);
	}
	if (value < root->data) {
		root->left = insert(root->left, value);
	} else if (value > root->data) {
		root->right = insert(root->right, value);
	}
	return root;
}

struct tree_node *find_min(struct tree_node *root)
{
	while (root->left != NULL) {
		root = root->left;
	}
	return root;
}

bool delete_node(struct tree_node **root, int value)
{
	if (*root == NULL) {
		return false;
	}

	struct tree_node *node = *root;
	bool deleted;

	if (value < node->data) {
		deleted = delete_node(&node->left, value);
	} else if (value > node->data) {
		deleted = delete_node(&node->right, value);
	} else {
		/* 命中：按孩子个数分情况，*root 直接改成新根 */
		if (node->left == NULL && node->right == NULL) {
			free(node);
			*root = NULL;
		} else if (node->left == NULL) {
			*root = node->right;
			free(node);
		} else if (node->right == NULL) {
			*root = node->left;
			free(node);
		} else {
			struct tree_node *successor = find_min(node->right);
			node->data = successor->data;
			delete_node(&node->right, successor->data);
		}
		deleted = true;
	}

	return deleted;
}

void inorder(const struct tree_node *root)
{
	if (root == NULL) {
		return;
	}
	inorder(root->left);
	printf("%d ", root->data);
	inorder(root->right);
}

void free_tree(struct tree_node *root)
{
	if (root == NULL) {
		return;
	}
	free_tree(root->left);
	free_tree(root->right);
	free(root);
}

int main(void)
{
	struct tree_node *root = NULL;

	int values[] = {50, 30, 70, 20, 40, 60, 80};
	for (int i = 0; i < 7; i++) {
		insert(&root, values[i]);
	}

	if (delete_node(&root, 40)) {
		printf("删到了 40：");
		inorder(root);
		printf("\n");
	}

	if (!delete_node(&root, 99)) {
		printf("没找到 99，树没变：");
		inorder(root);
		printf("\n");
	}

	free_tree(root);
	root = NULL;

	return 0;
}
```

输出：

```text
删到了 40：20 30 50 60 70 80
没找到 99，树没变：20 30 50 60 70 80
```

这一版演示的是**另一种方案**：函数接收 `struct tree_node **root`（二级指针），命中时直接改写父亲手里的指针（`*root = child`），不需要靠返回值传递新根；返回值空出来汇报"删没删到"。它和 9.5.5 的"返回新根"方案完全等价——任选其一用到底就好，混用两种风格才是真正的坑。注意这版里 `insert` 也要相应改成二级指针版本。
