# 1.1 C 语言是什么

第 0 章我们看过了计算机的硬件和程序运行的流程，但没有写过一行代码。从这一章开始，你将真正动手写程序。

这一节先回答三个问题：

- 程序到底是什么？
- 编译器在里面起什么作用？
- 为什么选择 C 语言？

## 1.1.1 什么是程序

计算机本身只会执行一条条指令。程序（program）就是一组有序的指令，告诉计算机按什么步骤完成一件事。

一个生活化的对比：把"做番茄炒蛋"这件事说给一个绝对听话但毫无常识的助手听，你不能只说"随便炒一下"，而必须写出明确的步骤：拿几个番茄、切多大块、放多少油、先炒什么。写程序也是同样的过程，只是这次听话的对象是计算机。

用更规范的话说：

> 编程就是把你想要完成的事情，拆解成一步一步的、计算机能理解的指令，再用编程语言写下来。

由此能理解一个初学者常见的困惑：计算机不会"猜"你的意思。它只会严格按照指令执行，步骤写错了、写漏了，它就照着错误的方式执行到底。后面调试程序时，这一点会反复体会。

## 1.1.2 什么是编程语言和编译器

人类语言用于人与人之间的交流，编程语言（programming language）用于人与计算机之间的交流。常见的编程语言有 Python、Java、JavaScript、C、C++ 等，它们各有擅长的领域。

但 CPU 只认识自己的指令集，也就是机器语言，并不直接认识任何编程语言。让机器听懂你写的代码，需要一个翻译角色——编译器（compiler）。

三者之间的关系可以画成一条流水线：

```mermaid
flowchart LR
    A["源代码<br/>hello.c"] --> B["编译器<br/>cc 或 gcc"]
    B --> C["可执行文件"]
    C --> D["操作系统加载并运行"]
```

第 0 章的 0.2 节已经讲过这条流水线。这一章我们会亲自把代码从第 1 步走到第 4 步。

对比一下人类语言和编程语言，能理解为什么写程序比说话"苛刻"：

| 对比项 | 人类语言 | 编程语言 |
|--------|----------|----------|
| 容错性 | 说错一个词，别人通常能猜到意思 | 错一个标点，程序就无法编译 |
| 歧义 | "他走了"可以有多种含义 | 每条语句的含义是唯一确定的 |
| 语法例外 | 存在大量不规则用法 | 规则严格，没有例外 |
| 学多少 | 需要掌握成千上万个单词 | C 的关键字只有三十多个 |

这也意味着：写程序出错是常态，几乎没有人能一次写对所有代码。关键不是不出错，而是学会读懂错误信息并改正。

## 1.1.3 C 语言的来历和定位

C 语言是 1972 年由贝尔实验室（Bell Labs）的丹尼斯·里奇（Dennis Ritchie）发明的。当时他和同事正在开发 Unix 操作系统，为了摆脱手写汇编语言的痛苦，他在 B 语言的基础上设计了 C 语言，随后用 C 重写了整个 Unix。它的名字就是"B 的下一个字母"。

C 的核心定位可以用一句话概括：

> C 是一门贴近硬件、运行高效、语言本身很小的编译型语言。

"语言本身很小"指的是它的关键字只有 32 个（C89 标准），靠标准库提供常用功能。这个特点带来的直接好处是：需要记住的核心语法并不多，这一章到下一章覆盖的内容，就是日常写 C 程序的主体。

## 1.1.4 C 语言用在哪里

五十多年过去，C 仍然是不可替代的语言，因为它擅长做"离机器近"的事：

| 领域 | 例子 | 为什么用 C |
|------|------|------------|
| 操作系统 | Linux 内核、Windows 内核的大部分 | 需要直接管理内存和硬件 |
| 嵌入式与单片机 | 家电、汽车电子、传感器 | 资源受限，C 生成的代码小而快 |
| 数据库与基础设施 | MySQL、Redis、Redis 的组件 | 追求极致性能 |
| 编程语言和工具链 | Python 解释器、Git | 底层组件需要稳定高效 |
| 驱动程序 | 各类硬件驱动 | 与硬件打交道是 C 的强项 |

另一类用途是学习本身：C 的语法直接对应机器行为，没有隐藏的运行时机制。学 C 时遇到的内存、地址、类型这些问题，在其他语言里被掩盖了，在 C 里必须弄明白。这也是很多人把 C 当作第一门语言的原因。

反过来说，C 也有明显的取舍：

| 优势 | 代价 |
|------|------|
| 运行速度快 | 需要手动管理内存，容易出错 |
| 贴近硬件，能力边界大 | 语法检查相对宽松，很多错误要到运行时才暴露 |
| 应用广泛，学完不浪费 | 编译工具链需要学习成本 |

这些代价不是劝退，而是提醒：学 C 要比学 Python 多一分细心。本书后面的章节会专门讲错误处理和内存管理，正是为了应对这些代价。

## 1.1.5 你的第一个程序长什么样

按照本书的习惯，先看一个完整的、可以运行的 C 程序。现在不必理解每一行，混个脸熟即可：

```c
// 1.1.5 hello_preview.c
#include <stdio.h>

int main(void)
{
	printf("你好，世界\n");
	return 0;
}
```

<!-- output: 1.1.5 -->
```text
你好，世界
```

逐行快速认识一下（详细拆解在 1.3 节）：

| 代码 | 作用 |
|------|------|
| `#include <stdio.h>` | 引入标准输入输出库，`printf` 在里面 |
| `int main(void)` | 主函数，程序从这里开始执行 |
| `printf("你好，世界\n");` | 在屏幕上打印一行文字 |
| `return 0;` | 告诉操作系统程序正常结束 |

值得注意的是：这个程序只有 6 行有效内容，但已经是一个完整的程序。C 的简洁由此可见一斑。

## 1.1.6 从想法到程序：一个完整的思考过程

写程序之前，先把任务拆成步骤。以一个具体任务为例："读入三科成绩，输出平均分"。

不写代码，先把步骤列出来：

1. 准备几个位置，存放三科成绩。
2. 从用户那里读到三个数。
3. 求和，除以 3。
4. 打印结果。

这个清单离程序已经很近了。对应到 C 的语法：第 1 步用变量，第 2 步用 `scanf`，第 3 步用算术运算，第 4 步用 `printf`——全部是本章要学的内容。学到 1.5 结束时，你就能独立写出这个程序，章末测试里就有它。

倒过来观察这条链路会更有意思：任何程序都可以拆到"存数据、做运算、输入输出"这几个基本动作上。第 2 章再补上两个动作——"做判断"和"重复执行"——你就能写出相当复杂的程序了。

这也解释了为什么零基础学 C 是可行的：需要掌握的"动作"总共就那么几类，剩下的都是把它们组合起来的练习。

## 1.1.7 编译运行的流程概览

把 1.1.5 的代码保存为 `hello.c`，在终端里需要做两件事：

```bash
cc hello.c -o hello
./hello
```

第一条命令调用编译器，把源代码翻译成可执行文件 `hello`；第二条命令运行它。这两个步骤的细节——包括编译失败时的三种错误——是 1.3 节的主题。

对照第 0 章 0.2 节的表格，可以预先建立一个意识：

| 阶段 | 你会看到什么 |
|------|--------------|
| 编译 | 终端报错，可执行文件没有生成 |
| 链接 | 报 `undefined symbol` 之类的错误 |
| 运行 | 程序启动了，但崩溃或结果不对 |

现在只需要记住：**编译和运行是两个独立的阶段，编译通过不代表程序正确。**

## 1.1.8 术语小词典

下面这些词会贯穿整本书，先混个脸熟，读到后面不理解时可以回来查：

| 术语 | 英文 | 含义 |
|------|------|------|
| 源代码 | source code | 你写的 `.c` 文件，本质是文本 |
| 编译 | compile | 把源代码翻译成机器指令 |
| 可执行文件 | executable | 编译生成的、能直接运行的文件 |
| 运行 | run / execute | 让程序真正执行起来 |
| 缺陷 | bug | 程序中的错误 |
| 调试 | debug | 找出并修正错误的过程 |
| 终端 | terminal | 输入命令、运行程序的黑窗口 |
| 标准库 | standard library | C 自带的函数集合，如 `printf` |

其中"源代码、编译、可执行文件"三个词在 1.3 节会反复出现，建议现在就记住。

## 1.1.10 小结

- 程序是一组有序的指令，计算机只严格按照指令执行，不会猜测意图。
- 编译器负责把源代码翻译成可执行文件，编译和运行是两个阶段。
- C 语言 1972 年诞生于贝尔实验室，语言本身很小，贴近硬件。
- 操作系统、嵌入式、数据库、语言工具链等底层领域，C 至今是主力语言。
- 任何程序都能拆成"存数据、做运算、输入输出"等基本动作，本章逐一学会它们。
- 学习 C 的代价是要多一分细心，好处是能真正理解程序如何运行。
