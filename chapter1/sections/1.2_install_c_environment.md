## 1.2.1 什么是"开发环境"？

### 🤔 一个常见问题

很多初学者会问："为什么不能直接写代码？为什么要安装这么多东西？"

### 🎯 生动的比喻：厨房理论

想象你要做一道菜：

| 需求 | 说明 |
|------|------|
| 🏠 **厨房** | 你需要一个地方做饭 |
| 🍳 **锅碗瓢盆** | 你需要工具来操作 |
| 🥬 **食材** | 你需要原料 |
| 🔥 **火/电** | 你需要能源来加热 |

编程也是如此：

| 需求 | 说明 | 对应到编程 |
|------|------|-----------|
| 🏠 **厨房** | 写代码的地方 | **代码编辑器** |
| 🍳 **锅碗瓢盆** | 把代码变成程序的工具 | **C编译器** |
| 🥬 **食材** | 写出来的代码 | **C源代码文件** |
| 🔥 **火/电** | 让程序跑起来的东西 | **操作系统环境** |

### ⚙️ 特别重要：什么是"编译器"？

C语言代码是用接近人类语言的英文写的，但计算机只懂 **0 和 1**。所以需要一个"翻译官"把C代码翻译成机器语言——这个翻译官就叫 **编译器（Compiler）**。

```
你写的C代码（main.c）
        ↓
   C编译器（gcc）
        ↓
   机器语言（可执行程序）
        ↓
      运行！
```

> 📌 **常用的C编译器：**
> - **gcc**：GNU Compiler Collection，最流行，Linux自带
> - **clang**：苹果系统推荐，速度更快
> - **MSVC**：Windows上 Visual Studio 自带的编译器

## 1.2.2 安装C编译器（gcc）

### 🐧 Linux 用户（最简单的）

Linux 系统一般自带 gcc，可以先检查一下：

```bash
# 查看 gcc 是否已安装
gcc --version
```

如果提示找不到，用包管理器安装：

```bash
# Debian / Ubuntu
sudo apt install gcc

# 或者
sudo apt install build-essential
```

> 📌 `build-essential` 会一次性装好 gcc、make 等一堆编译工具，推荐！

### 💻 Windows 用户

Windows 不自带 gcc，需要自己装。这里推荐 **MinGW-w64**：

> 💡 **先认识几个下载页上的词，别被吓到：**
> 
> | 词 | 意思 |
> |------|------|
> | **x86_64** | 64位的CPU架构（现在绝大多数电脑都是）。32位的老电脑才选 i686 |
> | **UCRT / MSVCRT** | 两种运行时（runtime），推荐选 **UCRT**（新、兼容好） |
> | **解压（解压缩）** | 把 .zip/.7z 压缩包里的文件"取出来"，类似打开一个打包的文件夹 |
> | **bin** | binary（二进制）的缩写，装着 `gcc.exe` 等可执行程序的那个文件夹 |
> 
> 看不懂也没关系——**照做就行**：选 x86_64、选 UCRT、解压到 C:\mingw64，准没错。

```
1. 打开浏览器，访问网址：
   https://winlibs.com/

2. 找到适合你电脑的版本（64位选 x86_64），点击下载
   - 推荐选择 "UCRT runtime" 版本

3. 下载完成后，解压到 C:\mingw64

4. 把 C:\mingw64\bin 添加到系统环境变量 PATH 中：
   - 右键"此电脑" → 属性 → 高级系统设置
   - 点击"环境变量" → 找到 Path → 点"编辑"
   - 新建一行，填入 C:\mingw64\bin
   - 确定保存，重新打开终端
```

> 📖 **术语卡：环境变量 / PATH**
> 
> "环境变量"是操作系统记住的一组**全局小设置**。其中最重要的 `PATH`，是"**去哪找命令**"的目录清单。
> 
> 当你在终端输入 `gcc` 时，系统会在 PATH 列出的文件夹里**挨个找** `gcc.exe`，找到就运行。如果 gcc 的文件夹（`C:\mingw64\bin`）不在 PATH 里，系统就找不到 → 报 `'gcc' 不是内部或外部命令`。
> 
> **类比：** 就像手机里的"常用App"——你把 gcc 所在文件夹"加入收藏"，这样不管在哪都能直接叫它干活。
> 
> > 💡 配好后**要重开一次终端**才生效（因为新终端启动时才读 PATH）。

> 💡 **更省事的办法：** 也可以直接安装 **Visual Studio**（勾选"使用C++的桌面开发"），或者安装 VS Code 后搭配 MinGW。嫌麻烦的话，先在 https://www.onlinegdb.com 在线网站练习也行！

### 🍎 Mac 用户

Mac 系统自带 **clang**（和 gcc 用法几乎一样），一般只需安装命令行工具：

```
1. 打开"终端"App
2. 输入以下命令，回车：

   xcode-select --install

3. 弹出窗口，点击"安装"
4. 等待安装完成
```

安装完成后，验证一下：

```bash
gcc --version
```

> 💡 如果提示让你安装 Command Line Tools，跟着提示装就行。

### 📱 手机用户（Termux 为例）

> 📱 **如果你在使用 Termux（安卓手机上的终端）**，有更简单的方法：

```bash
# 安装 gcc（Termux 里叫 clang）
pkg install clang

# 也可以顺便装一个文本编辑器
pkg install nano
```

> 📌 **Termux 小贴士：**
> - 如果上面的命令不行，可以先更新一下：`pkg update`
> - Termux 是一个免费的终端模拟器，可以在安卓手机上运行 Linux 命令

## 1.2.3 验证安装是否成功

### ✅ 检查方法

打开终端（或命令提示符），输入：

```bash
gcc --version
```

### 🎉 成功的样子

你应该看到类似这样的输出：

```
gcc (Ubuntu 11.4.0-1ubuntu1~22.04) 11.4.0
Copyright (C) 2021 Free Software Foundation, Inc.
...
```

> 📌 版本号可能不同，但只要看到 `gcc` 和一堆数字，就说明安装成功了！

### ❌ 失败的样子

如果看到类似这样的提示：

```
bash: gcc: command not found
```

或者：

```
'gcc' 不是内部或外部命令，也不是可运行的程序
```

**别慌！** 这通常意味着：

| 原因 | 解决方法 |
|------|----------|
| 没安装成功 | 重新按上面的步骤装一次 |
| 环境变量没配 | 重新打开终端试试，或者重启电脑 |
| Windows路径不对 | 检查 `C:\mingw64\bin` 是否添加到了 PATH |

## 1.2.4 选择代码编辑器

C语言写在哪里呢？你需要一个"代码编辑器"。

### 📝 编辑器 VS 文字处理器

| 工具类型 | 例子 | 适合写代码吗？ | 原因 |
|----------|------|---------------|------|
| **文字处理器** | Word, WPS | ❌ 不适合 | 会自动添加格式，代码不需要格式 |
| **记事本** | 记事本, TextEdit | ⚠️ 能用但不推荐 | 功能太少，没有提示 |
| **代码编辑器** | VS Code, Vim | ✅ 推荐 | 有高亮、提示、自动补全 |

### 🏆 推荐的编辑器

| 编辑器 | 适合谁 | 特点 |
|--------|--------|------|
| 🟦 **VS Code** | 大多数人 | 免费、功能强大、插件丰富 |
| ⬛ **Visual Studio** | Windows开发者 | 全功能IDE，自带编译器 |
| ⬜ **Vim / Neovim** | 终端爱好者 | 轻量、高效，需要配置 |
| 🟩 **Sublime Text** | 喜欢简洁的人 | 轻量、美观 |

> 💡 **学习建议：** 刚开始用 VS Code 或者 Nano 就够了，它更简单直观。等熟练了再学 Vim。

## 1.2.5 创建你的第一个C项目

安装好编译器后，让我们来创建一个项目文件夹：

### 📁 项目结构

C语言的项目组织方式很灵活：

```
myproject/           ← 你的项目文件夹
└── main.c           ← 你的代码文件（.c 结尾）
```

> 📌 一个C源文件就够了！.c 就是 **C 源码**的意思。（C++ 的文件则是 .cpp）

### 🛠️ 动手创建项目

```bash
# 1. 创建一个项目文件夹
mkdir hello
cd hello

# 2. 创建一个代码文件（空文件即可，内容下一节再写）
touch main.c
```

> 📌 **main.c 是什么？**
> 
> 就像作文纸一样，`main.c` 是你写代码的地方。`.c` 扩展名告诉编译器："我是C语言源码！"

## 1.2.6 常用的C命令

安装好编译器后，你会经常用到这些命令：

| 命令 | 作用 | 比喻 |
|------|------|------|
| `gcc --version` | 查看编译器版本 | 查看你的手机型号 |
| `gcc main.c -o main` | 编译C程序，生成可执行文件 | 把菜谱做成成品菜 |
| `./main` | 运行编译好的程序 | 开吃！ |
| `gcc main.c` | 只编译（默认输出 a.out） | 随手做一道菜 |
| `gcc -Wall main.c` | 编译并显示所有警告 | 厨师边做边检查食材 |

> 📌 **看懂编译流程：**
> 
> ```
> gcc main.c -o main
>  │     │       │   └─ 生成的文件名（-o = output，输出）
>  │     │       └───── 目标文件名
>  │     └───────────── 你的源代码文件
>  └─────────────────── 调用 gcc 编译器
> ```
