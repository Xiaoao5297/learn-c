# 1.2 搭建开发环境

写 C 程序需要三样东西：编译器、编辑器和终端。第 0 章已经介绍过它们各自是干什么的，这一节动手把它们装好、验证好。

本章以 Linux 为主线。使用 Windows 的读者，请留意每节末尾的"Windows 提示"小段。

## 1.2.1 需要安装什么

| 工具 | 作用 | 本教程使用的 |
|------|------|--------------|
| 编译器 | 把源代码翻译成可执行文件 | GCC 或 Clang |
| 编辑器 | 编写和修改源代码 | VS Code 或 Vim |
| 终端 | 输入编译、运行命令 | 系统自带 |

先检查编译器是否已经安装。打开终端，输入：

```bash
cc --version
```

如果输出类似下面的内容，说明编译器已经就绪，可以跳过安装，直接进入 1.2.4：

```text
cc (GCC) 13.2.0
Copyright (C) 2023 Free Software Foundation, Inc.
```

版本号不同没有关系，重点是出现了版本信息。

如果提示"command not found"或"不是内部或外部命令"，按下面的步骤安装。

## 1.2.2 Linux：安装编译器

Linux 发行版都用包管理器安装软件。根据你的发行版选择一条命令执行：

Debian / Ubuntu 及其衍生版：

```bash
sudo apt update
sudo apt install gcc
```

Fedora / RHEL 及其衍生版：

```bash
sudo dnf install gcc
```

Arch / Manjaro 及其衍生版：

```bash
sudo pacman -S gcc
```

如果希望使用 Clang（ 本书代码在两者下均可编译）：

```bash
sudo apt install clang      # Debian / Ubuntu
sudo dnf install clang      # Fedora
sudo pacman -S clang        # Arch
```

安装完成后再次验证：

```bash
cc --version
```

> **提示**
>
> Linux 上的 `cc` 通常是 `gcc` 或 `clang` 的别名，指向其中一个。用 `cc --version` 可以看出它实际指向哪个编译器。本书统一写 `cc`，命令在任何 Linux 上都一样。

## 1.2.3 验证安装：编译一个空程序

装完编译器，别急着进下一节，先用一个最小程序验证整条链路。创建 `check.c`，内容只有一行：

```c
int main(void)
{
	return 0;
}
```

编译并运行：

```bash
cc check.c -o check
./check
echo $?
```

三步都顺利的话：编译无输出，运行无输出，最后一条命令打印 `0`（`echo $?` 显示上一个程序的退出状态，`0` 表示正常结束，`return 0` 的作用在 1.3 节讲）。看到这个 `0`，说明编译器、终端、运行环节全部正常。

> **Windows 提示**
>
> PowerShell 里查看退出状态的命令是 `echo $LASTEXITCODE`，CMD 是 `echo %errorlevel%`。看到 `0` 同样代表验证通过。

## 1.2.4 Windows：安装 MinGW-w64

Windows 没有自带 C 编译器，需要单独安装。推荐两条路线：

### 路线一：MSYS2（推荐）

1. 访问 <https://www.msys2.org/>，下载安装包并安装。
2. 打开 MSYS2 终端，执行：

```bash
pacman -S mingw-w64-ucrt-x86_64-gcc
```

3. 把 `C:\msys64\ucrt64\bin` 加入 PATH：开始菜单搜索"编辑系统环境变量"，打开"环境变量"，在"用户变量"的 `Path` 中新建一条，填入上面的路径。

### 路线二：独立安装包

访问 <https://winlibs.com/>，下载 GCC 的 MinGW-w64 独立构建包，解压到 `C:\mingw64`，然后把 `C:\mingw64\bin` 加入 PATH。

### 验证

新开一个 CMD 或 PowerShell 窗口（修改 PATH 后必须新开窗口才生效），输入：

```bash
gcc --version
```

能看到版本号即安装成功。也可以按 1.2.3 的方法编译那个最小程序做完整验证。

> **Windows 提示**
>
> - MSYS2 装好后，`gcc` 在 `ucrt64` 子目录下；如果加入 PATH 后仍然找不到命令，多半是路径写错或没有重开终端。
> - 本教程后续的编译命令在 CMD、PowerShell 里写法相同，把 `cc` 换成 `gcc` 即可。
> - 运行编译好的程序，在 CMD 里输入 `hello.exe` 或 `.\hello.exe`（PowerShell 用后者）。

## 1.2.5 选择编辑器

编辑器负责写代码。两道常见的坑要先讲清楚：

**不要用 Word 或记事本写代码。** Word 会保存成专有格式；记事本默认编码和换行符都可能带来问题。

**代码文件必须是 UTF-8 无 BOM 编码、LF 换行。** 这两个词在第 0 章 0.3 节讲过：

| 属性 | 推荐值 | 不一致会怎样 |
|------|--------|--------------|
| 文件编码 | UTF-8（无 BOM） | 带中文注释的文件可能编译报错，或注释变乱码 |
| 换行符 | LF | 行尾带 `\r` 时部分工具报错，git diff 显示异常 |

推荐的编辑器：

| 编辑器 | 适合 | 要做的事 |
|--------|------|----------|
| VS Code | 零基础首选 | 安装扩展：C/C++（Microsoft 官方）、C/C++ Extension Pack |
| Vim | 想长期留在终端里 | 打开 `.c` 文件即有语法高亮，无需额外配置 |

VS Code 的安装：官网 <https://code.visualstudio.com/> 下载安装，然后在扩展面板（快捷键 `Ctrl+Shift+X`）搜索 "C/C++" 安装即可。它提供语法高亮、错误提示和代码补全，对初学者非常友好。

> **Windows 提示**
>
> 在 VS Code 中按 `Ctrl+Shift+P`，输入 "Save with Encoding"，选择 "UTF-8"；右下角状态栏可以查看并切换当前文件的编码和换行符（CRLF / LF），统一改成 LF。
>
> **控制台中文乱码**：CMD 默认使用 GBK 编码，打印 UTF-8 中文会变成乱码。两种解法：
>
> 1. 在 CMD 中执行 `chcp 65001`，把当前窗口切到 UTF-8 代码页，再运行程序。
> 2. 改用 Windows Terminal（微软商店可装），新建标签时默认就是 UTF-8。
>
> 本教程的示例输出都是 UTF-8 中文，请提前把终端设置好。

## 1.2.6 建立你的工作目录

从一个目录开始，专门存放练习代码。Linux 上：

```bash
mkdir -p ~/c_learn/chapter1
cd ~/c_learn/chapter1
```

用编辑器在这里创建一个空文件 `hello.c`。VS Code 可以这样：

```bash
code hello.c
```

> **Windows 提示**
>
> CMD / PowerShell 等价命令：
>
> | Linux | CMD | PowerShell |
> |-------|-----|------------|
> | `mkdir -p ~/c_learn/chapter1` | `mkdir %USERPROFILE%\c_learn\chapter1` | `mkdir $HOME\c_learn\chapter1` |
> | `cd ~/c_learn/chapter1` | `cd %USERPROFILE%\c_learn\chapter1` | `cd $HOME\c_learn\chapter1` |
> | `code hello.c` | `code hello.c` | `code hello.c` |

保存文件时确认两点：文件名是 `hello.c`（不是 `hello.c.txt`），编码是 UTF-8。Windows 上如果打开了"隐藏已知文件类型的扩展名"，建议在资源管理器选项里关掉它，否则很容易保存成 `hello.c.txt` 而不自知。

环境就绪。下一节开始写代码。

## 1.2.7 装不上？常见问题排查

环境搭建是本章最容易卡住的一步。先给出最常见的失败模式和对应检查点：

| 现象 | 最可能的原因 | 处理 |
|------|--------------|------|
| `cc: command not found` | 编译器没装或不在 PATH | 回到 1.2.2 重新安装，或检查 PATH |
| `gcc: command not found`（Windows） | PATH 没配好或没重开终端 | 检查 `bin` 目录路径，新开终端窗口 |
| `sudo: command not found` | 用的是没有 sudo 的环境 | 直接执行不带 `sudo` 的命令试试 |
| 权限错误 `Permission denied` | 无网络或无软件源访问 | 检查网络；校园网/公司网可能拦截软件源 |
| 安装包下载很慢 | 默认软件源在境外 | 换用国内的镜像源（搜索"发行版名 + 镜像源"） |

一个通用原则：**报错信息原文直接拿去搜索**。编译器和包管理器的报错都很具体，绝大多数你已经遇到的问题，别人早就遇到并写了解法。

再强调一次学习成本的分寸：装环境是一次性投入，装好之后整本书都在用它。卡住一两个小时是正常的，不值得为它放弃。

## 1.2.8 小结

- 需要三样工具：编译器、编辑器、终端。
- Linux 用包管理器安装 `gcc` 或 `clang`，用 `cc --version` 验证。
- Windows 推荐用 MSYS2 或 WinLibs 安装 MinGW-w64，并把 `bin` 目录加入 PATH。
- 源代码文件保持 UTF-8 无 BOM、LF 换行。
- 用 VS Code（装 C/C++ 扩展）或 Vim 作编辑器。
- 建一个专门目录存放练习代码。
- Windows 控制台中文乱码时，用 `chcp 65001` 或换 Windows Terminal。
- 装不上时对照 1.2.7 的排查表，报错原文直接搜索。

## 练习

1. 在你的系统上安装编译器，并记录 `cc --version`（或 `gcc --version`）的输出。
2. 按 1.2.3 的方法编译空程序 `check.c`，运行后用 `echo $?` 确认退出状态是 0。
3. 创建工作目录 `c_learn/chapter1`，并在里面新建一个空的 `hello.c` 文件。
4. 检查你的编辑器：当前文件的编码和换行符分别是什么？如果不是 UTF-8 和 LF，改过来。
5. Windows 用户：在 CMD 里执行 `chcp 65001`，然后用 `echo 你好` 试试中文是否正常显示。
6. 思考：为什么代码文件不能用 Word 保存？

<details>
<summary>参考答案</summary>

1. Linux 上执行 `sudo apt install gcc`（或其他发行版对应命令），然后 `cc --version` 验证；Windows 按 1.2.4 的路线安装。
2. 参考输出：编译和运行都没有输出，`echo $?` 打印 `0`。PowerShell 用 `echo $LASTEXITCODE`，CMD 用 `echo %errorlevel%`。
3. `mkdir -p ~/c_learn/chapter1 && cd ~/c_learn/chapter1 && touch hello.c`，或在编辑器里另存为。
4. VS Code 看右下角状态栏；Vim 可以在命令模式输入 `:set fileencoding? fileformat?` 查看。改动方法见 1.2.5。
5. 执行后看到"活动代码页: 65001"，`echo 你好` 能正常显示中文，说明当前窗口已切到 UTF-8。这个设置只对当前窗口有效，重开窗口需要重新执行。
6. Word 保存的是专有二进制格式（`.docx`），不是纯文本，编译器无法读取。代码文件必须是 UTF-8 纯文本。

</details>
