# 第 1 章：认识 C 语言

第 0 章看了计算机怎样运行程序，这一章开始亲手写程序。学完这一章，你会拥有一个能编译、能运行的 C 开发环境，并写出第一个能和你对话的程序：

- 理解什么是程序、什么是编译器，以及 C 语言用在哪里。
- 在 Linux 或 Windows 上搭好编译器和编辑器。
- 写出、编译、运行第一个 C 程序，看懂报错信息。
- 用变量存放数据，掌握 `int`、`double`、`char` 三个基本类型。
- 用 `scanf` 读取用户输入，并学会校验输入是否合法。

## 前置知识

- 第 0 章：计算机基础，不要求会编程。
- 会打开终端、切换目录、创建文件（第 0 章的 0.4 节练过即可）。

## 学完这一章，你应该能

1. 说清楚源代码、编译器、可执行文件三者的关系。
2. 在自己的电脑上安装并验证 C 编译器。
3. 独立完成"写代码、编译、运行"的完整流程。
4. 根据报错信息判断错误发生在编译、链接还是运行阶段。
5. 用 `int`、`double`、`char` 定义变量，用 `printf` 按格式打印。
6. 用 `scanf` 读入整数、浮点数和字符串，并对非法输入做校验。

## 本章工程支线

1.5 的输入校验不是可有可无的细节，而是本章的工程支线。"检查返回值、检查取值范围、清空缓冲区"这三件事，是所有和用户打交道的程序的基本功：

- 第 2 章学到循环和函数后，会把输入校验封装成可复用的"安全读整数"函数。
- 第 5 章讲错误处理时，会把它升级成统一的错误报告风格。
- `%s` 必须带宽度的规则，会在第 3 章讲数组和第 6 章讲内存安全时再次出现。

从这一章起就按工程标准写输入代码，后面学新东西时只需往上叠加，不必推倒重来。

## 预计时间

- 只读一遍：3 到 5 小时。
- 做完每节练习和章末测试：7 到 10 小时。
- 环境搭建如果不顺利，可能多花 1 到 2 小时，属正常情况。

## 学习建议

- 1.2 节装环境时耐心一点，报错就搜索报错信息原文。
- 每个示例先自己敲一遍、编译运行一次，再改几个数字看变化。
- 遇到编译错误，先读文件名、行号和第一条错误，不要从最后一行开始看。
- 1.5 节的三条 scanf 规则（查返回值、`%c` 前加空格、`%s` 带宽度）请背下来，后面每章都用到。
- 练习题先自己写，再展开参考答案对照。
